# Acceptance record

Enforced test outcomes, mapped to the adopted contracts' acceptance scenarios. A row appears only for an outcome a test enforces. Scenarios not listed here remain unexecuted targets.

| Scenario | Enforced outcome | Tests |
| --- | --- | --- |
| META-A7 (partial) | A touched mapped property defined more than once across descriptions, as both attribute and element, or with duplicate `xml:lang` refuses with `PdfXmpException`; Info, ModDate and the packet are unchanged. A duplicate ModifyDate refuses an edit that refreshes ModDate. An unrelated duplicate neither refuses nor changes. A property defined once in a later description is edited in place. Not covered: several descriptions with non-empty `rdf:about` beyond these fixtures. | `MetadataTests.duplicate_touched_definition_refuses_with_no_change`, `duplicate_modify_date_refuses_an_edit_that_refreshes_moddate`, `unrelated_duplicate_does_not_refuse_and_survives`, `property_defined_in_a_later_description_is_edited_in_place` |
| META-A7 / VALIDATE-01 unsafe packet (partial) | An existing packet that is malformed (three shapes), or well-formed with another root or no `rdf:RDF` (three shapes), refuses every touching edit (Title set and clear, Keywords, CreationDate, ModificationDate, a custom key, Trapped) with `PdfXmpException`; the saved bytes equal the original. An earlier pending `SetXmp` replacement survives a refused edit. Such documents still open, report Info, and the malformed packet still throws on `OpenXmp`. Not covered: fault injection after provisional changes (META-A9), UTF-16 packets, and cancellation. | `MetadataTests.malformed_packet_refuses_every_touching_edit_with_no_change`, `well_formed_packet_with_another_root_or_no_rdf_refuses_every_touching_edit_with_no_change`, `refused_edit_keeps_an_earlier_pending_raw_replacement`, `unsupported_packet_still_opens_and_reads_info`, `malformed_xmp_opens_and_reads_as_an_error_and_refuses_an_edit_with_no_change`; `FuzzRegressionTests.xmp_without_rdf_refuses_an_info_edit_with_no_change` |
| META-A4 (clear cases) | With no packet, a mapped clear under an automatic ModDate refresh saves a packet whose only property is `ModifyDate` (no cleared property, no Info backfill; Info Title absent, ModDate refreshed, unrelated Info kept). Not covered: assignment creation (A4 first clause) beyond existing tests, a clear that fails after provisional changes (META-A9), cancellation. | `MetadataTests.clear_with_no_packet_and_automatic_moddate_creates_a_packet_holding_only_the_date`, `explicit_moddate_clear_with_no_packet_creates_no_packet`, `clear_after_an_explicit_moddate_override_with_no_packet_creates_no_packet`, `refused_clear_keeps_earlier_pending_edits` |
