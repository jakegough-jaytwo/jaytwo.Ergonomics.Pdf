| Write authorization | Per-operation password-security permissions, DocMDP, FieldMDP, and Reader usage-rights preservation/removal mechanics. | Supported writes enforce applicable password-security permissions, certification restrictions (DocMDP), and field locks (FieldMDP), and apply documented Reader usage-rights preservation/removal rules. | Password and permission operations | Supported schemes, authentication roles, authorization, encryption interaction, output strategy, and signature restrictions. | Opening/modifying supported password-protected PDFs and reading/changing supported security permissions with appropriate authorization; permission inspection does not satisfy permission changes. | Digital signing/timestamps | Host/provider inputs, CMS/PAdES options, reservations, algorithm subset, token checks, revision ordering, and failures. | Detached CMS and PAdES B-B/B-T with host-controlled keys, optional RFC 3161 signature timestamps, and appended document timestamps; trust validation and B-LT/B-LTA construction excluded. |
| Signature/revision inspection | CMS inspection depth, revision identity, byte-range/coverage reporting, malformed structures, and completeness limits. | Inspection of signatures, embedded claims, and document revisions without cryptographic validation or trust assessment; depth is set by the operation contract. |
| Workflow ergonomics | Defaults, ordering, source lifetimes, staging, terminal calls, form-export shortcuts, and file publication. | Composition of supported operations with sensible defaults/order, form-export shortcuts, and file publication through the engine public API. |
| Foreground/background images | Painting order and visibility limits. | Foreground/background placement describes painting order and does not guarantee visibility over every page element. |
| Resource/failure contracts | Per-operation bounds and destination-specific outcomes before/during/after writing, restoration, publication, rollback, and retry. | Documented limits, explicit failures, and no blanket file-size support promise. |

Keep explanatory boundary distinctions in supported.md as well as linking their mechanics: separate document timestamps do not establish B-LTA conformance; attachments and associated-file keys do not imply PDF/A-3 compliance; incremental append is distinct from in-place rewrite. These distinctions prevent accidental scope expansion.

Retain all other enduring non-goals: rendering, page-content text extraction, general authoring/layout beyond the limited image exception, redaction, cryptographic signature validation, general repair, XFA packet editing, JavaScript authoring/editing/execution, general annotation editing, and the encryption/attachment/conformance boundaries above. Internal support for approved workflows does not establish new public capabilities.
