# jaytwo.Ergonomics.Pdf

Stream-native PDF operations for .NET. MIT licensed, no runtime dependencies beyond `System.Memory` and `Microsoft.Bcl.AsyncInterfaces` on `netstandard2.0`, and no `byte[]` of the whole file.

The library reads and updates PDF 1.0 through PDF 1.7 / ISO 32000-1 (with the PDF 2.0 xref and metadata behavior that shows up in real files). It is for the operations below, not a general PDF toolkit. Files produced by pypdf, qpdf, and pyHanko are part of the test suite, and those tools check the revisions this library writes.

## Scope

### Supported today

1. Fill AcroForm fields one at a time or in bulk, all or nothing, and export the form data. Flatten all fields or named fields into page content. Classify hybrid and XFA-only XFA forms; a fill removes the XFA of an unsigned hybrid form and refuses a signed hybrid or an XFA-only one.
2. Digitally seal a document with a host PKCS#11 signer (RSA, ECDSA P-256, or ECDSA P-384, with SHA-256, SHA-384, or SHA-512) and an RFC 3161 timestamp authority.
3. Read AcroForm field geometry: name, value, rectangle, page number, rotation, and media box.
4. Read and write document information and XMP metadata.
5. Read and write embedded-file attachments.
6. Inspect existing signatures: signer and embedded certificates, algorithms, claimed times, byte ranges, later revisions, time-stamp times, and certification level. Nothing is validated.
7. List logical revisions with their end offsets and signature coverage, including linearized files.

Everything else in this README describes what ships today.

### Target for 1.0 (Phase 1, not yet released)

Release 1.0 adds reading and incremental-update operations, such as page rotation. The specification is [`docs/spec/phase-1.md`](docs/spec/phase-1.md). These are targets, not shipped behavior, until this README lists them as supported.

### Later

Release 1.x adds operations that write a new file: page extraction, concatenation, compaction, removing revisions, and removing passwords ([`docs/spec/phase-2.md`](docs/spec/phase-2.md), draft). Caller-supplied fonts for non-WinAnsi appearances and PAdES long-term validation are also planned for 1.x.

## Tenets

- **Seekable streams, long offsets.** `PdfDocument.Open` requires `CanRead` and `CanSeek`. Offsets are `long` and are file offsets, including any preamble before `%PDF-`.
- **Do not buffer the file.** Opening reads the header and the tail xref. Later reads load the objects an operation touches. A 3 GiB file and a 1,000-page file stay sparse.
- **Incremental append.** `SaveIncremental` and `Sign` add one classic xref revision. The original bytes stay a prefix. Same-stream saves append. Cross-stream saves copy with a 1 MiB buffer into an empty destination, then append. The opened stream's bytes stay unchanged. A save or sign that fails or is canceled after it started writing truncates the destination to its starting length: empty, or the opened file's length.
- **Async signing and saving.** `IPdfExternalSigner.SignHashAsync`, `ITimestampAuthority.GetTimeStampTokenAsync`, and `IPdfSignatureProvider.CreateContentsAsync` return `ValueTask<byte[]>` and take a `CancellationToken`, so a cloud key service or a remote timestamp authority does not hold a thread. `SaveIncrementalAsync` and `SignAsync` sit beside `SaveIncremental` and `Sign` and write the same bytes. They copy into a different destination with asynchronous reads and writes, and `SignAsync` writes its appendix asynchronously; the `SaveIncrementalAsync` appendix is serialized synchronously. Cancellation is observed before anything is written, inside the signer and the timestamp authority, and between the 1 MiB blocks of a copy, and throws `OperationCanceledException`; the pending edits remain. The synchronous `Sign` passes `CancellationToken.None` and waits for the provider, so a host whose async code needs the calling thread's synchronization context calls `SignAsync`. Reads stay synchronous.
- **Read the xref forms writers actually emit.** Classic tables (CRLF, LF, and the 20-byte space-LF and space-CR rows), xref streams (Flate and PNG predictors), hybrid `/XRefStm`, and object streams. Writes are classic xref only. Edited objects that lived in an object stream are written as normal objects.
- **Logical revisions.** `Revisions` lists them oldest first with 1-based numbers and exclusive end offsets. A hybrid table and its `/XRefStm` are one revision, as are a linearized file's main and first-page xref sections. Signature coverage means a signature field's `/ByteRange` ends at that revision; it is reported, not validated, and the signed bytes are not read.
- **Working set is the xref map plus touched objects.** `/Size` is not an array. Clean objects loaded from an object stream are released when the public operation returns. A map that contains a dirty object stays. The 32 MiB and 64 MiB caps are decompression limits, and the bound for one structural stream. A signature appendix larger than 8 MiB (8,388,608 bytes as serialized, counting every object it writes, such as an attachment or a reused field's dictionary) throws `PdfSignException` before the destination is written; call `SaveIncremental` first. Strings are written in 4 KiB pieces, encrypted ones included, so a long string costs no transient copies of itself. Classic xref offsets stop at 9,999,999,999.
- **Password-based encryption is decrypted on read and encrypted on write.** Pass the user or owner password to `Open`. Revision 2 is 40-bit RC4. Revision 3 is RC4 at 40 to 128 bits. Revision 4 is AES-128 or RC4, chosen by the crypt filter. Revision 5 and revision 6 are AES-256. The new trailer keeps `/Encrypt` and `/ID`. The signature `/Contents` stays plaintext; every other string in a signature dictionary is encrypted and decrypted like any string. Cross-reference streams stay plaintext. `/Encrypt` is an uncompressed object found from the xref map. An encrypted xref stream fails `Open`. Public-key encryption is refused. A null password tries the empty user password, which opens a restrictions-only file. A user password is limited to the permission bits. `Permissions` reports print, high-quality print, modify, copy, annotate, form fill, assembly, and accessibility extraction. An unencrypted document allows every operation. The owner password is not limited by the reported bits. Revision 2 folds the later operations into print, modify, copy, and annotate.
- **Text is PDF text.** UTF-16BE (`FE FF`) and UTF-8 (`EF BB BF`) are recognized. Anything else is PDFDocEncoding, not Windows-1252. Text strings the library writes (information entries and dates, field values and names, file specification names and descriptions) use a literal string for ASCII and UTF-16BE hex otherwise. Attachment name-tree keys follow the one-encoding rule under Attachments, so a new tree's keys are UTF-16BE even for ASCII names.
- **Appearances are deliberately small.** A WinAnsi text or choice value gets a Helvetica appearance and `/NeedAppearances false`. For a `/DA` font size of zero, the generated size follows the field height (between 6 and 14 points); single-line text also shrinks to fit the field width, with 6 points as the floor. A regenerated text or choice appearance paints gray, RGB, or CMYK `/MK /BG` and `/MK /BC` colors, with a solid `/BS /W` border inside the box. Captions, icons, `/MK /R`, non-solid borders, and fonts outside the existing Helvetica subset are not generated. A list-box appearance draws the selected display values, not the full option list and selection highlight, and filling removes a stale `/I` array. Helvetica advances use the Adobe glyph widths, 1000 units per em, indexed by the WinAnsi byte. Check boxes and radios reuse the existing on-state. A check box with no appearance gets a generated `Yes`/`Off` mark. Checking a field whose widgets advertise different on-state names throws `PdfFieldValueException` instead of selecting an appearance that another widget does not have. One radio widget with no on-state gets a mark named for its export value, drawn with Bezier curves. Comb, rich text, and non-WinAnsi values set `/NeedAppearances true` and return `NeedsViewer`. Signing and flattening throw while that flag is true. Password, signature, and push-button fields throw `PdfFieldValueException` and do not dirty the document.
- **Certification follows DocMDP `P`.** `P` 1 blocks fills, attachment edits, metadata writes, flattening, rotation, and `Sign`. `P` 2 and `P` 3 allow fills and `Sign`. Metadata, attachments, flattening, and rotation stay blocked. On a document with a signature, flattening and rotation throw `PdfSignatureConflictException` unless `AllowBreakingSignatures` is set. A certification that does not resolve is treated as `P` 1. FieldMDP `All` blocks every fill. `Include` locks the named fields. `Exclude` locks every field except the named ones. A named field covers its descendants. An unknown action locks every field. Reads still work. An incremental save leaves an existing signature byte range in place.
- **PKCS#11 stays in the host.** The library does not P/Invoke a PKCS#11 module. `PdfSignatureOptions.DigestAlgorithm` picks SHA-256 (the default), SHA-384, or SHA-512, and `IPdfExternalSigner.SignHashAsync` receives the raw digest (32, 48, or 64 bytes) and its `HashAlgorithmName`. The key type comes from the leaf certificate. For an RSA key, the host matches `RSA.SignHash(hash, hashAlgorithm, Pkcs1)`; with PKCS#11 `CKM_RSA_PKCS`, the host prepends the DigestInfo for that algorithm. For an ECDSA P-256 or P-384 key, the host returns the IEEE P1363 `r||s` value (64 or 96 bytes) that `ECDsa.SignHash` and `CKM_ECDSA` produce, and the library DER-encodes it. `CKM_SHA256_RSA_PKCS` or `CKM_ECDSA_SHA256` would hash the digest again. Other keys, such as P-521 or RSA-PSS, are refused. `AdditionalCertificates` is the chain beyond the leaf, and those certificates are embedded in the CMS signature. `PdfSignatureOptions.Format` picks the CMS format: `AdbePkcs7Detached` (the default) signs content-type, message-digest, and a CMS signing-time; `PadesBaselineB` writes `/ETSI.CAdES.detached` with content-type, message-digest, and signing-certificate-v2 (the SHA-256 of the leaf, with its issuer and serial), and no CMS signing-time, so the signing time is only in `/M` (ETSI EN 319 142-1). With a timestamp authority, a `PadesBaselineB` signature is PAdES baseline B-T. B-LT and B-LTA, which need revocation data, are not written. A custom `IPdfSignatureProvider` must honor `PdfSignatureContext.Format`, because the `/SubFilter` already names it.
- **Timestamps.** `CmsDetachedSignatureProvider` can take an `ITimestampAuthority`. It hashes the signature value with SHA-256, whatever the signature's digest, requests an RFC 3161 token with a random nonce and `certReq` set to true, and stores that token as the unsigned attribute `1.2.840.113549.1.9.16.2.14`. The provider rejects a token whose message imprint, digest algorithm, or nonce does not match the request, or that does not carry the TSA signing certificate identified by its ESS signing-certificate attribute. A document timestamp is still a second revision from `DocTimeStampSignatureProvider`, and that provider applies the same checks. It hashes with SHA-256, and another `DigestAlgorithm` with `PdfSignatureKind.DocTimeStamp` throws `PdfSignException`. Certificate inclusion makes the token self-contained; it does not validate the signature or establish certificate trust. `HttpTimestampAuthority` POSTs `application/timestamp-query` and accepts PKI status 0 or 1. A response body larger than 2 MiB (2,097,152 bytes) throws `PdfTimestampException`, and the entire exchange stays under `HttpClient.Timeout`; a timeout is a `TaskCanceledException` with a `TimeoutException` inner exception. The caller's cancellation is an `OperationCanceledException` that carries the caller's token, not a timeout. An exception from a host `ITimestampAuthority`, a `PdfTimestampException` included, is replaced with a generic `PdfTimestampException` without its message, data, or inner exception; `HttpTimestampAuthority` exceptions pass through as described here.
- **Failed signs do not write.** The provider runs after `/ByteRange` is patched and before the appendix is appended. A throw, or a token larger than the reserved gap, leaves the destination length unchanged. Exceptions from any `IPdfExternalSigner` member, including the enumeration of `AdditionalCertificates`, are replaced with a generic `CryptographicException` without the provider's message, data, or inner exception. After the caller cancels, a signer or host timestamp-authority exception becomes a fresh `OperationCanceledException` instead. `CertificateDer` is read once and `AdditionalCertificates` is enumerated once, both before `SignHashAsync`. A CMS value larger than `ReservedContentsBytes` throws `PdfSignatureTooLargeException`, whose `ActualBytes` is the exact length the value needed, as pyHanko reports it; the signer and any timestamp authority have run by then, and a time-stamp token is parsed only once the value fits. Reserve that length plus a margin when retrying, because an ECDSA value and a fresh token can differ by a few bytes from one sign to the next. Certificates past 1,048,576 bytes, the largest reservation, throw `PdfSignException` and stop enumerating the chain before `SignHashAsync`. A null or empty leaf certificate, a leaf that is not one DER-encoded certificate, a leaf whose key is not RSA, P-256, or P-384, a null or empty additional certificate or signature value, and an ECDSA value that is not the P1363 length for its curve (a DER-encoded value, for example) each throw `PdfSignException`. A leaf failure leaves `SignHashAsync` uncalled.
- **Not thread-safe.** Dispose does not save. `leaveOpen: false` disposes the active stream.

## Out of scope

Never in scope: rendering, page-content text extraction, reflow, stamping and watermarks, layout or creating a PDF from scratch, rewriting a file in place, redaction, signature validation (trust, revocation, or cryptographic verification), PDF/A conversion, XFA editing, JavaScript, annotation editing beyond what flatten requires, page-level file attachment annotations, public-key encryption, and adding encryption to a file. Page content streams are never decoded.

No PDF/A conformance is claimed. Appending to a PDF/A file is not guaranteed to keep it conformant. Filters other than Flate, LZW, RunLength, ASCIIHex, and ASCII85 (and the abbreviations `Fl`, `LZW`, `RL`, `AHx`, and `A85`) throw when their bytes are actually required.

| Limits | `Open` requires a readable seekable stream. Offsets are `long`. The 32 MiB and 64 MiB caps are decompression limits, and the bound for one structural stream. A literal or hex string holds at most 32 MiB. A name, number, or keyword is at most 65,536 bytes. An array or dictionary holds at most 1,048,576 entries, counting repeated keys. An xref stream lists object numbers below 8,388,608, within its decoded entries and its `/Size`. A file's cross-reference sections list at most one distinct object per 8 bytes of file, never fewer than 65,536 and never more than 2,097,152. An xref stream's `/Index` subsections must ascend without overlapping. A classic xref subsection lists object numbers 0 through 2,147,483,647. An object stream's `/N` header pairs must fit before `/First`; parsing its objects reads at most four times its decoded length plus 64 KiB, and parsing 65,536 integer members allocates less than 16 bytes per decoded byte on net10.0. A page tree nests at most 256 levels below the root. `/Filter` is a name or an array of names, and `/DecodeParms` has one dictionary or null per filter. Either one, its entries, and the decoder parameters may be indirect, and a chain of references is followed at most 256 deep. In a cross-reference stream they must be direct. A file past a limit throws `PdfObjectTooLargeException` or `PdfParseException`. The type is not thread-safe. Dispose does not save. | Same-stream saves append. Cross-stream saves copy with a 1 MiB buffer into an empty destination, then append. Classic xref offsets stop at 9,999,999,999. A file past a cap throws before the destination grows. |

## Usage

```csharp
using System.Collections.Generic;
using jaytwo.Ergonomics.Pdf;
using jaytwo.Ergonomics.Pdf.AcroForm;
using jaytwo.Ergonomics.Pdf.Attachments;
using jaytwo.Ergonomics.Pdf.Metadata;
using jaytwo.Ergonomics.Pdf.Signatures;

using var document = PdfDocument.Open(stream, leaveOpen: true);

foreach (PdfField field in document.AcroForm.Fields)
{
    Console.WriteLine($"{field.FullName} page {field.PageNumber} {field.Rect.Width}x{field.Rect.Height} checked={field.IsChecked}");
}

document.AcroForm.Fill("Name", "Ada");
document.AcroForm.Fill(new Dictionary<string, PdfFieldValue>
{
    ["Agree"] = true,                     // check box
    ["Size"] = "Large",                   // radio on-state name
    ["Colors"] = new[] { "Red", "Blue" }, // multi-select choice
});
IReadOnlyDictionary<string, PdfFieldValue> data = document.AcroForm.Export();
document.AcroForm.Flatten(new[] { "Name" }); // paints the value into the page and removes the field
foreach (PdfSignatureInfo signature in document.Signatures)
{
    Console.WriteLine($"{signature.FieldName} signed={signature.IsSigned} revision={signature.SignedRevisionNumber} {signature.SubFilter} {signature.SigningTime} later revisions={signature.HasLaterRevisions}");
}
foreach (PdfRevision revision in document.Revisions)
{
    Console.WriteLine($"revision {revision.Number} ends at {revision.EndOffset}, signed={revision.IsCoveredBySignature}");
}

document.Metadata.Title = "Signed copy";
document.Metadata["Department"] = "Forms";
document.Attachments.Add("factur-x.xml", invoiceXml, leaveOpen: true, new PdfAttachmentOptions
{
    MimeType = "text/xml",
    Relationship = PdfAttachmentRelationship.Alternative,
    Compress = true,
});

PdfPage page = document.Pages[0];
document.Sign(
    new PdfSignatureOptions
    {
        PageNumber = page.Number,
        Rect = new PdfRect(page.CropBox.Urx - 180, 36, page.CropBox.Urx - 36, 72),
        DigestAlgorithm = PdfDigestAlgorithm.Sha384,
    },
    new CmsDetachedSignatureProvider(pkcs11Signer));
```

Pass the password to `Open(stream, password)` when the file requires one. `Open(stream)` tries the empty user password, which is how a restrictions-only file opens. The permission bits still apply. `Permissions` reports them for either password: an owner open can modify the file and still shows the user-password limits. An unencrypted file reports every operation allowed. Supported files are revision 2 or 3 (RC4), revision 4 (AES-128 or RC4), and revision 5 or 6 (AES-256). Revision 5 takes the UTF-8 password, cut at 127 bytes. Revision 6 prepares that password first, so a decomposed password matches its composed form. `SetText`, `SetCheckBox`, `SetRadio`, and `SetChoice` return a `PdfAppearanceDisposition` so the caller can see whether a viewer still has to regenerate appearances. `SaveIncremental()` with no destination appends to the opened stream, and so does `Sign(options, provider)`. Pass an empty destination stream to `SaveIncremental` or `Sign` when the opened file must stay unchanged. `SaveIncrementalAsync` and `SignAsync` take the same arguments and a `CancellationToken`. A large attachment that does not fit in the 8 MiB signature appendix is `SaveIncremental` to that private stream, then `Sign` on the same private stream. Replace the visible file only after `Sign` returns.

`Pages` reports each page number, media box, crop box, and rotation, which is enough to place a signature rectangle. Set `Pages[n].Rotation` to rotate a page in 90-degree increments. Every rectangle and box is PDF user space as the file stores it: the origin is the bottom-left corner, y increases upward, and one unit is 1/72 inch. Nothing is translated to a top-left or on-screen system, and changing rotation does not change those coordinates. `/UserUnit` is not applied, so on a page that declares it, one unit is that multiple of 1/72 inch. `Sign` reuses an existing empty signature field named by `FieldName` and keeps its `/Rect` and `/P`. A null `FieldName` creates `SignatureN`. Signing that field again throws `PdfSignException`. A name that is not a signature field throws `PdfSignException`. `AcroForm.GetFields` looks a field up by its dotted name. Check boxes and radios expose `IsChecked`, so the on-state name does not have to be guessed. For buttons, `ExportValue` and `SetRadio` use that appearance on-state name; a button `/Opt` array is not mapped to another public value. Choice fields expose `/Opt` as `Options`; `SetChoice` writes those export values, and a multi-select value is a PDF array. `Metadata["Key"]` reads and writes the information dictionary, including private keys. `Trapped` stays a name (`True`, `False`, or `Unknown`). Attachments can be opened by name. `Signatures` and `Revisions` report structural claims, not validation: `SigningTime` is the signer's claim, `IsCoveredBySignature` only matches a `/ByteRange` end offset, and `HasLaterRevisions` says only that an update follows the signed revision, not whether that update is permitted.

PDF 1.0 through 1.7, the operations above, standard security revisions 2 through 6, and the caps above. A file past a cap throws before the destination grows. This is not a promise that every conforming PDF can be modified.
