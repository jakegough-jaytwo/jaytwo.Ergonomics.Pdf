# D-57. An unsigned 32-bit /P is a tolerated writer quirk

## Context

ISO 32000-1 Table 21 gives `/P` as a signed 32-bit integer. pypdf (5.9.0 through at least 6.21.2) writes the same bits as the unsigned value, for example `/P 4294967292` for `-4`, and `Open` refuses those files (W-99). qpdf, pyHanko, Poppler `pdfsig`, and MuPDF read them. Revisions 2 to 4 hash `/P` into the file key as four little-endian bytes, and revisions 5 and 6 compare it with the decrypted `/Perms`; both depend only on the 32 bits.

## Decision

1. An encryption dictionary's `/P` that is an integer from 2,147,483,648 through 4,294,967,295 is read as the signed 32-bit value with the same bits. That is the third entry on the closed writer-quirk list (spec section 8).
2. Any other `/P` outside the signed 32-bit range, and a `/P` that is not an integer, is still refused with `PdfEncryptedException`.
3. Permission evaluation, the revision 2 to 4 key derivation, and the revision 5 and 6 `/Perms` check use the same 32 bits. Password and `/Perms` checks are not relaxed.
4. The output keeps the original encryption dictionary; `/P` is never rewritten.

## Consequences

- W-99 implements it, with a pypdf-produced fixture, a test, and a `README.md` writer-quirk entry.
- G8 fuzzing covers the unsigned range and its boundaries (W-104).

## Authority

The owner, 2026-10-23, adopting option A of the W-99 disposition question (tolerate, rather than refuse and document).
