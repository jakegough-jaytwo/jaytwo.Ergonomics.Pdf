# D-45. No write changes usage rights on a signed document

## Context

Spec §7.3 keeps a Reader-extended file's `/UR3` signature only when its UR3 transform grants the write and otherwise removes it in the same revision (D-44). W-88 found that pyHanko 0.38.0's difference analysis treats any change to `/Perms` after a signature as outside every modification level. On a document certified at `P` 2 or `P` 3, every permitted write that removed `/UR3` made pyHanko report the certification broken (`OTHER`, `docmdp_ok=False`, 56 of 56 built cases), and it reported earlier approval signatures, including the corpus file `cms-40b-pyhanko-approved`, as `OTHER` for the same reason. When `/Perms` was unchanged, pyHanko accepted the result.

## Decision

On a document that already has a signature, no write changes `/Perms`: `/UR3` stays even when its transform does not grant the write. Every refusal, DocMDP and FieldMDP rule, and permission check is unchanged, and unsigned documents keep the W-67 and W-87 policy.

A document has a signature when the catalog `/Perms` has a `/DocMDP` entry, or a signature field in the AcroForm field tree has a `/V` that resolves to a dictionary. That is the test `Sign` uses to refuse an already signed field, and the one the DocMDP and FieldMDP checks use. The `/UR3` signature itself does not count. A `/V` that does not resolve is null (ISO 32000-1 7.3.10), so that field is unsigned, as `Sign` treats it. The check runs before `Sign` creates its own signature dictionary, so writes in the revision that adds the first signature follow the unsigned policy. Every `Sign` saves at once, so no unsaved signature exists when a later write runs.

This narrows D-44 for signed documents: there, a `Sign` that creates a new signature field, a document timestamp, a metadata write, and a write the transform does not grant now leave `/UR3` in place. D-44 still governs unsigned documents.

The owner approved this text for `AGENTS.md`, replacing "Usage rights (`/UR3`) are kept only when they provably permit the write and are otherwise removed in the same revision (spec §7.3).":

> Usage rights (`/UR3`) are kept when they provably permit the write. Otherwise they are removed in the same revision, except on a document that already has a signature, where they are left in place (spec §7.3).

and this paragraph, added at the end of §7.3 of `docs/spec/phase-1.md`:

> On a document that already has a signature (approval, certification, or document timestamp), a write never changes `/Perms`: `/UR3` stays even when its transform does not grant the write, because removing it is a change no signature permits, and validators report the earlier signatures as modified. Adobe Reader may then report that its extended features are unavailable.

The owner also approved, and made on 2026-10-20, the matching edit to the `QUALIFICATION.md` §6 (G3) sentence on usage-rights cases: on an unsigned document every non-permitting case removes `/UR3`, and on a document that already has a signature every write leaves `/Perms` unchanged.

## Consequences

W-90 implements it, with `ACCEPTANCE.md` and `README.md`. On a signed Reader-extended document, the usage-rights signature may no longer match the document after a write its transform does not grant, and Adobe Reader may then report that its extended features are unavailable instead of dropping them silently; no Adobe Reader was available to confirm this. The usage-rights signature is still not validated, the legacy `/Perms /UR` entry is still not read, and no API removes `/UR3`.

## Authority

The owner, 2026-10-20, under W-90.
