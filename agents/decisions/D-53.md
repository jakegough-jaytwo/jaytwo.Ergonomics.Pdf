# D-53. Routine work uses focused verification and compact records

## Context

The owner found that test breadth and workflow ceremony were consuming more time and tokens than implementation. D-52 shortened full test runs but still made the fast lane the default for every task and left evidence-oriented records in the ordinary loop.

## Decision

- Once scope and the changed contract are clear, implementation starts without additional planning ceremony.
- Routine work runs the smallest focused tests that can falsify the change. Each confirmed defect gets at least one permanent regression test. Broader cases require a distinct risk.
- The fast lane, target matrix, Docker gate, independent-tool sweep, test-value assessment, report, and qualification-record update are opt-in. They run when the item names the need, the owner requests it, the change is cross-cutting or framework-sensitive, or release qualification requires it.
- Work items keep the lifecycle and `allowed_changes` control of D-33, but their required body is reduced to problem, scope, acceptance, verification, and closeout. Public behavior documentation changes only with public behavior.
- Qualification evidence is maintained during release qualification or an explicit qualification item, not opportunistically during routine work.

## Consequences

D-52's test categories and framework allocation remain. This decision supersedes only its default fast-lane requirement for task commits. D-31's task-specific verification rule remains: the item states what proportionate verification it needs. High-risk parser, encryption, signature, compatibility, and resource changes can still require broad or independent checks; breadth follows risk instead of being automatic.

## Authority

The owner, 2026-10-23, directing the repository to reduce test and process overhead.
