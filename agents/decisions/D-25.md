# D-25. Single-agent skills replace standing roles


Decided 2026-10-19 by the owner. Future work uses one active agent and the repository skills under `.agents/skills/`. Product Manager and Technical Lead sequencing collapse into `pdf-task-workflow`; the Core, AcroForm, and Signing roles become domain-change skills; QA becomes `pdf-change-verification`; and the Security Auditor becomes the read-only `pdf-security-review` workflow.

This decision supersedes the standing-role and mandatory role-handoff portions of D-01 through D-08 and D-11. Those decisions, `team.md`, `roles/`, and role-named reports remain as history. Role labels in older state describe provenance, not a requirement to launch another agent.

D-04's rule to stop and report when the governing documents disagree still applies. D-08's owner-only rule now covers `AGENTS.md`, `QUALIFICATION.md`, and `.agents/skills/` in place of `team.md` and `roles/`. D-07 kept test authorship separate from implementation. That separation ends here. The same context may now write code and its tests, so `pdf-change-verification` requires tests derived from the criterion, the standard, and independent tools rather than from the implementation.

One agent may plan, implement, verify, update state, and report a task without persona handoffs. That does not turn self-review into independent review. D-23's independent-review requirement still needs a human or a fresh agent context that did not implement the affected code; use `pdf-security-review` there. Subagent delegation is not the default and requires the user's explicit request.
