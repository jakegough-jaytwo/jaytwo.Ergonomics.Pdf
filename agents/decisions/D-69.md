# D-69. XFA handling and PDF/A input scope

## Context

During W-218 the agent restored enduring exclusions but prematurely chose the XFA and PDF/A boundaries without the requested owner decision. The owner supplied the following explicit decisions to supersede that wording.

## Decision

- **XFA:** Commit to classification and operation-specific acceptance, refusal, and removal rules, including supported use of hybrid forms' AcroForm representation. Exclude XFA packet editing. Removal must be an explicitly documented consequence.
- **PDF/A:** Accept PDF/A inputs under normal operation contracts and preserve relevant structures where practical. Exclude PDF/A conversion, validation, and guarantees of creating or preserving conformance, including PDF/A-3. Attachment support does not imply PDF/A-3 compliance.

## Consequences

SUPPORTED.md records these durable commitments. behavior.md retains the current per-operation support, preservation, omission, and refusal rules. No universal PDF/A input-acceptance or structure-preservation guarantee is introduced; no existing operation contract or implementation changes in this documentation transaction.

## Authority

Jake explicitly supplied and approved both decisions on 2026-10-27 following the correction to commit 8295ed8.
