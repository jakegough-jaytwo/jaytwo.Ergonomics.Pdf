# D-63. Registered focused fixture sets are a third fixture class

## Context

D-59 made the fixture layout exhaustive: the G2 corpus is `Fixtures/*.pdf` and `Fixtures/corpus/*.pdf`, defect and writer-quirk fixtures are in `Fixtures/defects/`, and a fixture PDF anywhere else fails `CorpusManifestTests`. W-163 added four unmodified PDF Association SafeDocs files in `Fixtures/assembly-links/` with their own manifest, license, and attribution. They are feature-specific interoperability inputs: neither defect reproductions nor members of the representative corpus. Jenkins build 14 failed on them. Moving them into `defects/` would corrupt its meaning, and adding them to G2 would subject them to corpus rules they were never chosen for.

## Decision

This extends D-59; its rules 1 to 3 are unchanged, and rule 4 now also admits registered focused sets.

1. A focused fixture set is a first-level directory `Fixtures/focused-<purpose>/`, registered by name in `FocusedFixtures.Sets` in the test project. A `fixtures.json` alone does not authorize a directory: an unregistered directory, a nested directory, or a PDF without an entry fails the fast lane.
2. Each set has a `fixtures.json`. Every entry records identity (file, SHA-256, work item, purpose), provenance (producer, source, acquisition date, transformations), licensing (SPDX identifier, redistribution basis, and the attribution files it requires, which must be in the set), and evidence (the consuming tests, which must exist, the expected behavior, and validators). A validator result follows D-59 rule 3. As there, a version is required only for an `unsupported` result, because the consuming tests rerun the validators with the installed tools.
3. Every PDF in a set has exactly one entry and every entry names an existing PDF whose hash matches. A set contains no subdirectories and no symbolic links.
4. Focused sets are outside the G2 corpus: they are never in its numerator or denominator, never get a corpus manifest entry, and are never cited as G2 qualification evidence. They are reported as feature-specific interoperability tests.

## Consequences

- W-176 moves the W-163 fixtures to `Fixtures/focused-assembly-links/`, registers the set, rewrites its manifest to rule 2, and adds the checks.
- The G2 corpus, its thresholds, and the `defects/` register are unchanged.
- A later set is added by registering it in the same commit that adds its files.

## Authority

The owner, 2026-10-25, adopting an outside expert's recommendation (option 1, with an explicit registry and the `focused-<purpose>` naming) on the build 14 failure. The version-only-when-unsupported rule keeps D-59's validator rule rather than the expert's per-validator version, for the reason in rule 2.
