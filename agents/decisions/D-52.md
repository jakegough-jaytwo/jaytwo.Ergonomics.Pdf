# D-52. Tests are classified by what they touch; interop runs on one framework

## Context

A full run is about 4,400 tests and 12.5 minutes on each framework, so all five hosts take about 45 minutes on Windows. In the net10.0 run of the 2026-10-23 Docker gate, about 85% of the tests took about 13% of the summed test time. The rest was tests that start external tools (about 1,180 s), walk the G2 corpus (about 770 s), or build large data or sweep every failure point (about 720 s). Work items were verified with full runs, and flaky timing defects (W-98, W-120, W-121) were re-proved with loaded full runs, so each round cost 45 minutes.

A cutoff by duration does not classify a test stably, because the duration moves with host load. What a test touches is fixed in its code.

Interop tests ask an implementation written elsewhere (qpdf, pyHanko, pypdf, Poppler, pdfsig, OpenSSL, iText) to judge bytes the library wrote or read. The library's output does not depend on the target framework: `src/` has three `#if` blocks (a polyfill, a span overload, and a parse overload) and formats numbers and dates with fixed formats and the invariant culture. The one runtime-dependent output is the `DeflateStream` encoding, which every Deflate decoder reads. Repeating interop on every framework re-asks the same question about the same bytes.

## Decision

- Tests carry `Category` traits for what they touch, never for how long they take: `Interop` (an implementation written elsewhere judges the result), `External` (starts an external tool or loads a native tool library only to make input or set up), `Corpus` (G2 corpus files), `LargeData` (data sized to reach a cap, a budget, or an allocation bound), and `Sweep` (repeats an operation across every offset, failure point, or fixture). A test may carry several.
- The fast lane, `make quiet-test LANE=fast`, leaves out all five categories and is the default verification for a task commit. In it, the helpers that start tools, load iText, or open corpus files refuse, so an unclassified test fails the fast lane instead of slowing it. `LargeData` and `Sweep` have no single helper; the fast lane lists its slowest tests so a reviewer can classify one that should not be there.
- `make unit-test` runs `Interop` tests on net10.0 only. net8.0, net6.0, the netstandard2.0 lane, and net48 run every other test. An output-identity test on every framework writes a fixed set of operations and compares them with recorded output, so a change that makes output depend on the framework fails there. This narrows D-51's "net48 on Windows keeps the full suite".
- The full matrix and `make docker-builder docker-test` run at integration checkpoints, not for each task commit. A long run goes in a separate worktree so the next item can proceed.

## Consequences

A task commit's verification takes minutes. The categorized tests still run at every checkpoint, so a failure there is found later and becomes its own item. net48 and the netstandard2.0 build lose direct interop evidence; the output-identity test is the argument that net10.0's interop evidence covers them, and it does not cover a defect that appears only in a runtime's Deflate encoder. A test that makes its input with a tool still runs on every framework.

## Authority

The owner, 2026-10-23, directing classification by what tests touch, the per-item fast lane, and interop on one framework. The `AGENTS.md` and `.agents/skills/` wording in W-122 and W-123 is on branch `lanes` for the owner's review before merge.
