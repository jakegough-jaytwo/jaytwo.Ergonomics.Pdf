# D-56. An update matches the cross-reference format of the section at startxref

## Context

The charter allowed classic cross-reference output only. On a source whose section at `startxref` is a cross-reference stream, the appended classic trailer's `/Prev` points at that stream. iText 9.8.0 cannot read the result: after a classic section it expects every `/Prev` to be a classic table, fails, and rebuilds the cross-reference by a line scan that loses object-stream members (`agents/evidence/itext-comparison.md`, finding 1). qpdf, pypdf, pyHanko, and pdfsig accept the same files. W-112 found 14 of the 41 corpus files ending in a cross-reference stream, among them the IRS 1040-ES and W-9, USCIS I-9, and Grants.gov SF-424.

ISO 32000-1 Table 15 defines a classic trailer's `/Prev` as the offset of the previous cross-reference section, without saying it must be a table, and Table 17 defines a stream's `/Prev` as the previous cross-reference stream. The normative text does not plainly forbid the mixed chain. Adobe guidance (Leonard Rosenthol, as quoted by mkl on Stack Overflow) says an incremental update keeps the original cross-reference format, and pyHanko's incremental writer does so.

## Decision

1. When the section at the source's `startxref` is a cross-reference stream, an incremental update writes a cross-reference stream: `/Type /XRef`, `/Size`, `/Prev`, `/Root`, `/Info`, `/ID`, `/Encrypt`, `/W`, and `/Index`, Flate-compressed, with an entry for itself. It is never encrypted.
2. When that section is a classic table, a hybrid file's included, the update writes a classic table.
3. An update never writes an object stream and never rewrites an earlier section.
4. The 9,999,999,999-byte offset limit and `PdfTooLargeForClassicXrefException` keep applying to every save and signature. Lifting the limit for stream output is not part of this decision.

## Consequences

- W-117 implements it and changes the `AGENTS.md` write rule and `docs/spec/phase-1.md` section 4 to say so.
- iText reads updates to cross-reference-stream sources, and the corpus iText check no longer skips them.
- The incremental writer has two section formats, and each write path is tested on both.

The owner, 2026-10-23, adopting option A of the W-117 disposition question (fix, rather than exclude or defer).
