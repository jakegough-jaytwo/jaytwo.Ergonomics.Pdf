# D-58. Certification is detected from signature fields as well as the catalog

## Context

Before a write, the engine takes the most restrictive certification level from the catalog `/Perms /DocMDP` and from a walk of the signature fields in the AcroForm field tree. W-116 asked whether the walk could be skipped when the catalog has no `/Perms /DocMDP`, or when AcroForm `/SigFlags` SignaturesExist is clear too, since iText checks neither on a general write.

An outside review found that ISO 32000-1 §12.8.1 says a certification's signature dictionary "may also be referenced" from `/Perms /DocMDP`. Table 258 makes the entry optional. So a certification referenced only from its signature field's `/Reference` can be conforming. `/SigFlags` is optional with default 0, and bit 1 means only that if it is set, a signature field exists. ETSI EN 319 142-1 V1.2.1 §4.1 and §5.3 keep the ISO 32000-1 §12.8 rules and add no catalog requirement.

## Decision

1. Neither a missing catalog `/Perms /DocMDP` nor a clear or missing `/SigFlags` SignaturesExist shows that a document is uncertified. Both count only as evidence that a certification exists.
2. The signature-field walk stays for every write that checks certification. ISO 32000-1 does not require a writer to walk the fields. The walk is what lets this library keep its guarantee that it never appends a change a certification forbids.
3. The current shortcuts stay as they are. There is no walk when the catalog has no AcroForm or the AcroForm has no `/Fields`. A field tree that cannot be fully walked fails closed. A dangling `/Perms` counts as `P` 1.

## Consequences

- No implementation change follows. A metadata or attachment write on a large form keeps the cost of one cached signature-only walk per revision (W-114).
- No item is opened for an early return when the catalog already says `P` 1, because that path only refuses sooner. No item is opened for the remaining allocation either. If a benchmark later shows a material problem, profile object-stream decompression and allocation before proposing a change.
- Research note: the review did not check the normative wording of ISO 32000-2 §12.8.1. If that text says "shall", it still does not change this decision, because the library reads PDF 1.x files.
- For stage R4 only: pyHanko and EU DSS allow document timestamps and DSS updates on certified documents in some profiles. Under the current spec (section 7.2), `P` 1 still blocks every write and signing. Reconsider that only in R4, with the owner.
