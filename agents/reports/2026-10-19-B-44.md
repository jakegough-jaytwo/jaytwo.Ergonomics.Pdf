# B-44: unresolvable references are null

## Task

Under owner decision D-26, implement ISO 32000-1 7.3.10 for skill-review finding F-1 (`agents/reports/2026-10-19-F-1.md`). Undefined, free, and mismatched-generation references resolve as null.

## Changes made

- `Internal/PdfEngine.cs`: `Resolve` returns null for a reference that `IsLive` rejects. That covers no xref entry, a free entry, an unknown entry type (ISO 32000-1 7.5.8.3), a type 1 entry with a different generation, or a compressed object named at a generation other than 0. The object-number check on an indirect object's own header is unchanged.
- Edit paths no longer write through a dangling reference. The affected paths are `/AcroForm`, `/DR`, `/DR /Font`, `/Helv`, `/Names`, `EditArray`, and `/Info`; each now creates a new object instead of editing whatever object holds that number. `EditCatalog` checks the catalog first. A widget `/P`, a page `/Annots` entry, a field `/Parent`, and an embedded file's `/EF` stream count only when they are live.
- Certification stays strict, extending the charter rule that an unresolved certification is `P` 1. A null `/Perms`, `/Reference`, `/Reference` entry, or DocMDP `/TransformParams` counts as `P` 1. A null FieldMDP `/Reference`, `/Reference` entry, `/TransformParams`, `/Fields`, or `/Fields` entry locks the field.
- `/Encrypt` is not read as null, because that would treat ciphertext as plaintext. A generation mismatch now throws `PdfParseException`. Previously the library read the object at that number regardless of generation.
- `Internal/PdfParser.cs`: the indirect `/Length` resolver takes the whole reference, so it applies the same rule.
- `Internal/XrefEntry.cs`: the comment now describes field 2 as the generation that `IsLive` compares.
- Tests: `NullReferenceTests.cs` (22 cases) and `ForeignPdfTests.pypdf_free_undefined_and_stale_generation_references_are_null`.
- Fixture: `Fixtures/pypdf-dangling.pdf`, made by `write_dangling` in `generate_foreign_pdfs.py`. pypdf 6.21.1 wrote the deleted field as a free entry (generation 1). The undefined and generation-1 references were added through pypdf's object model.
- `README.md` and `ACCEPTANCE.md` (Opening and AcroForm rows) describe the behavior. No criterion was weakened.

## Verification run

- Independent tools on the fixture: `qpdf 12.4.2 --check` passes and ignores the three references as non-dictionaries. pypdf 6.21.1 resolves all three to `None` and reports only `Name`.
- The 23 new tests failed on the HEAD source and passed after the change (`net8.0`).
- Full suite on Windows: `dotnet test` with qpdf, Poppler 26.09.0, SoftHSM 2, and OpenSSL 3.2.4 passed 336/336 on each of `net8.0`, `net6.0`, and `net48`.
- Linux: `make docker-builder docker-test` passed 336/336 on `net8.0` and `net6.0`.

## Limitations

- A dangling `/Reference` on any signature field, including an approval signature, reads as a `P` 1 certification and blocks every mutation. This is the strict reading of the charter rule.
- A dangling `/Encrypt` keeps its previous rejection. Treating it as null, which would mean the file is unencrypted, is not implemented.
- Evidence level: internally tested, plus independent-tool reading of one pypdf-produced fixture. The fixture's undefined and stale-generation references were placed deliberately; no producer emitted them unprompted.
