# F-5: auto font size and widget `/MK`

## Task

Reproduce the claims that a zero default font size does not fit field width and that regenerated appearances drop widget `/MK`, then classify them against the deliberately small appearance policy.

## Verified facts

- A temporary desired-behavior test filled `WWWW` into a 20-by-24-point field whose `/DA` specified `/Helv 0 Tf`. It failed because the generated stream contained `/Helv 14 Tf`; width was not considered.
- A temporary desired-behavior test supplied `/MK << /BG [1 0 0] /BC [0 0 1] >>`. It failed because the generated stream painted neither color.
- The incremental widget rewrite retained `/MK`, `/BG`, and `/BC`. The original claim that `/MK` is “dropped” is therefore too broad: the appearance builder ignores it, but the dictionary survives.
- After the intentionally failing probes were removed, a retained preservation test and all other `AcroFormTests` passed 35/35 on `net8.0`, `net6.0`, and `net48`.

## Disposition

The width behavior is a Medium appearance limitation; ignored `/MK` colors are Low. `README.md` and `ACCEPTANCE.md` now state both limitations accurately. B-47 awaits an owner decision because fitting width and drawing `/MK` would expand the approved appearance subset. No appearance implementation was changed.
