# B-41: classic xref subsection bounds and QA-B36-02

## Task

B-41, step 1 of the order agreed in `agents/skill-reviews/2026-10-19-skill-plan.md`. Primary skill `pdf-core-change`, verified with `pdf-change-verification`. Evidence level: internally tested, plus an out-of-process heap-limit probe for the resource claim.

## Verified facts

- **Out-of-range subsection headers were accepted.** Before the fix, `ParseClassicXref` cast a subsection's start and count from `long` to `int` with no range check. Headers `-1 1`, `2147483648 1`, and `0 4294967297` opened without error. `2147483647 2` and `0 -1` failed only by accident, on a later row ("Xref entry must end in CRLF..."). Shown by `HardeningTests.classic_xref_subsection_outside_the_object_number_range_is_refused` failing on the unfixed code.
- **QA-B36-02 reproduced.** A classic section was built in full in its own `Dictionary`, then merged into `_xref` while still live, so `Open` held two copies of the map. The unfixed code measured 271.4 bytes allocated per entry and 206.2 bytes per re-listed entry in a `/Prev` chain (`classic_xref_map_memory_grows_with_unique_objects_not_with_prev_sections`, limits 128 and 48).
- **A hybrid section reached through `/Prev` used the wrong precedence.** For such a section, `/XRefStm` entries were merged before the section's own classic table and were never overwritten, so the stream won. ISO 32000-1:2008 7.5.8.4 (page 52) says that when an entry is not found in a standard cross-reference section, the search proceeds to its `XRefStm` stream before the `Prev` section. The table is therefore searched first. `ACCEPTANCE.md` already said a classic xref with `/XRefStm` overrides the stream. The last section behaved correctly. `OpenTests.hybrid_classic_xref_reached_through_prev_overrides_its_xref_stream` returned `Stream` on the unfixed code and `Classic` after the fix.

## Defects confirmed

1. **B-41 (Medium).** Unchecked classic subsection start and count. Fixed.
2. **QA-B36-02 (Medium).** Classic section built beside the merged map, causing `OutOfMemoryException` under a 256 MiB heap. Fixed.
3. **New (Medium).** Inverted precedence between the classic table and `/XRefStm` for a hybrid section reached through `/Prev`. The result was a wrong object version with no error. Found while restructuring the merge, and fixed in the same change because the merge order decides it. A regression test covers it.

## Assumptions and limitations

- **Duplicate rows within one older section.** When an older (`/Prev`) classic section lists the same object number twice, the first row now wins. Before, the last row won. The last section is unchanged: there the last row wins, as before. ISO 32000-1 does not define overlapping subsections within one section. No test covers this.
- **Object-number ceiling.** Classic subsections are not held to the 8,388,608 ceiling that applies to xref stream `/Index` subsections. A classic row costs at least 19 file bytes, so the length-based entry budget already bounds the map.
- **Not automated.** The heap-limit probe is out-of-process evidence, not a test in the suite.

## Decisions needed

None. The precedence fix applies the `ACCEPTANCE.md` row and ISO 32000-1 7.5.8.4. It does not reinterpret them.
