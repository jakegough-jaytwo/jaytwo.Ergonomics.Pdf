## Findings

W-183: Medium harness startup failure. `dotnet publish ... -c Release -o /tmp/seed-repro`, then `dotnet ... seeds /tmp/seeds-before` passes (CMS 19/10 ordinary and 1/28 timestamp); after `sharpfuzz /tmp/seed-repro/jaytwo.Pdf.dll`, identical `seeds /tmp/seeds-after` aborts in `CmsSignatureReader.Read -> CmsSeeds.Build -> SeedWriter.Build -> Program.Main`. No mutated input was executed and no product parser defect is established. Fixed at `dc4ce64` by generating seeds before instrumentation. Permanent regression `tools/fuzz/test-campaign-startup.sh` fails on the old runner and passes on the corrected runner with both targets instrumented, nonzero coverage and zero artifacts. CMS 11,303 executions/713 counters, RFC 3161 16,114 executions/426 counters in the short startup replay; neither short allocation substitutes for this completed rerun. No minimized product input applies: the failure depends on runner ordering, not an untrusted parser input. The complete rerun from corrected code produced no finding artifacts, so no mutation minimization or product regression was needed.

## Limitations

This refresh targets CMS inspection and RFC 3161 parsing only; historical W-18 evidence remains unchanged. Controlled rejection is not cryptographic validation. Smoke and campaign evidence do not constitute an independent security review, a full G8 pass or production qualification. W-182 owns the framework and Docker integration checkpoint.

The logs report an unavailable external symbolizer; coverage counters and finding artifacts are still retained. Since there were no finding artifacts, no symbolized finding stack is claimed. Coverage is aggregate instrumented feedback, not proof that every parser branch or seed class mutated successfully. No additional independent security review was requested or performed by this item.
