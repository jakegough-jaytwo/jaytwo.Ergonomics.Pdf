# F-1: undefined, free, and mismatched-generation references

## Task

Reproduce skill-review finding F-1 without changing parser behavior. The agreed plan reserves the conformance-versus-limitation decision for the owner after a concrete reproduction.

## Verified facts

A temporary `AcroFormTests` probe put each reference in `/AcroForm /Fields` and expected null-object behavior:

1. `99 0 R`, with no xref entry, threw `PdfParseException`: `Object 99 is not in use.`
2. `4 0 R`, whose xref row was free, threw `PdfParseException`: `Object 4 is not in use.`
3. `4 1 R`, while object 4 existed at generation 0, resolved the generation-0 field and returned it instead of treating the mismatched reference as null.

The three focused `net8.0` probes failed exactly in those ways. The temporary tests were then removed so the repository does not retain failing tests before the product decision.

## Expected basis

The skill review cites ISO 32000-1 7.3.10 for treating references to undefined objects, free objects, and nonmatching generations as the null object. The current public contract does not state that behavior explicitly. This is not permission to introduce general PDF repair.

## Decision needed

The owner chooses whether the cited behavior is required in-charter conformance or a documented limitation. Backlog item B-44 records both dispositions and the evidence required for implementation or documentation.
