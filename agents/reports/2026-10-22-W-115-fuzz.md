# W-115 fuzz rerun, 2026-10-22

## Predeclared plan

- Work item: W-115. Its criteria require every fuzz target to be rerun from the changed code at the campaign's predeclared allocation, as in W-108, because the parser, `PdfCursor`, and the stream decoder sit under every target.
- Declared before any target started, after the intermediate W-115 commit `daa81c0`, which carries the code and tests.
- Changed code: the buffer `PdfCursor` serves its array directly; the parser reads names, keywords, strings, and reals through one token buffer, reuses fixed strings from `PdfCommonTokens`, builds dictionaries and arrays at final size, and builds the object-stream repeat set only when object numbers stop ascending; `PdfObject` clones presize; `PdfEngine.Resolve` builds its cycle set at a chain's second reference; the zlib input buffer is sized to what a seekable source has left.
- Targets and allocation: `open`, `edit`, `object`, `objstm`, `decode`, `der`, `tsr`, and `xmp`; 120 seconds per target with 7 workers, the predeclared allocation of the W-18 campaign (`agents/reports/2026-10-22-W-18-fuzz.md`) and the W-108 rerun. Each target's stop condition is completion of its allocation. The scheduled ceiling is 6,720 worker-seconds, or 1.87 CPU-hours; with the W-18 campaign, its rerun, and the W-108 rerun (about 4.58 CPU-hours), the total stays near 6.5 CPU-hours, under D-23's 24-hour cap.
- Per-input limits: 10 seconds and 2,048 MiB RSS; 1 MiB maximum input for `open` and `edit`, and 64 KiB for every other target.
- Seed sources: harness-generated fixture and builder seeds, qpdf and OpenSSL variants from `tools/fuzz/external-seeds.sh`, and the committed minimized inputs in `tools/fuzz/regressions/`.
- Outcome rule: only the documented exceptions in `.agents/skills/pdf-fuzz-qualification/references/targets.md` are controlled rejections. Every other exception, crash, stack overflow, timeout, or memory-limit breach is an artifact requiring reproduction, deduplication, severity, and disposition.
- Completion rule: every target reaches its allocation and every artifact is triaged. A confirmed defect becomes a deterministic regression and the affected targets are rerun from the fixed code.
- Output directory: `out/fuzz-2026-10-22-w115`.

## Limitations

- Elapsed wall time multiplied by worker count is an estimate, not measured process CPU time.
- The runner did not set or record an explicit libFuzzer PRNG seed.
- Coverage counts are not strictly comparable with W-108's, because the changed code has a different set of edges. Against W-108: `open` 8,016 against 7,704, `edit` 12,185 against 11,740, `object` 875 against 744, `objstm` 319 against 278, `decode` 1,247 against 1,127, `der` and `xmp` the same (147 and 55), and `tsr` 424 against 427. The code `tsr` exercises (`DerCodec`, `Rfc3161TimeStampToken`) uses none of the changed types, so its three-edge difference is run-to-run variation.
- The `open`, `edit`, `der`, and `tsr` seed hashes differ from W-108's at the same counts; those seed sets include qpdf and OpenSSL variants generated at run time, as recorded in W-108.
- `xmp` stayed at coverage 55 and `der` at 147; the limits recorded in W-18 still apply.
