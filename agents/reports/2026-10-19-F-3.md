# F-3: button `/Opt` values

## Task

Reproduce the claim that radio-button `/Opt` values are not mapped and classify it against the current public contract.

## Verified facts

The probe used a radio field with `/Opt [(Red) (Blue)]`, widget on-state names `0` and `1`, and `/V /1`.

- A temporary expectation that the second `ExportValue` was `Blue` failed: the actual value was `1`.
- `PdfField.ExportValue` XML documentation already defines the property as the appearance on-state name.
- `PdfAcroForm.SetRadio` XML documentation already requires the appearance on-state name.
- The retained contract test confirms `ExportValue` values `0` and `1`, the second widget selected by `/V /1`, and successful selection of `0` through `SetRadio`.

## Disposition

This is not a defect under the current public API contract. Button `/Opt` mapping is a documented limitation. Changing `ExportValue` semantics or adding another public value would be an owner-approved product/API change.

`README.md` and `ACCEPTANCE.md` now make the limitation explicit. The focused retained test passed 1/1 on `net8.0`; the full AcroForm matrix will run after the remaining step-2 triage.
