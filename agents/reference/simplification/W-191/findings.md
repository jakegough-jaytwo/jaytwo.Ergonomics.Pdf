# W-191: bounded tag preservation and admission

Research, 2026-10-26. Product baseline `c2412525000c48e4651aee80f02b7db71d72a4cf`. Single planning agent; no independent reviewer or product approval is claimed. The four historical review attachments remain unavailable as recorded by W-188. This does not prevent the focused research below; review reconciliation and independent review remain adoption gaps.

## Recommendation

Retain the owner's forms-and-tags preservation principle. Develop a bounded, explicitly described tag-preservation subset with typed refusal outside it. Do not adopt successful silent tag loss as the future default. A temporary whole-input refusal can be approved independently if an earlier fail-closed checkpoint is useful; it is not the final accessibility feature. Keep an explicitly untagged business derivative a separate decision, with no automatic fallback or generic remove-tags API. Exact candidate wording and three separately approvable scopes are in [proposal.md](proposal.md).

Page-local structure is a plausible first slice, not demonstrated coverage of ordinary customer documents. General cross-page paragraphs, tables and lists can require preserving a logical hierarchy independently of page order. The proposed first slice refuses those cases; its real-file acceptance rate is unknown. Support expansion requires evidence, not a broader preservation label.

## Manual semantic procedure

The procedure is intentionally small enough to audit by hand using pypdf object dumps and qpdf JSON. `validate_probes.py` automates the same fixture-specific checks and records the order and failures; it is not a generic accessibility tool.

1. Start at Catalog.StructTreeRoot.K, follow ordered K children, check P reciprocity and stop on a repeated active object. Resolve inherited Pg. Match Pg to the actual page tree, not merely any dictionary. Never infer reading order from the physical page list.
2. For an integer K or MCR, identify the actual page, MCID and owning StructElem. Check page.StructParents -> ParentTree array -> MCID slot -> that element. The fixture's known content grammar has one marked-content sequence with MCID 0 and one printed PageN token; compare those tokens to the expected logical list in the manifest. This grammar deliberately does not generalize to arbitrary stream operators.
3. For OBJR, resolve Obj and Pg, require the annotation/widget in that page's Annots, then check annotation.StructParent -> ParentTree -> owning element. Inspect the Form alternative label and widget TU; inspect Lang, role/class mapping, Alt and ActualText values on the mappings input.
4. Minimal input reads Page1 then Page2. Cross-page input reads Page2 then Page1 inside one element despite physical order Page1, Page2. The form has Page1, Customer-name widget, Page2. Deliberately broken inputs identify invalid-page, parent-mismatch and cycle respectively. Inspect the unmarked-tree case independently of MarkInfo.
5. In outputs check the same root and ownership paths. Their absence establishes loss of those semantics. qpdf independently checks file syntax and JSON ownership-key absence. For a future preservation implementation, expected logical order must be specified before comparing, and repeated-page coverage must be checked in both directions: every retained content/annotation occurrence has exactly one intended owner, and every output tag target names a retained output instance. The current oracle's forward walk alone would miss an unowned extra repeated page.

Missing semantic evidence: no assistive-technology user testing, table/header correctness, list semantics, arbitrary MCID completeness, artifact classification, nested marked content, tagged Form XObjects, PDF 2.0 namespaces, IDTree/Ref relationships, or customer-document accessibility audit. These remain blockers to claims about those properties. Rendering cannot close them.

## Structural responsibilities and code anchors

`PdfPageExtractor.Assemble` builds a minimal catalog with Pages and optional AcroForm. Import creates distinct output page instances and occurrence-local widgets; its PageKeys omit StructParents, AnnotationKeys omit StructParent, and resource Policy removes both. This is the integration point for a future tag importer, not permission to widen the generic copier's resource policy. `PdfAssemblyInspection.Catalog/Page/Resources` inspects enumerated catalog and retained resource structures, explicitly not discarded tag trees or stream bodies. Existing `PdfNewFileLimits` supplies mapped-object/output-page limits of 1,000,000, aggregate structural bytes of 256 MiB, and the shared traversal-depth bound; a future tag graph must charge the same budget, including amplification by output instances. No cumulative CPU claim follows (W-168/W-149 remain separate).

| Structure | Required preservation work / failure boundary |
| --- | --- |
| StructTreeRoot / K / P | Import only the approved hierarchy; register identities before traversal; reject child cycles/multiple ownership. Parent backreferences are legitimate. Root presence and Marked are separate indicators. |
| ParentTree / StructParents | Fresh output number-tree keys per output page instance, not source page number; rebuild sparse MCID arrays including null holes and ParentTreeNextKey. Do not allocate by an unchecked maximum key. |
| MCIDs and MCR | Keep page content encoded and MCIDs unchanged. Rebuild references to output pages. A Stm target needs its own tagged-stream model; refuse it in the first slice. Runtime checks cannot prove actual MCID coverage without interpreting content. |
| RoleMap / ClassMap | Preserve meaningful mappings/attributes and class use. Initially support only compatible identical definitions, refuse conflicts; do not silently use the first input's mapping. Renaming is an alternative with new complexity, not required now. |
| Lang / Alt / ActualText | Carry source effective language into the occurrence wrapper and preserve element overrides and text values. A single output catalog language cannot replace per-input language. Do not synthesize accessible labels from painted text. |
| Reading order / subset | Preserve logical sibling order within supported retained blocks. Selection can omit entire page-local blocks; it cannot silently break a cross-page paragraph, table or list. Empty semantic cells cannot be pruned by a generic empty-node rule. |
| Annotation/widget OBJR | Map Obj to the actual retained annotation instance and Pg to its output page, with fresh StructParent. A dropped meaningful annotation must refuse tag-preserving assembly rather than leave dangling ownership. Link rebuilds need explicit tag integration. |
| Repeated inputs/pages | Separate occurrence identities; clone page-local subtrees per page instance even when immutable streams/resources are shared. Repeated widgets may remain one field within an occurrence (W-190) while each widget has its own tag ownership. |

## Comparison with forms, compatibility and recovery

Forms and tags both need identity maps, pruning rules, bounded graph walking, occurrence isolation, annotation ownership and subsequent-use evidence. Fields chiefly express field/widget identity and values; tags also express ordering, content association, inherited language and potentially cross-page semantic units. Reusing field logic alone cannot preserve those units. Tags therefore earn preservation on the same usefulness principle while needing additional machinery and different tests. A successful fill is not an accessibility test.

Business use: accessible invoices, forms and combined business packets whose reading order/labels remain useful after assembly. Untagged copies may serve visual distribution or an archival intake that explicitly accepts semantic loss; demand for that derivative has not been measured. Keep the original tagged file and obtain a supported source/export when refusal occurs. Re-tagging through an external accessible authoring/remediation workflow may be needed; the engine has no renderer or tagging authoring API. A password cannot recover unsupported structure; encrypted inputs still require existing consent and appropriate credentials. Derivative permission/signature/rights rules remain W-197's responsibility.

W-189 measured 18 tagged files among 51 tracked inputs; eight tagged inputs were among 30 successful default combines (and tags disappeared in eight accepted consent outputs). A blanket tagged rule therefore newly refuses 8/30 previously accepted default inputs, 26.7% of that curated accepted set, not a customer rate. Six are Chrome/Edge/Office documents and two are hybrid public forms with overlapping rights/XFA/script issues. W-189's hypothetical all-preparation scenario recovers 8/12 core newly refused files only when an untagged derivative is added; this is combined-policy modeling, not eight recoveries attributable solely to tags. Tagged+active-content/XFA/rights overlaps must not be double-counted. A bounded preservation subset's gain within those eight is **unmeasured**: tree presence does not classify page-local support. No percentage of real tagged forms is inferred from our one original unscripted form.

## External precedent

Measured with the same minimal, tagged-form and cross-page inputs; subset, reorder and repeat each:

- pypdf **6.21.1** PdfWriter.append produces no StructTreeRoot in all nine outputs and removes page StructParents. This is a copying precedent, not a preservation recommendation.
- qpdf **12.3.2**, `--empty --pages input selection -- output`, produces no tree in all nine; page StructParents remain. Source-primary `qpdf input --pages . selection -- output` retains the tree in all nine. The fixture oracle flags an excluded-page target for each subset. For the minimal reorder, logical tokens remain Page1,Page2 while physical order becomes Page2,Page1; repeat retains tags for the original page instances without establishing ownership for the additional copy. Whole-tree presence is insufficient.
- [PDFBox 3.0.7 merger source](https://raw.githubusercontent.com/apache/pdfbox/3.0.7/pdfbox/src/main/java/org/apache/pdfbox/multipdf/PDFMergerUtility.java) explicitly rebuilds a parent tree and merges K entries, roles and language. This supports the conclusion that tag merge is distinct work. PDFBox was not executed; mode, ClassMap/conflict handling and semantic quality on our fixtures are unverified. No PDFBox behavioral equivalence claim.
- Aspose.PDF is not installed/licensed for these probes; no version-specific tag behavior is inferred. Broader four-library reproduction remains an adoption evidence gap, not a reason to postpone this bounded proposal.

Primary documentation consulted 2026-10-26: [PDF Association syntax guide 1.0.1, sections 3.3-3.6](https://pdfa.org/wp-content/uploads/2023/07/Tagged-PDF-Best-Practice-Guide.pdf) explains language, cross-page logical content, meaningful empty elements and role maps; it informs the refusal boundaries, not a conformance claim. [qpdf page selection and limitations](https://qpdf.readthedocs.io/en/stable/cli.html#page-selection) describes primary-document metadata limitations (served version 12.4.2; measurements use 12.3.2). [pypdf merging guide](https://pypdf.readthedocs.io/en/latest/user/merging-pdfs.html) documents append/selection and field grouping (served version 6.21.2; measurements use 6.21.1). Exact commands and versions in inspection.json take precedence over floating documentation for observed behavior.
