On approval, update phase-2 A6 to A8/A10 and the link paragraphs in ACCEPTANCE.md and docs/behavior.md in the implementation transaction. Coordinate catalog/page admission with W-197's A5a; do not create a second admission pass.

## Exact proposed wording

**R192-1 — Internal navigation.** Assembly supports link `/Dest` and single `/GoTo` actions. A destination must resolve to a valid local page and one of `/XYZ`, `/Fit`, `/FitH`, `/FitV`, `/FitR`, `/FitB`, `/FitBH` or `/FitBV`, with the parameter count and types required by ISO 32000-1 Table 151. Name and string destinations are resolved in that input's catalog destination dictionary or destination name tree and emitted as direct destinations. A self-link targets its own output copy. Any other link targets the first selected copy of its target page within the same input occurrence. Reusing a document as another input occurrence never creates cross-occurrence navigation.

**R192-2 — Exclusion and failure.** A structurally valid destination whose source page exists but is deliberately outside the occurrence's selection omits the complete link and increments `ExcludedDestination`. A missing named destination, dangling or non-page target, invalid destination mode or parameter, unresolved structure, or simultaneous `/Dest` and `/A` refuses assembly before destination writing. An unsupported meaningful action refuses assembly; it is never replaced with an inert annotation. Discarded pages and their annotations are outside inspection except where whole-input inspection already applies. Limits and source-integrity failures retain their dedicated error classes. Malformed source structures use `PdfParseException`; well-formed unsupported semantics use `PdfAssemblyNotSupportedException`. Refusal diagnostics identify the input occurrence and a stable reason, without embedding the URI, filesystem path or host details. Adopt the common diagnostic frame from W-197 rather than duplicating it.

**R192-3 — URI meaning.** With `PreserveSupported`, a single `/URI` action has a required ASCII URI-reference string, no `/Next` entry, and `/IsMap` absent or false. Assembly validates URI syntax, including percent escapes, and rejects whitespace, control characters, backslashes and non-ASCII bytes rather than repairing them. An absolute URI is retained without scheme allowlisting or rejection of userinfo. A relative URI is resolved using RFC 3986 against a syntactically valid, absolute, explicitly supplied source catalog `/URI /Base` that supports relative resolution. The result is absolute. No base is inferred from the source path, stream, output path or current directory. A missing, malformed or unusable base refuses a relative URI. Absolute references do not require a base. The output preserves URI meaning and retains the original ASCII absolute spelling where resolution is unnecessary; it does not decode reserved percent escapes or silently normalize through filesystem conventions. No network request, file opening, action execution, target-existence check or credential validation occurs. A preserved URI is not a safety or trust verdict; applications decide whether and how to activate it.

**R192-4 — Unsupported actions and explicit dropping.** Link `/AA`, any action `/Next` entry (including null), `/IsMap true`, `/Named`, `/GoToR`, `/Launch`, `/JavaScript`, and action types outside R192-1/R192-3 refuse before output. An invalid `/IsMap` type is malformed. No action or file-specification graph is copied by general reachability. `Drop` remains an explicit request to omit URI-link annotations and count `ExternalLinkDropped`; it does not authorize dropping other action types or skipping structural validation. Malformed URI actions, chains and additional actions still refuse. `Drop` needs no usable base for a structurally valid relative URI that will be removed. The option removes the complete annotation, including its appearance; it never leaves a visible nonfunctional link.

**R192-5 — Document and page events.** A valid destination-array `/OpenAction`, or a single `/GoTo` open action with no `/Next`, is initial-view navigation. The new-document rule deliberately omits it and counts `InitialViewDropped` once per input occurrence, including when its valid source target page is excluded. Malformed initial navigation refuses. An action open action outside that subset, nonempty catalog `/AA`, and nonempty selected-page `/AA` refuse before output. There is no first-input-wins rule for initial view. These rules use W-197's bounded inspection frame; they do not scan content streams, discarded pages, earlier revisions, or arbitrary reachable objects.

**R192-6 — Counts and failures.** Results retain fixed-cardinality aggregate counts without URLs, annotation history or objects. `ExcludedDestination` counts per omitted link instance; `InitialViewDropped` counts per input occurrence. No result is returned after a refusal. Preflight completes before destination writing. Existing guarantees for later source/destination failures remain unchanged; preflight is not a promise that serialization cannot fail.

## Why the unsupported subset remains narrow

- `IsMap` changes the URI based on click coordinates. Keeping its base string while losing the flag changes meaning. A future preservation slice would copy the boolean and verify coordinate semantics with appearances/rotation; this packet recommends refusal.
- `/Named /NextPage` is a viewer-relative command, unlike a named destination. Reordering or repeating pages changes its referent. Supporting it needs an approved choice between source-relative and output-relative navigation; neither is inferred here.
- `/GoToR` includes a file specification, remote page number or named target, and window behavior. It is not a URI alias. Supporting relative file specifications would require an explicit source-location policy and a bounded typed copier; this packet recommends refusal.
- `/Next` and `/AA` encode ordered effects and event-triggered effects. Copying only the first action is a semantic loss. Supporting them would expand action scope and cycle/budget handling; this packet recommends refusal.
- Initial view is a documented new-document loss, reconciled with W-197. It is not classified as active content merely because the key is `/OpenAction`. The new count makes the deliberate loss observable.
