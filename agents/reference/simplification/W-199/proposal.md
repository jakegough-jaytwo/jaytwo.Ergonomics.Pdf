## Exact proposed rule

> `PdfDocument.HasUsageRights` is a public read-only Boolean detecting a catalog `/Perms /UR3` entry. It reports structural presence, not signature validity or effective viewer privileges. A UR3 value that is null, dangling, malformed or has unknown transform parameters still counts as present. Absence of Perms or of UR3 returns false. An unresolved Perms follows the existing fail-closed certification policy; a non-null resolved Perms of the wrong type throws `PdfParseException`. No whole-document scan or rights-signature validation is performed. Legacy `/Perms /UR` remains unsupported and is neither interpreted nor removed; this property makes no claim about that legacy mechanism.
>
> `bool PdfDocumentEditor.RemoveUsageRights()` explicitly removes only the current catalog's `/Perms /UR3` entry. It preserves the Perms dictionary and all other keys, fields, widgets, values, appearances, XFA, encryption and unrelated pending changes. It returns true on removal and false when UR3 is absent, with no new edit. It does not regenerate rights, discard signatures, remove passwords or sanitize historical data. Incremental saves preserve prior bytes, including old rights dictionaries and signatures.
>
> Validation order is ordinary disposed/argument checks, bounded Perms resolution and structural presence determination, absent-rights no-op, certification refusal, approval/document-timestamp refusal, password modification permission, then transactional dictionary editing. An unresolved Perms is treated as unresolved certification and throws `PdfCertificationLockedException`; a wrong-type resolved Perms throws `PdfParseException`. The absent-rights no-op may succeed on an otherwise signed, certified or restricted document when Perms is resolvable; this grants no authority for a later mutation.
>
> With rights present, any DocMDP certification, including unresolved certification treated as P1, throws `PdfCertificationLockedException`. Any approval signature or document timestamp throws `PdfSignatureConflictException`. The existing structural signature definition is retained: catalog DocMDP or a signature field whose value resolves to a dictionary; UR3 by itself is not an approval signature, and an unresolved field value does not make that field signed. No trust validation is implied. `AllowBreakingSignatures` does not override either refusal. A user password must allow general modification, otherwise `PdfEncryptionRestrictedException`; an owner password bypasses only encryption permission bits. Unencrypted input needs no credential.
>
> Removal writes no destination. A failure restores the exact state from before that call, including prior pending edits, dirty objects and cache-visible rights state. Earlier successful preparation remains pending after a later call fails. A second removal returns false. Editor disposal does not undo successful removal. Save/signature failures retain the existing pending-state and best-effort physical-destination restoration guarantees; an in-memory rollback does not prove that a destination is safe to retry.
>
> Ordinary operations never remove UR3 as a side effect and do not interpret its grants. On an otherwise unsigned document with UR3 present, a nonempty fill, flatten, metadata edit, attachment edit, page rotation, signature or document timestamp throws `PdfUsageRightsPreparationRequiredException` before applying changes or calling host signing/timestamp code. This new public sealed `PdfException` subtype identifies the need for explicit removal; its diagnostic states that modification permission and loss of viewer rights apply. It carries no raw objects or host exception details. Save merely serializes accepted pending edits; it is not itself a preparation trigger. Reads/export and existing empty no-ops remain available. Ordinary certification, FieldMDP, permission and argument/field checks retain their current precedence; the new rights check runs after checks that can already refuse, before mutation. Hybrid fill/flatten also require W-198 preparation and retain its proposed earlier hybrid diagnostic. Signing checks rights before creating its own signature dictionary so the first signature cannot bypass the unsigned rule.
>
> On a document already carrying an approval signature, certification or document timestamp, existing permitted ordinary writes preserve Perms unchanged, as D-45 requires. This exception does not permit explicit rights removal, XFA abandonment or an operation otherwise refused by signature, certification, FieldMDP or password policy. The engine makes no promise that a viewer continues to enable the retained rights. Assembly refusal is a separate whole-input rule, including on signed inputs; it does not use this ordinary-write exception to bypass W-197's proposed admission policy.
>
> If both rights removal and hybrid-XFA abandonment are required, call removal first, then `AbandonXfa`, then the intended operation. Removal alone does not remove XFA; abandonment with remaining rights refuses. There is no transaction spanning those calls: failed abandonment keeps a prior successful removal pending. Reads and engine assembly observe pending preparation in the same open document; no intermediate save is needed. Workflow Combine performs no implicit preparation and gains no new preparation option in this slice.

The new exception name and public detection are proposed API surface, not current API. A malformed UR3 payload need not be parsed to remove its entry; required surrounding object/traversal failures keep existing typed failures. No new generic input-policy framework or raw object access is proposed.
