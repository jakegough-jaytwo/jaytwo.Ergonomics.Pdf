## Exact proposed wording

Add the following ordinary-form paragraph to phase-2 section 3's form-field rule; retain signature-field policy as a separate row pending W-194:

> Extraction and concatenation preserve supported non-signature fields with widgets on selected pages. Each input occurrence is assigned the synthetic top-level field name `InputN`, where N is its positive, 1-based position in the input sequence, written in invariant decimal without leading zeroes. Positions are counted even for an occurrence selecting no pages or retaining no fields. Extraction has one occurrence, `Input1`. A synthetic parent is emitted only when that occurrence retains fields. Original partial names and their tree order remain below that parent; a source full name `Group.Name` therefore becomes `InputN.Group.Name`. Naming does not depend on collisions, file names, document identity or output page numbers. Fields from different input occurrences are never joined by name or by shared source identity.

> A source field has one output field identity per input occurrence. Selecting several of its pages retains only the selected widgets, including every selected widget of a multi-page field. Repeating a source page makes distinct output page and widget instances belonging to that occurrence's same field. Filling that field affects all its retained widgets; callers needing independent values use separate input occurrences. Each retained widget is an indirect annotation, belongs to exactly one output page instance, has a `/P` referring to that page and a `/Parent` referring to its output field, and appears in that field's `/Kids` and that page's `/Annots`. Merged field/widget dictionaries are split. Empty ancestors and fields without selected widgets are pruned. Retained branches preserve source field-tree order; copied widgets of one field follow output page order and then source annotation order. Immutable appearance, font and content resources may be shared; field and widget identities must remain independent between input occurrences.

> Retained fields preserve their supported effective field type, flags, current and default values, option values, alignment, field geometry, default-appearance dependencies and editability. Required inheritance is retained or materialized without changing its meaning. Page media box, crop box, resources and rotation preserve their effective inherited values. Required default fonts are copied with occurrence-local resource names and default-appearance references are rewritten consistently. Existing content and appearance streams retain their encoded bytes and filter parameters, apart from the already documented removal of input encryption. Text, choice and button values, widget states and appearances must remain consistent after assembly and subsequent supported fills. No automatic flattening, value joining, viewer regeneration or content-stream decoding is used to hide a preservation failure. An existing `/NeedAppearances true` remains visible to the caller and retains the existing fill, flatten and signing restrictions; assembly does not claim that a viewer can draw every value.

> Inspection of ordinary forms includes the non-signature AcroForm field topology and its field/widget action dictionaries and calculation order before pruning, the selected page annotation lists, retained field dictionaries and ancestors, effective form defaults and required default resources, and retained widget appearance/state/resource graphs. Unsupported field/widget actions, nonempty calculation order, cyclic or multiple ownership, unresolved inspected references, ambiguous field identity, unsupported effective field semantics/defaults, and an unpreservable selected widget or required appearance refuse the operation with a typed error before the first destination byte. Selection of unrelated pages does not bypass the whole-form topology/action/calculation checks. Intentionally unselected widgets and their empty branches are excluded by selection. No silent widget or appearance omission is permitted for a retained ordinary form. Local appearance-budget exhaustion refuses the operation; global structural-budget exhaustion retains its dedicated resource-limit error. Inspection remains bounded by the documented structural and appearance limits and does not scan or execute page content or arbitrary reachable objects. Failures while later reading/copying/writing retain the separate documented engine/workflow failure guarantees.

Replace only the ordinary-form widget part of A9 with:

> A selected non-signature form widget and its supported appearance/state/resource graph are preserved under the documented structural limits. An unsupported, unclassifiable, unresolved or locally over-budget required form appearance refuses the operation before output; it never produces successful widget omission. A global resource-limit or source-integrity failure aborts. The existing omission rule for other annotation kinds is unchanged by this ordinary-form requirement.

Proposed ACCEPTANCE.md / docs/behavior.md ordinary-form paragraph:

> Ordinary selected fields retain occurrence-local names, values, inheritance, editability and supported appearances. `InputN` uses the input's 1-based position even when an earlier input has no selected pages. Repeated pages produce distinct page-owned widgets of one field within an occurrence; separate occurrences produce independent fields. Unselected widgets and empty ancestors are pruned, merged field/widgets are split, default fonts and DA references are remapped, and immutable resources may be shared. Whole-form topology/action/calculation checks and retained defaults/appearance inspection are bounded. An ordinary-form widget that cannot be preserved refuses before output, including a local appearance-budget failure; it is never silently omitted. Global budgets retain PdfResourceLimitException. The existing late source/destination failure guarantee still applies. Signature fields, other annotation subtypes and document-level omissions retain their separately adopted contracts.

No spec status change is made now: the owner must adopt exact text first, and implementation would then update the affected New/Change statuses and shipped contract under D-43. ## Approval choices and limits

Recommendation: approve the namespace/ownership wording as a preservation baseline, and adopt the ordinary-widget refusal change once W-192/W-197 have reconciled admission/annotation wording. Do not change the public meaning of `UnsupportedAppearance` for all annotations incidentally. LastModified demonstrates that an unsupported classification can be a safe-copy opportunity; its omission does not justify refusing every form or removing forms entirely.

The tradeoff is concrete: a caller who currently gets an incomplete file from E190-9 would receive either a fully preserved file after bounded support or a typed refusal. Retaining InputN and editable forms has no naming migration; refusal needs host error handling and a supported input or separately approved preparation. No customer refusal total, complete field-type coverage, independent-review sign-off, or broad deletion saving is available. The owner's settled independence principle is retained; independent source-review arrangements remain a gap for final reconciliation, not a claim supplied by tools.
