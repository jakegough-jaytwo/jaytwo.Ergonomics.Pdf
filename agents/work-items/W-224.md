# W-224. Restore metadata state when an edit fails after its first provisional change

## Problem

META-A9 (METADATA-SYNC-01, METADATA-FAIL-01): on I/O failure or observed cancellation after provisional Info or XMP changes, both stores, the date-override state and earlier pending edits must match their pre-call state. The ordinary edit path changes Info first and reads the XMP packet from the source afterwards, with no rollback.

## Scope and exclusions

Determine the behavior with a controllable source (an `IPdfSource` that throws at the nth read); fix the smallest thing that restores state; add regression tests. Observed cancellation: the metadata members take no cancellation token, so there is no point to reach; recorded as untested, not simulated. Out: destination or save failures, the adopted contract text, and an incremental save dropping an unedited direct trailer Info (observed, separate).

## Acceptance criteria

- A failure at each reachable late read leaves Info, XMP, version, ModDate override and earlier pending edits as before, in the open document and after Save/reopen.
- The new tests fail without the fix.

## Evidence required

`MetadataFailureTests` against old and new code; metadata tests; full net10.0 suite; build; `make task-check`.

## Closeout

2026-11-01: defect confirmed. A sweep over an injected `IOException` at the nth source read reached three read points per edit (the first is the pre-mutation check; the later ones run after Info has changed). Without the fix all seven tests failed: after the failure the open document reported the new Title or a cleared Title, a changed ModDate, and a failed explicit ModDate assignment or clear had set the override (the next ordinary edit did not refresh ModDate). Fix: `PdfInfoMetadata.Atomic` wraps the mutating part of `SetInfoText`, `SetTrapped` and `SetInfoDate` in the object store's backup/restore (the mechanism fill and flatten use) and also restores the direct trailer Info reference and `_modDateExplicit`. Seven tests in `MetadataFailureTests` (class carries `Lane.Sweep`, D-52) pass with the fix.

Checks run: `MetadataFailureTests` net10.0 7/7 (all fail on the old code); metadata, fuzz-regression and failure tests net48 61/61; full `jaytwo.Pdf.Tests` net10.0 4821/4821; fast lane net10.0 passed; Ergonomics tests net10.0 202 passed, 3 skipped; `make quiet-build` (StyleCop as errors); `make agents-check`, `make task-check`.

Not reached or not run: observed cancellation (no token on the metadata members), failure after an earlier metadata edit in the same session (the packet is then in memory, no source read), destination write failures, Docker checkpoint, independent-reader checks. Observation outside scope: an incremental save of an unedited direct trailer Info dictionary does not carry the Info forward (probe: Title Old before, absent after reopen).
