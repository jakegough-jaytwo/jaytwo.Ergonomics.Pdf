# W-213. Make the README the project's intent anchor and move shipped behavior to docs/behavior.md

## Problem

The owner asked for a focused README that anchors the project's intent, so later work can be checked against it. The README was 276 lines and about 10,000 words, almost all shipped-behavior detail (support matrix, limits, failure semantics, workflow rules). Its scope section had drifted: it listed page rotation as a 1.0 target after rotation shipped.

## Scope and exclusions

Rewrite `README.md` from the charter and `reset.md` as a short statement of purpose, the two libraries, what they do and never do, commitments, tenets, a fit test, one example, and status. Move the shipped-behavior text verbatim into `docs/behavior.md` and the build section into `CONTRIBUTING.md`. Redirect the rules that name `README.md` as the shipped-behavior contract (authority order, D-43 shipping rule, quirk and limit entries, G1 support matrix) to `docs/behavior.md`, with the owner's approval of the protected wording; skills and `QUALIFICATION.md` follow under D-47. Two test comments that cite README sections follow.

No behavior text is reworded, shortened, or dropped; tightening `docs/behavior.md` is separate work. G10 ("README examples compile and run") is unchanged because the README keeps an example. Historical decisions and closed work items keep their README references.

## Acceptance criteria

- `README.md` states purpose, boundaries, and commitments consistent with `AGENTS.md`, and no longer carries the support matrix or failure semantics.
- Every non-empty line of the old README is present verbatim in `docs/behavior.md`, `CONTRIBUTING.md`, or `README.md`, except the superseded scope list, its stale 1.0 and later paragraphs, and retired headings.
- No maintained rule, spec gate, skill, or test comment names `README.md` as the home of shipped behavior, quirks, limits, or the support matrix.

## Evidence required

A line-presence script comparing the old README with the new files; `make agents-check`; staged `make task-check`; `git diff --cached --check`. Documentation only: no runtime tests, graph rebuild, or Docker checkpoint.
