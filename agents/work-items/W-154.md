# W-154. Correct encryption permissions and expose authentication outcomes

## Problem

Encrypted-document callers cannot distinguish authentication role or failure cause without inference or message parsing. Page-rotation permission handling also needs a specification-backed determination between assembly and general modification permission.

## Scope and exclusions

Confirm the applicable PDF permission rule for rotation, correct the engine if required, add typed encrypted-open failure reasons, and expose owner-versus-user authentication separately from declared permission flags. Preserve supported algorithms and the rule that an owner password bypasses permission restrictions.

## Acceptance criteria

- Rotation under a user password follows the cited PDF-standard permission bit, with fixtures that distinguish `CanAssemble` from `CanModify`.
- Callers can distinguish missing credentials, rejected passwords, malformed encryption data, and unsupported encryption without parsing exception messages.
- The authenticated role is observable independently of the document's declared permission flags; unencrypted documents have an explicit documented outcome.
- Existing R2 through R6 password and permission behavior remains covered on all supported target families.
- Public behavior documentation is updated with the contract.

## Evidence required

Focused encryption and rotation-permission tests on net10.0 and net48, plus independent qpdf-produced fixtures for the affected revisions.

## Notes

- Source backlog identifier: SEC-007.
- Permission determination: [ISO 32000-1:2008, 7.6.3.2 Table 22](https://opensource.adobe.com/dc-acrobat-sdk-docs/standards/pdfstandards/pdf/PDF32000_2008.pdf): bit 4 excludes operations controlled by bit 11; bit 11 grants page insertion, rotation, and deletion for revision 3 and later. Revision 2 assembly follows bit 4. The existing rotation gate incorrectly used bit 4 for every revision. The permanent regression is `PageTests.rotation_uses_assembly_even_when_modify_disagrees`, with qpdf-generated revision 3 through 6 inputs granting each flag independently. The separate revision 2 test preserves its rule.
- Missing/malformed encryption fields and dictionaries now carry `MalformedEncryption`, while unsupported handlers/revisions/configurations carry `UnsupportedEncryption`. An AES permission-block mismatch after successful authentication is malformed data, not a rejected password. Authentication algorithms and permission flags are retained; role disclosure is additive.
- Structural invariants: no source buffering or allocation based on PDF size was added; `/P` retains signed handling plus D-57; plaintext exceptions and encryption algorithms are unchanged. Rotation tests retain the original prefix, refused writes remain byte-identical, and existing encryption round-trip tests cover the cipher and trailer invariants.
