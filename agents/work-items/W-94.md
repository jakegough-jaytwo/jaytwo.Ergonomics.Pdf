# W-94. State the external test tools without a per-class list

## Problem

The `AGENTS.md` paragraph on external test tools names test classes per tool, and the list has drifted. It names `ForeignPdfTests` and `SigningInteropTests` for qpdf and Python, but at least `AttachmentTests`, `CorpusTests`, `UsageRightsTests`, `InteropTests`, and `WriterQuirkTests` also use them (W-93 noted this for `UsageRightsTests`). Test files that reference an external tool on 2026-10-20: `AppearanceRenderTests`, `AttachmentTests`, `CorpusManifest`, `CorpusManifestTests`, `CorpusTests`, `DenseMemoryTests`, `ForeignPdfTests`, `InteropTests`, `LargeWorkloadTests`, `OpenSslTimestampAuthority`, `OpenSslTimestampTests`, `SigningInteropTests`, `UsageRightsTests`, `WriterQuirkTests`. A per-class list goes stale whenever a test is added.

## Why now

The owner asked on 2026-10-20, after W-93, for an item to fix it at the owner's computer. `AGENTS.md` changes only with the owner's approval, so the owner makes or approves the edit.

## Scope and exclusions

- `AGENTS.md`: replace the per-class tool paragraph with a general statement of the tools, their environment variables, and the fail-not-skip rule.
- Before the edit, confirm the tool set is complete by checking every `ExternalTool` use in `test/`, and that the Linux `base` stage of the `Dockerfile` installs each tool.
- Excluded: changing how tests find tools, and the CI section's rule that a test needing a new tool adds it to the `Dockerfile`.

Draft for the owner (not yet approved). Current text:

> Tests may use external tools. `ForeignPdfTests` and `SigningInteropTests` require qpdf (`JAYTWO_QPDF` or `PATH`) and Python with pyHanko and pypdf. `AppearanceRenderTests` requires Poppler (`JAYTWO_POPPLER` or `pdftotext` on `PATH`). `SigningInteropTests` also requires SoftHSM 2 (`JAYTWO_PKCS11` pointing at `softhsm2-x64.dll` on Windows or `libsofthsm2.so` on Linux, with `softhsm2-util` in the sibling `bin` directory or on `PATH`). `OpenSslTimestampTests` and `UsageRightsTests` require OpenSSL 3 (`JAYTWO_OPENSSL` or `openssl` on `PATH`) as a local RFC 3161 authority and token verifier. Those tests fail when a tool is missing. Those tools are not runtime dependencies.

Proposed text:

> Tests may use external tools: qpdf (`JAYTWO_QPDF` or `PATH`); Python with pyHanko and pypdf; Poppler (`JAYTWO_POPPLER` or `pdftotext` on `PATH`); SoftHSM 2 (`JAYTWO_PKCS11` pointing at `softhsm2-x64.dll` on Windows or `libsofthsm2.so` on Linux, with `softhsm2-util` in the sibling `bin` directory or on `PATH`); and OpenSSL 3 (`JAYTWO_OPENSSL` or `openssl` on `PATH`) as a local RFC 3161 authority and token verifier. A full test run needs all of them. A test that uses a tool fails, rather than skips, when the tool is missing. Those tools are not runtime dependencies.
