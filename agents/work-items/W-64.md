# W-64. Switch the target frameworks

## Problem

The library targets `net8.0`, `net6.0`, `netstandard2.1`, and `netstandard2.0`, and the tests run on `net8.0` and `net6.0` (plus `net48` on Windows). D-38 and D-40 set the targets to `netstandard2.0`, `net6.0`, `net8.0`, and `net10.0`.

## Why now

Reset plan C2 item 2. Later items build and test on the final targets.

## Scope and exclusions

- Library: `netstandard2.0;net6.0;net8.0;net10.0`. Tests: `net6.0;net8.0;net10.0`, plus `net48` on Windows.
- Update the test project's `System.Security.Cryptography.Pkcs` condition, the `Dockerfile` SDK and runtimes, `Makefile` `unit-test`, the `AGENTS.md` CI line (exact text shown to the owner), and README's build line.
- Mark D-13 superseded by D-38 and D-40.
- Excluded: the D-39 package (the async item adds it), and any source change beyond what a new target requires.

## Acceptance criteria

- Every target builds with StyleCop warnings as errors.
- The suite passes on Linux `net6.0`, `net8.0`, and `net10.0` (`make docker-builder docker-test`) and on Windows `net48`.
- `make pack` shows the four target groups, with only `System.Memory` on `netstandard2.0`.

Refine these criteria, and the `ACCEPTANCE.md` rows they add or change, when the item becomes active. A write item also meets every check in plan C4.

## Evidence required

Build, test, and package evidence on both platforms.

## Notes

- 2026-10-20: Created under W-63 from `agents/reference/charter-reset-plan.md` C2.

- 2026-10-20: The owner approved the `AGENTS.md` CI line (net10.0, net8.0, and net6.0 on Linux; net48 on Windows).
- 2026-10-20: The local system SDK is a 10.0 release candidate (`10.0.100-rc.1`). It does not prune framework-provided packages, so NuGet audit flagged xunit 2.4.1's transitive `System.Net.Http` and `System.Text.RegularExpressions` 4.3.0 (NU1903). Pinning patched versions then failed on the GA SDK with NU1510, because GA prunes those packages. The pins were removed; GA SDK 10.0.402 restores cleanly with no audit warning. A GA toolchain was installed at `%LOCALAPPDATA%\jaytwo-tools\dotnet` for local runs.
