# W-116. Decide whether writes may detect certification without walking the field tree

## Problem

Even after W-114, the first write on a document walks the whole field tree to find a certification, where iText does no walk. Skipping it would mean deciding certification from the catalog `/Perms /DocMDP`, and possibly from AcroForm `/SigFlags`, instead of from each signature field. That changes a documented certification rule.

## Why now

The owner asked for a brief to take to a separate reviewer: `agents/reports/2026-10-22-certification-detection-brief.md`.

- Excluded: implementation.

## Acceptance criteria

## Closeout

Done: the owner kept the walk (D-58). No code changed.

The outside review, of the brief's questions:

1. ISO 32000-1 §12.8.1 says a certification's signature dictionary "may also be referenced" from `/Perms /DocMDP`, and Table 258 makes the entry optional. A certification referenced only from its signature field can be conforming. ETSI EN 319 142-1 V1.2.1 §4.1 and §5.3 add no catalog requirement. ISO 32000-2's normative wording was not checked, which is a research note, not a blocker.
2. Validators: the review found field-tree enumeration in iText's `SignatureUtil`, and catalog-only certification in older iText `GetCertificationLevel`. It did not establish how Acrobat, pyHanko, or iText 9.8.0 treat a certification that exists only in a signature field.
3. Producers: PDFBox and EU DSS write both the field reference and the catalog entry. No producer was found that writes a certification without the catalog entry. `/SigFlags` is optional, and bit 1 only means that if it is set, a signature field exists, so a clear bit proves nothing.
4. Recommendation: A. B and C cannot show that a document is uncertified. D would skip the walk on exactly the metadata and attachment writes where missing a certification found only in a field would break the guarantee.
5. No cheap strict signal: cross-reference and revision data do not classify objects, and a byte scan is unreliable.

Existing implementation, against the review's suggested optimizations (`PdfWriteGate`): it already skips the walk when the catalog has no AcroForm or the AcroForm has no `/Fields`. The walk visits only signature fields and is cached per revision (W-114). A cycle, an over-deep tree, or a dangling `/Perms` fails closed. Not taken: an early return when the catalog says `P` 1, and profiling the remaining allocation (D-58 Consequences).
