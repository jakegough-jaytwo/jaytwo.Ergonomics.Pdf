# W-145. Form-export read shortcut

## Problem

`reset-plan.md` section 8 allows read shortcuts only where they reduce real ceremony. D-60 adopts one: exporting a file's form values without managing a document's lifetime (spec F16).

## Scope and exclusions

Implement `PdfWorkflow.ExportFormValues(path, options)` and `ExportFormValuesAsync(path, options, cancellationToken)`.

Excluded: any other read shortcut, and any inspection the engine does not already provide.

## Acceptance criteria

- Each returns the same values as `PdfDocument.AcroForm.Export()` on the same file, and reads no more source bytes.
- The file is closed after success, failure, and cancellation. The password option opens an encrypted file.

## Evidence required

Focused `jaytwo.Ergonomics.Pdf.Tests` on net10.0 and `make quiet-build`.

## Closeout

- `PdfWorkflow.ExportFormValues(path, options)` and `ExportFormValuesAsync(path, options, cancellationToken)` bind the path through `WorkflowInput.OfFile`, open it through the same `WorkflowInput.OpenAsync` the terminal calls use (read access, read sharing, asynchronous file I/O in the async form), and return `PdfDocument.AcroForm.Export()`. The session closes the document and the file on success, failure, and cancellation. Argument errors come from `OfFile`; in the async form they fault the task, as the builder's async terminal calls do. The engine is unchanged.
- Tests: `WorkflowExportTests`, on two new fixtures, a filled `WorkflowPdf.Form` (now with optional unreferenced padding, object 21) and `WorkflowPdf.EncryptedForm` (AES-128, user password `user`). The export equals the direct engine export, sync and async; a file without a form exports none; the password opens the encrypted file and its absence throws `PdfEncryptedException`; the file reopens exclusively after success, failure, and a pre-canceled async export (the file is opened before the engine observes the token); null and empty paths throw. "Reads no more source bytes" is falsified on Windows by a byte-range lock on the middle of a 3 MiB unreferenced stream: a whole-file read fails under the lock, and the direct engine export and both workflow exports succeed.
- `make quiet-test TEST_PROJECT=./test/jaytwo.Ergonomics.Pdf.Tests TEST_FRAMEWORK=net10.0`: 113/115 passed, 2 skipped (the Linux-only symbolic-link tests).
- `make quiet-build`: pass.
- Spec F16 is Exists (D-43). `README.md` (Supported today item 9, Usage › Workflows) and `ACCEPTANCE.md` (Workflows) describe the shipped behavior.
- No defects were found. Limitation: the read-equivalence test runs on Windows only, because a byte-range lock does not block reads on Linux or macOS; elsewhere the criterion rests on the shortcut making exactly the engine's open and export calls. Not run: net48, net8.0, and net6.0 (no framework-specific code), and the Docker checkpoint, which W-146 runs.
