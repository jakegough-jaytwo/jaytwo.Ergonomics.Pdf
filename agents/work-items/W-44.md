# W-44. Unresolvable references are null (F-1)

## Problem

Skill-review finding F-1. With each reference placed in `/AcroForm /Fields`:

1. `99 0 R`, with no xref entry, threw `PdfParseException`: `Object 99 is not in use.`
2. `4 0 R`, whose xref row was free, threw the same.
3. `4 1 R`, while object 4 existed at generation 0, resolved the generation-0 field instead of treating the mismatched reference as null.

ISO 32000-1 7.3.10 treats references to undefined objects, free objects, and nonmatching generations as the null object. The public contract did not state either behavior.

## Why now

The skill plan (D-27, step 2) asked for a reproduction and then an owner choice between in-charter conformance and a documented limitation. The owner chose conformance under D-26.

## Scope and exclusions

Under D-26: undefined, free, and mismatched-generation references resolve as null. The charter rule that a certification that does not resolve is treated as `P` 1 stands, and extends to null certification and FieldMDP lock data. No general repair heuristics.

## Acceptance criteria

Those references resolve as null across reads and edit paths. Edit paths do not write through a dangling reference. Null certification or FieldMDP lock data still locks. Regression tests fail on the unfixed source. An independent reader agrees on a foreign fixture. `README.md` and `ACCEPTANCE.md` describe the behavior, and no criterion is weakened.

## Evidence required

Not stated in the original entry. Internally tested, with qpdf and pypdf reading one pypdf-produced fixture.

## Closeout

Accepted under D-26 at the internally tested level. One pypdf-produced fixture was also read by independent tools. `Resolve` returns null for a reference that `IsLive` rejects: no xref entry, a free entry, an unknown entry type (ISO 32000-1 7.5.8.3), a type 1 entry with a different generation, or a compressed object named at a generation other than 0. Edit paths (`/AcroForm`, `/DR`, `/DR /Font`, `/Helv`, `/Names`, `EditArray`, and `/Info`) create a new object instead of writing through a dangling reference. Null certification or FieldMDP lock data still locks. A generation mismatch on `/Encrypt` throws `PdfParseException`. The indirect `/Length` resolver applies the same rule. 23 regression tests (`NullReferenceTests.cs` and `ForeignPdfTests.pypdf_free_undefined_and_stale_generation_references_are_null`) failed on the unfixed source and now pass. qpdf 12.4.2 and pypdf 6.21.1 read `pypdf-dangling.pdf` the same way the library does. Full suite: 336/336 on Windows `net8.0`, `net6.0`, and `net48`; `make docker-builder docker-test` passed 336/336 on Linux `net8.0` and `net6.0`. Limitations: a dangling `/Reference` on any signature reads as `P` 1, and a dangling `/Encrypt` is rejected rather than read as null. Report: `agents/reports/2026-10-19-B-44.md`. Completed 2026-10-19.
