# W-112. Add iText to the compatibility tests

## Problem

W-111 found that iText 9.8.0 cannot open this library's incremental output on a file whose last section is a cross-reference stream. None of the independent tools in the suite (qpdf, pypdf, pyHanko, Poppler, pdfsig) catches it. iText is one of the most common readers of the PDFs this library writes.

## Why now

The owner asked on 2026-10-22 to add iText to the compatibility tests, and accepted AGPL for testing and CI.

## Scope and exclusions

- The test project references iText Core 9.8.0 (`itext`, `itext.bouncy-castle-adapter`) on every target. Packages are test-only, so `AGENTS.md` needs no change.
- An `IText` helper opens a file with iText and fails when iText had to rebuild the cross-reference (`PdfReader.HasRebuiltXref`), so a reconstructed read never passes.
- `ITextInteropTests` on built fixtures. iText reads back:
  - the Info and XMP metadata edits;
  - single and bulk fills;
  - a flatten;
  - attachment bytes;
  - a rotation;
  - fills and signatures on AES-256 and 128-bit RC4 files under each password.

  iText's `PdfPKCS7.VerifySignatureIntegrityAndAuthenticity` accepts RSA and ECDSA signatures in both formats, and the first of two signatures after a later revision.
- The G2 corpus write tests (metadata revision, fill, bulk fill, flatten) also check every output with iText: it opens without a rebuild, the page count and terminal field names agree, a filled value reads back, and each earlier signature still verifies.
- Excluded: outputs on sources whose last section is a cross-reference stream. iText cannot read them until W-117. The corpus check finds those 14 sources from their last cross-reference section and skips only them, and `ACCEPTANCE.md` states the gap.

## Acceptance criteria

- The new tests pass on net10.0, net8.0, net6.0, and net48, and in `make docker-builder docker-test`.
- `ACCEPTANCE.md` names iText as an independent reader and states the cross-reference-stream exclusion.

## Evidence required

Independently validated with iText 9.8.0.

## Notes

- 2026-10-22: iText quirks the checks allow for: it names a kid whose `/T` is empty with a trailing period (`Service.` on the LibreOffice radio groups, where pypdf and this library report `Service`), and `PdfDocumentInfo.GetTitle` returns the XMP `dc:title` when the file has XMP, so the helper reads the trailer `/Info` `/Title` directly. Neither is a defect in this library's output.
- 2026-10-22: Corpus sources ending in a cross-reference stream, skipped until W-117 (14 of the 41 corpus entries): `cms-40b-pyhanko-approved`, `cms-40b`, `faa-8710-1`, `frb-beige-book-2024-01`, `grants-sf424-v4`, `inkscape-network`, `irs-f1040es-2026`, `irs-fw9-2024-03`, `nist-sp1271`, `opm-of306-pyhanko-certified`, `opm-of306`, `uscis-i9-2025`, `va-21-4138`, and the foreign fixture `qpdf-object-streams`. The hybrid `excel-invoice`, `powerpoint-photos`, and `word-report` end in a classic table and are checked.
- 2026-10-22: The first `make quiet-docker-test` reported one `net8.0` failure without a name. Its `docker run` had hit a name conflict with another session's running `jaytwo_ergonomics_pdf__builder` container, and the summaries came from that container. The fixed image and container names let concurrent Docker runs report each other's results; W-118 proposes unique names.

## Closeout

- Observed: iText 9.8.0 reads every write path's output on classic and hybrid sources and verifies the signatures; the corpus check agrees on the 26 classic-ending sources that open.
- Verification: Windows `make quiet-test TEST_FILTER="FullyQualifiedName~ITextInteropTests|FullyQualifiedName~CorpusTests"` 217/217 on each of `net10.0`, `net8.0`, `net6.0`, and `net48`; `make quiet-build` passed. Linux builder image under the unique tag `jaytwo_ergonomics_pdf_w112`: `make quiet-test` 4335/4335 on each of `net10.0`, `net8.0`, and `net6.0`.
- Limitations: Outputs on sources ending in a cross-reference stream are not checked until W-117. iText's verification is integrity and authenticity only, with no trust or revocation. Completed 2026-10-22.
