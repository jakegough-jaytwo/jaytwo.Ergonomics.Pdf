# W-222. Refuse ordinary metadata edits that must touch an unsafe existing XMP packet

## Problem

METADATA-VALIDATE-01 and METADATA-SYNC-01 refuse an ordinary edit that must touch an existing packet that cannot be edited safely, with no Info-only fallback. The code instead updates Info and leaves a malformed packet, a packet with another root, or one without `rdf:RDF` unchanged and reports success. Two tests pin that result.

## Scope and exclusions

Owner-approved on 2026-11-01, including the intentional caller-visible change from success to `PdfXmpException`. In: refuse before Info, ModDate, XMP or earlier pending edits change; replace the two pinning expectations; update behavior and acceptance records; correct the "Remaining gaps" note in `docs/spec/metadata.md` for W-221 only. Out: opening, reading and raw replacement, fault injection (META-A9), clear-with-no-packet behavior, any other contract text.

## Acceptance criteria

- Malformed, other-root and no-`rdf:RDF` packets each refuse every touching edit with no change; earlier pending edits survive.
- Open, read and `SetXmp` behave as before.
- The new tests fail against the previous implementation.

## Evidence required

Focused `MetadataTests` and `FuzzRegressionTests` run against the old and new code; full net10.0 suite; Ergonomics tests; `make quiet-build`; `make task-check`.

## Closeout

2026-11-01: `CheckXmpEdit` now runs before any Info change for an edit that touches a mapped key or refreshes ModDate (unless an explicit override is in force): an existing packet that fails to parse throws `PdfXmpException`, and so does one whose root is neither `rdf:RDF` nor `x:xmpmeta` containing it. The silent Info-only fallbacks in `SyncXmp` became errors (unreachable after the pre-check). The two pinning tests were replaced (`xmp_without_rdf_refuses_an_info_edit_with_no_change`, `malformed_xmp_opens_and_reads_as_an_error_and_refuses_an_edit_with_no_change`) and four tests added covering 3 malformed and 3 well-formed unsupported shapes, a retained earlier raw replacement, and unchanged open/read. Against the old code 8 tests failed (7 refusals plus the replaced FZ-3 test; the open/read test passes either way by design). `docs/behavior.md`, `docs/acceptance.md`, the public XML docs and the `docs/spec/metadata.md` "Remaining gaps" parenthetical (W-221 only) updated.

Compatibility change: an ordinary metadata edit on a document whose existing XMP is malformed or not an rdf:RDF packet now throws `PdfXmpException` and changes nothing, where it previously succeeded Info-only. Callers replace the packet with `SetXmp` first.

Checks run: focused `MetadataTests` + `FuzzRegressionTests` net10.0 (49/50 before the second pinning test was found, then green); full `jaytwo.Pdf.Tests` net10.0 4810/4810; Ergonomics tests net10.0 202 passed, 3 skipped; net48 focused 50/50; `make quiet-build` (StyleCop as errors); `make agents-check`, `make task-check`. Not run: other frameworks' full suites, Docker checkpoint, independent-reader checks, META-A9 fault injection, UTF-16 packet cases.
