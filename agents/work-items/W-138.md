# W-138. Decide asynchronous inspection, so a source need not read synchronously

## Problem

After W-132, `OpenAsync` awaits every read, but the document's properties (`Pages`, `AcroForm.Fields`, `Signatures`, `Revisions`, metadata, attachments), the synchronous methods, and the appendix of an asynchronous save read through `IPdfSource.Read`. Every `IPdfSource` therefore has to read synchronously. For the remote storage adapters of stage R5, that is the blocking remote I/O spec W20 says a synchronous convenience must not hide.

## Scope and exclusions

Propose the API for the owner before R5 adapters start. Candidate shapes:

- Asynchronous accessors on the document and editor, such as `GetPagesAsync`.
- An explicit asynchronous load step that brings the objects an inspection needs into the operation's working set.
- A source capability flag that lets a source refuse synchronous reads with a clear exception.

The proposal says how each keeps D-49's per-operation windows and D-20's budgets, and how the editor's writes find their objects. D-55's single async-shaped implementation already reaches `Load` and `Resolve`, which bounds the engine work.

Excluded: implementation, and the storage adapters themselves (R5).

## Acceptance criteria

A proposal the owner can choose from, recorded as a decision once chosen, with the implementation item it implies.

## Evidence required

The proposal itself, plus a count of the public members that read the source synchronously today.
