# W-122. A fast lane that leaves out tests by what they touch

## Problem

Iterating on a work item takes too long. The narrowest standard run is the whole suite on one framework, 12.5 minutes in the 2026-10-23 Docker gate (net10.0, 4,391 tests). About 85% of those tests took about 13% of the summed test time; the rest start external tools, walk the G2 corpus, build large data, or sweep every failure point. Nothing marks those tests, so a run cannot leave them out except by naming classes by hand.

## Why now

The owner asked for faster iteration per work item (D-52).

## Scope and exclusions

- `Category` traits `Interop`, `External`, `Corpus`, `LargeData`, and `Sweep` on the tests that touch them, by reading what each test does.
- `make quiet-test LANE=fast` leaves out those categories, combines with `TEST_FILTER` and `TEST_FRAMEWORK`, and sets `JAYTWO_LANE=fast`. In that lane `ExternalTool.Locate`, the iText reader, and the corpus manifest's file accessors refuse with a message naming the trait to add. The lane reports its slowest tests.
- The verification skill, `AGENTS.md`, and the work-item template name the fast lane as the per-item default and the full matrix as the checkpoint gate. Wording is for the owner's review.
- Excluded: running interop on one framework (W-123), changing what any test asserts, and serializing wall-clock tests. W-121 is retiming the HTTP timestamp tests in another worktree.

## Acceptance criteria

1. `make quiet-test LANE=fast TEST_FRAMEWORK=net10.0` passes with every test that reaches a guarded helper classified.
2. The fast lane on net10.0 takes a few minutes, not 12.
3. Each excluded category is still selected by `Category=<name>`, and a run with no `LANE` selects the same tests as before.
4. An unclassified test that starts a tool fails the fast lane with a message that names the trait to add.

## Evidence required

Internally tested: the fast lane on net10.0 and net48, and the full suite on net10.0 with the same count as before.

## Notes

- 2026-10-23: Started at the owner's direction on branch `lanes` in a separate worktree while W-121 is active in the main worktree. A probe confirmed that `Category!=X` leaves out a test when any of its `Category` values is X, and that class and method traits combine.
- 2026-10-23: The guards drove the classification. The first fast-lane run failed 383 tests, each naming the tool, iText, or the corpus; reading each test decided `Interop` (a tool judges the output or the read) or `External` (a tool only makes input). A test that also asserts library behavior is `Interop`, so under W-123 those assertions run on net10.0 only. The G7 `LargeWorkloadTests` are `External` and `LargeData`, not `Interop`, because their budgets are per runtime. Guarding `ExternalTool.Start` as well as `Locate` found 10 more methods (Poppler rendering and `pdfinfo` version checks) that reached tools without `Locate`; `ForeignPdfTests` and `InteropTests` now start processes through `ExternalTool.Start`. `CursorWindowTests` reads the corpus through `CorpusManifest.Directory`.
- 2026-10-23: Unloaded durations differ from the loaded Docker run by up to 40 times (`AsyncTests.a_same_stream_append_that_fails_part_way_restores_the_original_length`, 61 s there and 1.6 s here), so `LargeData` and `Sweep` were assigned by reading what each slow test does: one G7 workload, the cursor-window fixture walk, and two cursor-window sweeps. The AsyncTests cases each run one operation and stay in the fast lane.
- 2026-10-23 (after completion): The owner approved the `AGENTS.md`, verification skill, and template wording before merge (D-52).

## Closeout

Done 2026-10-23. 111 test methods carry `Category` traits; the fast lane holds 3,903 tests and the categories 489 on net10.0, which is the whole suite (4,392).

Verification, Windows 11, .NET SDK 10.0.402, tools from `.tools/` (D-51):

- `make quiet-test LANE=fast`: PASS in 44 s, 3,903/3,903 on net10.0, net8.0, net6.0, net48, and the netstandard2.0 lane on net8.0.
- `make quiet-test LANE=fast TEST_FRAMEWORK=net10.0` before classification: 383 failures, each with the message naming the trait to add (criterion 4).
- `make quiet-test TEST_FRAMEWORK=net10.0 TEST_FILTER="Category=Interop|Category=External|Category=Corpus|Category=LargeData|Category=Sweep"`: PASS, 489/489 in 5m04s, so the categories still select and the guards stay silent outside the fast lane (criterion 3).
- `make agents-test`: PASS, including the new `test_slowest_tests.py`.

Limitations: `LargeData` and `Sweep` have no guard; the fast lane's slowest-test list is the prompt to classify. The full matrix with every category was not run for this item; it runs at the next checkpoint (`make quiet-docker-test`). The `AGENTS.md`, verification skill, and template wording awaits the owner's review on branch `lanes`.
