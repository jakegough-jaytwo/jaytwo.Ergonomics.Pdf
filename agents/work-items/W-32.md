# W-32. Honor JAYTWO_QPDF in the qpdf interop test

## Problem

`InteropTests.TryLocateQpdf` used `where.exe qpdf`, and `Check` started `qpdf` by name, so `InteropTests.qpdf_checks_built_incremental_filled_and_signed_pdfs` ignored `JAYTWO_QPDF`. `ForeignPdfTests.LocateQpdf` reads `JAYTWO_QPDF` first, and `AGENTS.md` says `JAYTWO_QPDF` or `PATH`.

## Why now

The Product Manager logged it while accepting W-31.

## Scope and exclusions

`InteropTests.cs` only. Locate qpdf with `ExternalTool.Locate("JAYTWO_QPDF", "qpdf.exe")`, log the path, and run all four `qpdf --check` calls from it. Delete `TryLocateQpdf` and `ProbeQpdf` and any `using` left unused. Do not change `ExternalTool.cs`, `ForeignPdfTests.cs`, `DenseMemoryTests.cs`, `src/`, or the fixtures generator. The QA Engineer implements it, so the Technical Lead reviews and verifies.

## Acceptance criteria

On `net8.0` and `net6.0`, with `JAYTWO_TOOLS` unset:

- With `JAYTWO_QPDF` set and qpdf off `PATH`, the test passes and logs that path; on the unfixed code it fails.
- With qpdf on `PATH` only, it passes.
- With neither, it fails, not skips, with a message naming `JAYTWO_QPDF` and `PATH`.

## Evidence required

Internally tested, with the three configurations above and the qpdf version recorded. Do not run the full suite.
