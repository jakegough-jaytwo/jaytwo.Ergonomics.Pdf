# W-169. Make the work counters opt-in and correct the baseline report

## Problem

The 2026-10-24 review of W-167 found two problems.

- **The counters are not test-only.** `PdfWorkCounters` is allocated for every document and incremented on every decode, load, resolution, and visit in release builds, so production pays for it. Being internal is not the same as being test-only.
- **The report overclaims.** Corrections:
  - "fields twice" is not exactly twice "fields": the open's work is shared.
  - Linear scaling is shown for one generated fixture family, not as a general bound.
  - Observed managed heap growth is not a budget guarantee.
  - "No benign file uses a filter chain" holds for the examined corpus only.
  - The A to E expressions are illustrative, not worst-case bounds. The entry budget does not bound object loads or stream switches.
  - Unique objects, cumulative loads and decodes, and retained decoded objects need to be distinguished.

## Scope and exclusions

Make counting opt-in: a document gets counters only when a test asks for them at open, and an ordinary document allocates and updates none. Correct `agents/reference/w-149-work-budgets.md` as listed above. Also add, as unmeasured paths for W-168:

- predictor processing;
- LZW and RunLength decoder work;
- deep parsing and nested containers;
- form appearance and widget processing.

Separate expected linear work, such as signing's whole-document hash, from repeated work on the same structures. Add to the cancellation section that W-149 must measure the time from a cancellation request to the return. Do not change measured values, D-49, or production behavior.

## Acceptance criteria

- A document opened without opting in has no counters, and the production paths only test for null.
- The counter tests and the baseline harness opt in and report the same counts as before.
- The report contains none of the overclaims above and adds the four paths, the three-quantity distinction, and the cancellation note.

## Evidence required

`make quiet-test TEST_FRAMEWORK=net10.0 TEST_FILTER=FullyQualifiedName~WorkCounterTests`, plus one baseline run whose counts match the recorded ones.
