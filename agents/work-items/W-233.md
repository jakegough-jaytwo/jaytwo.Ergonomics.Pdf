# W-233. Retain failed bytes and drop the metadata alias heuristic for ordinary workflow Save(path)

## Problem

Two gaps left by W-232 against adopted contracts. (1) WORKFLOW-RESTORE-01: the engine truncated the destination of a failed ordinary workflow save, so the file did not hold the bytes written before the failure. (2) WORKFLOW-ALIAS-01: the direct save refused a distinct copy that merely matched the input's length and last-write time, a suspicion-based refusal the contract does not adopt.

## Scope and exclusions

Ordinary `Save(path)` and `SaveAsync(path)`. Out: stream `Save`, Combine, Sign, Timestamp (the staged terminals keep the metadata check), standalone engine save, source append, and link identity.

Decision: no engine change. An internal engine mode would need `InternalsVisibleTo` for the Ergonomics assembly, which `EngineBoundaryTests.engine_grants_the_ergonomics_assembly_no_internals` (D-54) forbids; that exception was tried and not kept. The workflow instead passes the engine a `FailedOutputRetainingStream` wrapper that declines `SetLength`, the only call the engine uses to restore a separate destination, so engine restoration, source append and signing are untouched. `CheckDestination` takes a flag so only the staged path applies the metadata check.

## Acceptance criteria

- A save that fails after bytes were written leaves exactly those bytes, sync and async, with and without a prior file.
- A distinct matching-metadata copy is overwritten; an established same-path alias (including `sub/..` spelling) is refused before the destination is opened.
- Engine public save, source append, signing and staged terminals behave as before.

## Evidence required

The direct-file, file-save and begin tests on net10.0 and net48; the full Ergonomics suite on net10.0; build; `make agents-check`, `make task-check`.

## Closeout

2026-11-01: implemented. New `FailedOutputRetainingStream`; `WorkflowFiles.CheckDestination` takes `refuseMatchingMetadata` (true only from `Publish`). Tests: `a_failure_after_bytes_were_written_retains_exactly_those_bytes` (sync/async, existing/absent, asserts the 1 MiB prefix bytes and length), `a_distinct_copy_with_the_input_length_and_last_write_time_is_overwritten`, and the input-alias refusal theory (sync/async, plain and `sub/..` spelling). The old possible-alias test was removed; the hard-link test is Windows-only because no identity check covers hard links.

Checks run: `make quiet-build` exit 0; the engine source is unchanged from HEAD (an earlier engine-mode variant, which passed 4831 engine tests, was reverted because of the D-54 boundary test), so the engine suite was not rerun on the final tree; full `jaytwo.Ergonomics.Pdf.Tests` net10.0 285 passed, 3 skipped, exit 0; the direct-file, file-save and begin tests on net48, net8.0 and net6.0 exit 0; `make agents-check` and `make task-check` exit statuses reported in the handoff. Not run: Docker checkpoint (not a named integration checkpoint), the netstandard2.0 lane (no engine change), Linux/macOS.

Remaining limits: hard-link and path-race aliases are undetected by the direct save (Windows sharing refuses a hard link to the open input); stream `Save`, Combine and extract do not yet have restoration-free output; WORKFLOW-A4 stays partial; no release qualification is claimed.
