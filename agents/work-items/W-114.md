# W-114. Detect certification and signatures from a signature-only walk cached per revision

## Problem

Every write calls `CertificationLevel()`, which calls `CollectFields()`. That builds the page tree, an index of every page's `/Annots`, and a `FieldSlot` for every field, then inspects only the signature fields' `/V`. On the 500-page form, a metadata edit walks twice and allocates 87 MiB, against iText's 1.5 MiB (`agents/reports/2026-10-22-performance-gap.md`).

## Why now

It is the largest measured gap with iText, and the fix keeps the certification guarantee unchanged.

## Scope and exclusions

- `CertificationLevel` and `HasSignature` read from a walk of the field tree that resolves only what is needed to find signature fields and their `/V`. The walk builds no page or annotation index and no slot for other field types.
- The result is cached per revision. It resets when this library writes a revision that can add a signature (`Sign`, a document timestamp), and whenever an edit could change it. Before relying on the cache, this item lists every path that can add or change a signature field's `/V`, the catalog `/Perms`, or the field tree, and records the list in Notes.
- Excluded:
  - any change to which fields or entries count as a certification or a signature (W-116);
  - object-stream retention (W-109);
  - parser allocation (W-115).

## Acceptance criteria

- Every existing certification, FieldMDP, usage-rights, and signature-conflict test passes unchanged. Every write's output is byte-identical to before on the G7 workloads and the signing interop tests.
- New tests:
  - a certification found only through a signature field's `/Reference` still blocks writes;
  - a cached answer resets after `Sign` and after a document timestamp;
  - a refused write leaves the cache valid.
- In `make compare-itext`, the 500-page metadata edit allocates under 30 MiB and the form sign allocates less than before. Both are recorded in `agents/evidence/itext-comparison.md`.
- The G7 workloads pass with the D-49 tripwires unchanged or lowered.

## Evidence required

Internally tested. The pyHanko and pdfsig signing interop tests pass unchanged.

## Notes

- Cache-affecting paths audited on 2026-10-22:
  - `BuildSignature` is the only path that adds a signature field or changes a signature field's `/V`; it invalidates the cache after the edit and restores the prior cache if signing rolls back. This covers CMS signatures and document timestamps, on new and reused fields.
  - `Flatten` can prune the field tree, but it excludes signature fields when flattening all fields and refuses a requested signed signature field. Removing an unsigned signature field cannot change either cached answer. Its existing full field collection seeds the cache.
  - `Fill` refuses signature fields, so it cannot change a signature `/V`. Its existing full field collection seeds the cache.
  - `ApplyUsageRights` can remove only `/UR3`; the library has no path that adds or changes catalog `/Perms /DocMDP`. `/UR3` does not count as `HasSignature` or certification.
  - Other catalog and field edits do not add a signature, change a signature `/V`, or change `/DocMDP`.
- The lightweight walk preserves the old terminal-widget and inherited `/FT` and `/V` rules, field-tree cycle/depth failures, dangling-reference treatment, and separate catalog `/Perms` handling. It builds no page list, annotation index, or `FieldSlot`.
- Same-environment `a844155` to W-114 comparison: 500-page metadata edit allocation 127.39 to 20.64 MiB; form sign 104.15 to 78.90 MiB.
- Focused G7 `net10.0`: extraction, metadata edit, bulk fill, and sign passed with unchanged D-49 thresholds; metadata edit used 447,304 bytes / 41 calls / 479,677 decoded bytes and sign used 1,651,417 / 241 / 1,494,125.
- Verification: focused `net10.0` AcroForm and signature tests passed 121/121. The final `make quiet-docker-test` checkpoint passed 4,339/4,339 tests on each of `net10.0`, `net8.0`, and `net6.0`, including the unchanged pyHanko and Poppler `pdfsig` signing interoperability tests; the fuzz smoke run passed.

## Closeout

Implemented a signature-only field-tree walk whose certification level and signature-presence result is cached until a successful signature edit. Full field consumers seed the same cache from their existing slots, avoiding a second traversal. Regression tests cover field-only DocMDP discovery, cache reset after CMS signing and document timestamps, and refused writes. G7 output and signed-range hashes stayed unchanged, the D-49 tripwires passed without increases, metadata-edit allocation fell below 30 MiB, and form-sign allocation fell against the same-environment baseline.
