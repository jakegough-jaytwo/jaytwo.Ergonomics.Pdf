# W-185. Share the workflow file-save lifecycle

## Problem

`PdfWorkflowBuilder.SaveFileAsync`, `PdfWorkflowBuilder.SignFileAsync`, and the file branch of `PdfCombineWorkflow.RunAsync` separately coordinate temporary sibling creation, writing, configured flush, cancellation before publication, success tracking, and cleanup. `WorkflowFiles` shares the primitives but not this lifecycle. Every lifecycle correction therefore needs consistent changes in several paths. The duplication is demonstrated; this review did not establish an existing output-corruption defect.

## Scope and exclusions

Make a behavior-preserving C# refactor that gives the repeated temporary-file lifecycle one concrete implementation in the existing internal `WorkflowFiles` helper. Terminals supply their writing operation and retain their input/editor scopes and result construction. Share path preflight only where it removes real duplication without changing terminal-specific validation or exception ordering.

Keep F17/F20 and D-65 unchanged: unique siblings created with `CreateNew`, configured flush before publication, conservative normalized-path and metadata alias checks for every input, explicit overwrite for detected existing destinations, cancellation until publication, and cleanup after failure. Inputs remain open through the final alias check. Signing retains D-64's private staging, one original open and one editor, revision ordering, complete signing before publication, and no automatic host-call retries. Preserve synchronous/asynchronous forms, borrowed ownership, and stream-output behavior.

Exclude new public APIs, destination interfaces or strategy hierarchies, configuration systems, engine changes, cross-operation locks, native publication calls, new dependencies, stronger filesystem guarantees, and weakening alias or cancellation safeguards. File publication stays in Ergonomics.

## Acceptance criteria

- Ordinary save, sign/document-timestamp, and combine file terminals use the same temporary-file creation/flush/publication/cleanup lifecycle rather than each retaining its own success flag and cleanup block.
- Argument, path, known-alias, and detected-existing-destination checks retain their required pre-open timing. Engine exception categories and terminal-specific processing/external-call ordering remain intact.
- All affected file-terminal families preserve inputs and prior destinations on processing or pre-publication cancellation failures; unpublished temporary files are cleaned up after write, flush, or publication failure. A cleanup failure does not replace the original failure under the existing cleanup policy.
- Rechecks cover every combine input and keep inputs open through publication. Overwrite, link handling, unavailable input metadata, and concurrent-publication limitations retain D-65's behavior without adding isolation machinery.
- Signing and document-timestamp paths still publish only completed results, use one editor, add the required revisions, and invoke each provider/signer/authority at most once. Caller-owned resources remain open.
- The shared helper has fewer lifecycle branches and duplicated blocks overall; it does not become a general destination framework. Public signatures, defaults, and documented behavior are unchanged.

## Evidence required

Run focused `WorkflowFileSaveTests`, `WorkflowSigningTests`, and `WorkflowCombineTests` on Windows net10.0 and net48 and Linux net10.0, because managed publication/link behavior and available filesystem APIs differ across those environments. Reuse existing coverage and add only missing distinct cases for the shared lifecycle across the terminal families, especially cancellation, processing/flush/publication failure, aliases, overwrite, cleanup, and signing call counts. Use the existing test signer/authority support; no new independent signature-verification sweep is required. Build affected targets with StyleCop/XML checks. Run `make agents-check`, `graphify update .` after code changes, and staged `make task-check`. These are focused checks, not a full matrix or Docker integration checkpoint.
