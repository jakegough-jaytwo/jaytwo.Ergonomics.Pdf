# W-71. PAdES baseline B-B signatures

## Problem

Signatures use `adbe.pkcs7.detached`, which EU recipients may not accept as PAdES (spec W17). W-51 found that a size overflow reports a lower bound instead of the exact size; that is folded in here.

## Why now

Reset plan C2 item 12.

## Scope and exclusions

- `ETSI.CAdES.detached` with `signing-certificate-v2`, no CMS `signing-time`, and the time in `/M`.
- With a timestamp authority, PAdES B-T.
- Report the exact overflow size (former W-51).
- Excluded: B-LT and B-LTA.

## Acceptance criteria

Refined at activation on 2026-10-21. `ACCEPTANCE.md` Sealing gains two bullets (PAdES structure; PAdES interoperability) and changes two (`SigningTime` and the size limits).

- `PdfSignatureOptions.Format = PadesBaselineB` writes `/SubFilter /ETSI.CAdES.detached`, the signing time in `/M`, no `/Cert`, and a CMS whose signed attributes are exactly content-type (id-data), message-digest, and signing-certificate-v2 (one ESSCertIDv2: SHA-256 certHash with the DEFAULT hash algorithm omitted, and issuerSerial), with no signing-time. This holds for every W15/W16 key and digest, from `Sign` and `SignAsync`. The default stays `AdbePkcs7Detached`.
- With an `ITimestampAuthority`, the only unsigned attribute is the signature-time-stamp, so the signature is PAdES B-T.
- A document timestamp with a non-default format, and an undefined format, throw `PdfSignException` without calling the signer or the authority and without writing.
- B-B (every key and digest) and B-T (RSA SHA-256, P-256 SHA-384, OpenSSL TSA) pass pyHanko (intact, valid, trusted, signing-certificate-v2 match, token trusted), `pdfsig` (`ETSI.CAdES.detached`, valid, trusted), and an EN 319 142-1 6.3 checklist that reads the file with pyHanko and asn1crypto.
- `PdfSignatureTooLargeException.ActualBytes` from `CmsDetachedSignatureProvider` is the exact CMS length. Reserving exactly that many bytes fits with no padding, and one byte fewer reports the same length. A time-stamp token is parsed only once the CMS fits. Certificates past 1,048,576 bytes (the largest reservation) throw `PdfSignException` before the leaf is parsed or the signer is called, which also bounds an endless chain.
- Plan C4: encrypted input under the owner and the user password (AES-128 owner, AES-256 user, through qpdf, pypdf, pyHanko, `pdfsig`, and the checklist); the original bytes stay a prefix, and the destination is unchanged on every refusal. The format changes only the `/SubFilter` and the CMS attributes. Password permissions, DocMDP, FieldMDP, approval signatures, usage rights, and cancellation run before the provider on the same path for both formats, and their existing tests still pass.

## Evidence required

pyHanko 0.38.0 and `pdfsig` for B-B and B-T. For profile validation, the EN 319 142-1 6.3 checklist in `validate_signature.py`, cross-checked against pyHanko's own PAdES and adbe signatures. EU DSS was not run (see Notes).

## Notes

- 2026-10-20: Created under W-63 from `agents/reference/charter-reset-plan.md` C2.
- 2026-10-21: Activated. The exact-size criterion conflicted with `ACCEPTANCE.md`'s size-limit bullet, which refused an oversize chain, signature value, or token before signing and stopped an endless chain at the reserved size. When the certificates alone overflow, the exact CMS length cannot be known without the signer and the authority. The owner asked for what matches the PDF spec and what developers expect from other tools. ISO 32000 says nothing on this. pyHanko 0.38.0 (`pdf_byterange.py`, "allocated N bytes, but contents required M bytes"), iText, and PDFBox sign first and compare after. So the provider now builds the whole CMS and reports its exact length. The pre-signing bound moved from the reserved size to 1,048,576 bytes, the largest reservation, so an endless chain still stops before the signer runs. For owner review: an oversize request now calls the signer and the authority once before it fails.
- 2026-10-21: API: `PdfSignatureFormat` (`AdbePkcs7Detached`, `PadesBaselineB`), `PdfSignatureOptions.Format`, and `PdfSignatureContext.Format`. `IPdfSignatureProvider.Kind` is unchanged, because both formats are CMS. A custom provider must honor `Format`, as the `/SubFilter` already names it.
- 2026-10-21: signing-certificate-v2 includes issuerSerial, as pyHanko's `as_signing_certificate_v2` does. pyHanko's `check_ess_certid` matches both the hash and issuerSerial.
- 2026-10-21: Limitation. No ETSI conformance checker ran. EU DSS needs Java, which is not on this machine or in the CI image, and adding it was out of proportion for this item. pyHanko has no PAdES-level classifier. The checklist encodes our reading of EN 319 142-1 6.3. It accepts pyHanko's own PAdES signature and rejects its adbe signature.
- 2026-10-21: D-43: spec W17 status set to Exists in this commit.
