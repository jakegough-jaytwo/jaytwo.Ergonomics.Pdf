# W-148. Harden XMP XML parsing

## Problem

XMP is parsed from untrusted PDF bytes without an explicit XML-reader policy. The parser must not allow DTD processing or external resource resolution, and its work must remain bounded.

## Scope and exclusions

Use explicit XML reader settings for every XMP parse, prohibit DTDs and external resolution, and impose evidence-based document limits. Preserve the shipped metadata edit semantics. Do not add a general XML sanitization capability or a runtime dependency.

## Acceptance criteria

- Ordinary XMP, including supported UTF-8 and UTF-16 packets, continues to read and edit on every supported target.
- A DTD-bearing packet is rejected without resolving an external resource.
- Oversized or otherwise disallowed XML fails with a stable library exception and does not dirty an editor.
- Focused tests cover success, malformed XML, DTD refusal, encoding, and the configured limits on net48 and a current target.

## Evidence required

Focused metadata/XMP tests on net10.0 and net48, plus a warning-free build of the affected project.

## Notes

- Source backlog identifier: SEC-001.

## Closeout

- XMP parsing now uses explicit `XmlReaderSettings`: DTD processing is prohibited, external resolution is disabled, entity expansion is disabled, and document bytes/characters are capped at 32 MiB, matching the engine's structural-stream cap.
- `SetXmp` validates and copies the packet before applying write gates or mutating PDF objects, so malformed, DTD-bearing, and oversized packets throw `PdfXmpException` without dirtying the editor. Existing malformed packets still do not fail `Open`, and info edits still preserve their bytes.
- Focused `MetadataTests`: net10.0 13/13 passed; net48 13/13 passed. `dotnet build src/jaytwo.Pdf/jaytwo.Pdf.csproj --no-restore --nologo`: succeeded for netstandard2.0, net6.0, net8.0, and net10.0 with 0 warnings and 0 errors.
