# W-133. Stabilize the semantic jaytwo.Pdf public API

## Problem

Reset stage R1 step 5 (`reset-plan.md` section 7). After the move, editor split, and source change, the engine's public surface needs a pass against D-54: semantic page, geometry, field, widget, attachment, metadata, revision, permission, and signature models; no raw object model; lazy inspection.

## Scope and exclusions

Review the public surface of `jaytwo.Pdf`. Make any raw dictionary, token, or indirect object that is public internal, and make eager inspection lazy where practical. Keep password permissions, DocMDP and FieldMDP restrictions, and cryptographic enforcement as separate results (`reset-plan.md` migration rule 11). Record the surface in Closeout.

No new capability and no algorithm rewrite.

## Acceptance criteria

- No public type exposes the raw object model.
- Inspection keeps its sparse working-set tests green.

## Evidence required

Focused tests for any changed member and `make quiet-test LANE=fast`.

## Notes

- 2026-10-23: Created by W-128. Refine scope at activation from W-131 and W-132.
- 2026-10-23: Activated. The review found no public raw object model and no eager inspection at open, so the change is a namespace guard test and XML-doc remarks; no public behavior changes, so `README.md` and `ACCEPTANCE.md` leave the scope.

## Closeout

Surface reviewed: 57 public types, all in `jaytwo.Pdf`, `.AcroForm`, `.Attachments`, `.Metadata`, and `.Signatures`. Every type in `jaytwo.Pdf.Internal` is internal, so no public member can expose a dictionary, token, or indirect object. The models: `PdfPage`/`PdfPageEditor` and `PdfRect` (geometry), `PdfField` (one entry per widget, with `WidgetIndex`, rectangle, page, and rotation), `PdfFieldValue`, `PdfChoiceOption`, `PdfAttachment`, `PdfMetadata`/`PdfMetadataEditor`, `PdfRevision`, `PdfPermissions`, and `PdfSignatureInfo` with `PdfByteRange`. Opening reads only the header, `startxref`, the xref chain, and `/Encrypt`; pages, fields, attachments, signatures, revisions, and metadata are read when asked for. Migration rule 11 already holds: `PdfPermissions` carries only the password bits, `PdfSignatureInfo.CertificationLevel` carries DocMDP, and FieldMDP is enforced by the editor without a public result.

Changes: `PublicApiTests` fails if a public type appears outside those five namespaces. XML-doc remarks now say that `PageCount`, `Pages`, `Signatures`, `Revisions`, `AcroForm.Fields`, and the attachment collection read the document again on each access, pending edits included, so callers keep the returned list rather than indexing the property in a loop. `PdfPermissions` and `PdfDocument.Permissions` also say the certification level is reported separately. No behavior changed, so `README.md` and `ACCEPTANCE.md` are unchanged.

Left as they are: caching the per-access lists needs invalidation when edits are made, which counts as new engine state, so it is out of scope. `PdfDocument` and `PdfDocumentEditor` implement `IDisposable` only. W20 allows `IAsyncDisposable` but does not require it, and it belongs with W-138's asynchronous inspection.

Verification: `make quiet-build` passed (StyleCop warnings as errors). The focused `PublicApiTests` and `EditorTests` on net10.0 passed 8/8. `make quiet-test LANE=fast` passed 3,945/3,945 on net10.0, net8.0, net6.0, and net48, and in the netstandard2.0 lane on net8.0. `make quiet-test TEST_FRAMEWORK=net10.0 TEST_FILTER="Category=Sweep|Category=LargeData"` passed 16/16, covering the D-49 tripwires and the D-20 budgets.
