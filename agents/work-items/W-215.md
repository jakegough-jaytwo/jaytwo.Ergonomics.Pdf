# W-215. Honor explicit standard-security Crypt stream overrides

## Problem

W-155 confirmed a Medium defect: clear explicit Identity attachments are sent through default AES decryption; explicit StdCF streams later fail as an unsupported codec. qpdf extracts the exact seven-byte payload from the same fixtures. ISO 32000-1 7.4.10 and Table20 require the override; `ACCEPTANCE.md` promises decrypted standard-security streams. See W-155 `aes-128-crypt-{identity,stdcf}.pdf`, `independent.json` and two permanent red assertions in `regressions.py`.

## Scope and exclusions

Select the supported stream cipher from a first Crypt filter/DecodeParms, with Identity default, and consume that encryption filter once in required-stream reads. Preserve a stream's explicit crypt choice if it is rewritten. Check assembly's existing Crypt refusal separately; do not silently widen assembly preservation. No public-key, EFOpen, arbitrary security handlers, content decoding, or malformed-filter recovery. Rescope exact paths if implementation discovery needs more. Proposed and unqueued pending owner scheduling.

## Acceptance criteria

- Explicit Identity, omitted Name and supported named StdCF streams expose the expected bytes and retain subsequent compression decoding order.
- Unknown/unsupported encryption choices and a non-first Crypt fail predictably without publishing misleading bytes.
- Default StmF, metadata exemptions and EFF remain correct; a permanent suite regression covers each confirmed failure and the standards-derived missing-Name case.

## Evidence required

Focused encryption/stream tests, qpdf attachment extraction for explicit Identity/StdCF, and incremental-prefix/output checks if rewriting is exercised. W-155 records that qpdf and pypdf disagree with the Identity default on the missing-Name synthetic case: the standard supplies that expectation. No full matrix/Docker gate unless the actual change crosses those boundaries.

## Closeout

Not started. No runtime correction is claimed.
