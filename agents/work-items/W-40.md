# W-40. Resolve indirect stream filters and decode parameters

## Problem

The stream decoder has no resolver. Since B-36, an indirect `/Filter` or `/DecodeParms` is refused with `PdfParseException`, although ISO 32000 permits those values to be indirect.

## Why now

This is a known Low-severity compatibility limitation.

## Scope and exclusions

- `PdfStreamDecoder.FiltersOf` and `ParmsOf` take an optional resolver. With one, an indirect `/Filter`, `/DecodeParms`, array element, and the decoder parameters the library reads (`/Predictor`, `/Colors`, `/BitsPerComponent`, `/Columns`, `/EarlyChange`) resolve through `PdfEngine.Resolve`, which keeps its existing bounds: 256 references in one chain, cycle detection, and the 256-object load depth. A reference to a free or undefined object is null (ISO 32000-1 7.3.10, D-26).
- `PdfEngine.OpenBody` and `ReadDecoded` (attachments, XMP, object streams) pass the resolver. A cross-reference stream does not: ISO 32000-1 7.5.8.2 requires its `/Filter` and `/DecodeParms` to be direct, so a reference there is still refused with `PdfParseException`, and so is a reference among the decoder parameters, which was silently ignored before.
- Excluded: new filters, other `DecodeParms` keys, the fuzz harness (its decode target has no document and keeps the direct-only path), and any change to caps or the parser.

## Acceptance criteria

An indirect filter name, array, or parameter dictionary resolves through the document within the existing depth bound and decodes.

## Evidence required

Internally tested, with `IndirectFilterTests` covering each indirect form on the streaming (attachment) and whole-buffer (object stream) paths, the bounds, and the xref-stream refusal. Independent: qpdf rewrites a file with indirect filters (`--stream-data=preserve --object-streams=generate`), the library reads the qpdf output, and `qpdf --show-attachment` decodes the same bytes (`ForeignPdfTests`).

## Closeout

Done 2026-10-20. Work commit `W-40`, which also activated the item; verification ran on that tree.

- `PdfStreamDecoder.FiltersOf` and `ParmsOf` take an optional resolver; `PdfEngine.OpenBody` and `ReadDecoded` pass `Resolve`, and `ReadXrefStream` passes none (ISO 32000-1 7.5.8.2). An indirect `/Filter`, `/DecodeParms`, array entry, or decoder parameter resolves within `Resolve`'s bounds (256 references per chain, cycles refused) and `Load`'s 256-object depth. Parameter values are resolved into a copy, so the cached stream dictionary and saved bytes keep their references. A reference to an undefined object is null (D-26). The fuzz decode target keeps the direct-only path.
- `IndirectFilterTests` (26 cases): indirect name, array, array entry, reference chain, parameter dictionary, parameter array, parameter array entry, parameter values, and both at once on the attachment (streaming) path; an indirect filter array on the object-stream (whole-buffer) path; an undefined reference; malformed resolved values; a cycle; an object stream whose `/Filter` lives inside itself; 256 references decode and 257 are refused; and an indirect `/Filter` or `/Predictor` in an xref stream fails `Open`. Against the unchanged source, 21 of the 26 failed; the 5 that passed are refusals that already held.
- Independent: `ForeignPdfTests.qpdf_rewrite_with_indirect_filters_is_read_and_decodes_as_qpdf_decodes_it`. qpdf 12.4.2 (`--stream-data=preserve --object-streams=generate`) rewrites a file whose two attachments use an indirect name and an indirect array with an indirect entry, indirect parameters, and an indirect `/Columns`. qpdf keeps the references and puts their targets in an object stream. The library reads both attachments from qpdf's output, and they equal `qpdf --show-attachment`.
- `ACCEPTANCE.md` gains one Limits row. The `README.md` Limits row now says the values may be indirect, except in a cross-reference stream. No criterion was weakened.
- Verification: `dotnet test test/jaytwo.Ergonomics.Pdf.Tests` (GA SDK 10.0.402) 515/515 on Windows net48, net6.0, net8.0, and net10.0, with qpdf 12.4.2, Poppler 26.09.0, SoftHSM 2, OpenSSL 3.2.4, and Python 3.13 (pypdf, pyHanko). `dotnet build src/jaytwo.Ergonomics.Pdf -c Release`: 0 warnings, 0 errors on netstandard2.0, net6.0, net8.0, and net10.0. Fuzz smoke passed. `make agents-check` and `make task-check` OK for both commits. `make docker-builder docker-test` was not run; this commit is not an integration checkpoint.
- Limitations: no real-world producer file with indirect filters is in the corpus; the independent evidence is a qpdf rewrite of builder input. The resolved filter arrays are not counted separately from the existing container cap.
