# W-172. Plan the R4 signing work items and queue

## Problem

Reset stage R4 has an adopted outcome, scope, and exit criteria, and W-103 and W-104 are assigned to it, but the repository has no complete R4 implementation sequence. The security-hardening phase follows R4 under D-62, so the missing signing work must be itemized before that phase can start.

## Scope and exclusions

Read the R4 contract and the shipped signing baseline, then create the smallest ordered set of work items that covers the R4 scope and exit criteria. Reassess W-103 and W-104 in that sequence, and replace W-172's queue position with the complete R4 sequence ahead of the security-hardening phase. Excluded: product code, tests, public-behavior changes, edits to `reset-plan.md`, and adding signing scope beyond its adopted R4 boundaries.

## Acceptance criteria

- The R4 items cover ergonomic signing, any demonstrated final-model API migration, W-103 and W-104 or their approved replacements, refreshed signing qualification, and an R4 exit checkpoint.
- Dependencies and queue order make R4 complete before any remaining security-phase item can become next.
- The items do not propose signature validation, trust evaluation, or other R5 advanced capabilities as R4 work.

## Evidence required

`make agents-check` and the staged `make task-check` pass for the planning transaction.
