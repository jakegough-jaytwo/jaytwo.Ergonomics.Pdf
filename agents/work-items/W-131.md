# W-131. Separate inspection from editing with PdfDocumentEditor

## Problem

Reset stage R1 step 3 (`reset-plan.md` sections 4.4 and 7). `PdfDocument` both inspects and mutates. Spec requirement R14 (Change) and section 6 make `PdfDocument` read-only and route every write, save, and signature through `PdfDocumentEditor`.

## Scope and exclusions

- `PdfDocument.Edit()` returns a `PdfDocumentEditor`; move every mutation, save, and sign operation to it. Disposing an editor does not save.
- Keep all-or-nothing validation and destination rollback; state on the save and sign APIs the validation, processing, and output failure classes of `reset-plan.md` section 4.4 without claiming atomicity a destination cannot provide.
- Ship R14 under D-43: set its status to Exists and update `ACCEPTANCE.md` and `README.md`.

No source abstraction (W-132), no new behavior beyond the split, and signing changes only as the split requires.

## Acceptance criteria

- `PdfDocument` exposes no mutation, save, or sign member.
- Existing write, rollback, and signing tests pass through the editor; `OutputIdentityTests` passes without re-recording.

## Evidence required

`make quiet-test LANE=fast` and `OutputIdentityTests` on net10.0.

## Closeout

Done. `PdfDocument` now only inspects; `PdfDocument.Edit()` returns a `PdfDocumentEditor` that owns `SaveIncremental`, `SaveIncrementalAsync`, `Sign`, `SignAsync`, and `AllowBreakingSignatures`, and exposes write facades `PdfMetadataEditor`, `PdfAttachmentCollectionEditor`, `PdfAcroFormEditor`, and `PdfPageEditor`. `PdfMetadata`, `PdfAttachmentCollection`, `PdfAcroForm`, and `PdfPage` lost their setters and write methods. The engine is unchanged apart from `PdfPage` no longer holding it. Lifecycle choices: one open editor per document (a second `Edit()` throws `InvalidOperationException`); disposing an editor neither saves nor discards, so its pending changes stay for the next editor, and the document's reads show them; each editor starts with `AllowBreakingSignatures` false; a disposed editor, or an editor of a disposed document, throws `ObjectDisposedException`. Discarding pending changes on dispose would be new engine behavior and is left out. The editor class remarks and every save and sign overload state the validation, processing, and output failure classes and that rollback is best effort. R14 is Exists; `README.md` and `ACCEPTANCE.md` describe the split. Tests moved to the editor mechanically (an editor opened beside each mutated document, delegate helpers retyped to `PdfDocumentEditor`); new `EditorTests` covers the read-only surface and the editor lifecycle. The editor implements `IDisposable` only; async disposal belongs with W-132's async lifecycle.

Verification: `make quiet-test LANE=fast` passed 3917/3917 on net10.0, net8.0, net6.0, net48, and the net8.0 `netstandard2.0` lane, with `OutputIdentityTests` passing and no fixture re-recorded. Interop, External, and Corpus tests on net10.0 passed 483/483. `make fuzz-smoke` passed. The solution builds with StyleCop warnings as errors.
