# W-37. Exact signature-appendix size guard (audit SA-07)

## Problem

Audit finding SA-07 (High): the 8 MiB estimate runs before `BuildSignature` dirties a reused field, and counts only stream bodies that are already dirty. `WriteAppendix` later serializes the full cloned dictionary with no guard on the actual serialized length.

## Why now

SA-07 is a release blocker. The audit disposition kept it separate from the parser and signer batches because it crosses the writer and signing code and needs an exact append-size design.

## Scope and exclusions

Measure or bound the appendix that is actually serialized, with a regression test that measures it and asserts that the destination is not extended. The Core code owns the writer; the signing code is consulted. `SaveIncremental`, the serializer, and the parser are not in scope.

## Acceptance criteria

The appendix that is actually serialized is measured or bounded, and an oversize appendix throws without extending the destination.

## Evidence required

Internally tested.

## Closeout

Accepted at the internally tested level. Closes SA-07. `Sign` serializes the appendix into the new `Internal/PdfAppendixBuffer.cs`, which refuses any write past 8,388,608 bytes and clamps its capacity to that value, before the destination is touched. The early estimate is now a strict lower bound. An appendix of exactly 8 MiB signs, whether a reused field's dictionary or an attachment fills it, and one byte more throws `PdfSignException` with both destinations unchanged. Writing the buffer straight to the destination removed one appendix-sized copy. Three tests cover the reused-field trigger, the exact boundary, and the buffer's allocation ceiling. `README.md` says the limit applies to the serialized appendix, and `ACCEPTANCE.md` gained an appendix-limit row under Limits. Limitation (QA-B37-02): the serializer still allocates about 7× to 12× an oversize literal before the refusal, and the bound covers only the buffer; it became W-50. Reports: `agents/reports/2026-10-19-core-engineer-B-37.md`, `2026-10-19-qa-engineer-B-37.md`, and `2026-10-19-tech-lead-B-37-review.md`. Completed 2026-10-19.
