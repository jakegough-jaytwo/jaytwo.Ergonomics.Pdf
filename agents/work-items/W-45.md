# W-45. Document that button /Opt is not mapped (F-3)

## Problem

Skill-review finding F-3: button `/Opt` export values are not mapped, and button export values come from appearance-state names. A probe used a radio field with `/Opt [(Red) (Blue)]`, on-states `0` and `1`, and `/V /1`. The second `ExportValue` was `1`, not `Blue`.

## Why now

The skill plan (D-27, step 2) asked for a reproduction and a disposition from observed public behavior.

## Scope and exclusions

Reproduce and classify the claim against the current public contract. Changing `ExportValue` semantics or adding another public value would be an owner-approved API change and is out of scope.

## Acceptance criteria

The finding has a disposition. If it is a limitation, `README.md` and `ACCEPTANCE.md` state it, and a retained test pins the contract.

## Evidence required

Not stated in the original entry. Internally tested.

## Closeout

Accepted as a documented limitation, not a defect. A radio button's `/Opt` array is not mapped to a public value. `PdfField.ExportValue` and `PdfAcroForm.SetRadio` were already documented as the appearance on-state name, and the probe confirmed that contract. No runtime code changed. `ACCEPTANCE.md` now says "Button `/Opt` does not remap that public on-state value." `README.md` says a button `/Opt` array is not mapped to another public value. The retained contract test is `AcroFormTests.radio_button_opt_does_not_replace_the_on_state_contract`; it passed 1/1 on `net8.0`. Mapping `/Opt` would change public semantics and would be an owner decision; none is proposed. Report: `agents/reports/2026-10-19-F-3.md`. Completed 2026-10-19.
