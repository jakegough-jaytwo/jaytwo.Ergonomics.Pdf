# W-95. Update the AcroForm field matrix for the fill value model

## Problem

W-68 replaced `SetText`, `SetCheckBox`, `SetRadio`, and `SetChoice` with `Fill` and a `PdfFieldValue`. `.agents/skills/pdf-acroform-change/SKILL.md` still points to "the per-setter invariants", and `references/field-matrix.md` titles its table "Per-setter invariants" with a "Setter" column. The table also does not list two behaviors W-68 shipped: filling no value turns every radio widget off (`/V` and each `/AS` become `/Off`), and filling no value or an empty list clears a choice field (`/V` and `/I` removed, empty appearance generated). The Topology list does not name the producer variant W-68 found: LibreOffice copies `/FT` onto the widget kids of a field, and the value still belongs to the field dictionary (ISO 32000-1 12.7.3.1).

## Why now

Found while doing W-68. `.agents/skills/` changes only with the owner's approval, so W-68 recorded it instead of editing. Not queued.

## Scope and exclusions

Proposed edits, for the owner to approve:

- `SKILL.md`: "the per-setter invariants a fill must keep" becomes "the invariants a fill of each field kind must keep".
- `references/field-matrix.md`: rename the heading to "Fill invariants by field kind" and the column to "Field kind"; in the Radio row, add "no value: `/Off`, every widget `/Off`"; in the Choice row, add "no value or an empty list: `/V` and `/I` removed, empty appearance in the subset".
- `references/field-matrix.md` Topology: add "Widget kids that carry field entries such as `/FT` (LibreOffice) are still widgets: the value is read from and written to the field dictionary."
- Excluded: any behavior change.

## Acceptance criteria

- The skill and its matrix name no removed API and list the clearing behavior and the LibreOffice variant as `ACCEPTANCE.md` states them.

## Evidence required

None beyond a read against `ACCEPTANCE.md`.
