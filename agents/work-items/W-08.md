# W-08. Reject a choice value when the field has no /Opt and Edit is clear

## Problem

`ACCEPTANCE.md` says a choice value that is not listed throws `PdfFieldValueException` and does not dirty the document, unless the Edit flag is set. `RequireOption` returned early when the option list was empty, even with Edit clear. `simple_text_generates_helvetica_and_other_values_request_appearances` filled `Choice`, which has no `/Opt`, with `Yes` and expected `Generated`. This reading treats "not listed" as including a field with no `/Opt`. The planning report also recorded the other reading and did not adopt it.

## Why now

The W-05 AcroForm audit found it, and the planning report recommended a backlog item for it as a candidate defect against an existing criterion.

## Scope and exclusions

Make the choice rule apply when `/Opt` is absent. The existing choice sentence in `ACCEPTANCE.md` stays as written; this item does not edit that file, which W-04 had claimed.

## Acceptance criteria

- A choice field with no `/Opt` and Edit clear throws `PdfFieldValueException` and does not dirty the document.
- A field with the Edit flag still accepts an unlisted value.
- The choice sentence in `ACCEPTANCE.md` is unchanged.

## Evidence required

Not stated in the original entry. Internally tested, the level at which it was accepted.
