# W-126. Clarify reset I/O and execution contracts

## Problem

Independent feedback accepted by the owner found that the reset plan did not state enough of the random-access source, lazy-loading, revision-count, permission, and destination-commit contracts to guide implementation safely. The same feedback proposed moving ergonomic signing earlier, which conflicts with the owner's settled phase order.

## Scope and exclusions

Clarify stable source snapshots, partial and serialized reads, ownership, async cancellation, bounded caching, lazy inspection, validation versus processing and output failures, best-effort rollback, destination-specific commit behavior, normal revision counts, and distinct permission mechanisms. Record that core signing remains available from Phase 1 while ergonomic and further signing work remains Phase 4.

Do not change the phase order, protected authority documents, current queue, code, tests, packages, or shipped behavior.

## Acceptance criteria

- `reset-plan.md` specifies an implementable `IPdfSource` contract without requiring concurrent access in Phase 1.
- It distinguishes validation guarantees from processing failures and destination failures, and makes rollback conditional on destination capabilities.
- It preserves sparse lazy inspection and defines the normal revision count for compatible edits and signing.
- It distinguishes password permissions, certification restrictions, and cryptographic enforcement.
- It keeps assembly before ergonomic and further signing work while stating that direct core signing remains available.
- Phase 0 remains limited to removing contradictory guidance.
