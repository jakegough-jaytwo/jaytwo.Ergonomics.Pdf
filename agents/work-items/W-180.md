# W-180. Add staged signing and document-timestamp workflow terminals

## Problem

Direct engine signing is available, but deferred workflows cannot finish with a signature or document timestamp. D-64 adopts a staged terminal contract that avoids placing large ordinary edits in the bounded signing appendix.

## Scope and exclusions

Implement the W-179-approved F4 and F18 to F21 using only public engine APIs: dedicated synchronous/asynchronous signing and document-timestamp terminals for separate streams and files, common signer/authority conveniences and the existing provider overload. Keep one original open and one editor: save ordinary edits to a private readable/writable seekable file, then sign that file through the same editor. Complete signing before caller-output copying or publication. Preserve existing defaults and resource ownership. Exclude engine API changes, signed append-to-source, multiple cryptographic operations, automatic retries, new algorithms/profiles, and runtime validation. A demonstrated engine gap requires a separately scoped follow-up, not a speculative migration.

## Acceptance criteria

- Terminals consume the workflow once, retain existing ordinary-operation ordering, reject shape errors before opening, and delegate document checks to the engine.
- Sign unchanged and timestamp unchanged each add one revision; edit then sign/timestamp adds an ordinary edit revision and a separate signature/timestamp revision when edits exist. Embedded signature timestamps add no revision.
- A test records one original input open and exercises save-then-sign with one editor, including an encrypted input and existing empty signature field. Existing certification, FieldMDP, permissions, and unresolved-appearance refusals remain enforced.
- A streamed attachment larger than the 8 MiB appendix succeeds by staging ordinary edits; buffers remain bounded and no whole-PDF array is introduced.
- Signer/TSA, size, validation, staging-I/O failures and cancellation before final copying/publication leave caller outputs unchanged. Final-copy I/O failure/cancellation attempts rollback with existing best-effort semantics. File output preserves overwrite, alias, flush, cleanup, and publication rules.
- Count host calls: each required provider/signer/TSA invocation occurs at most once; overflow never triggers retry. Caller resources remain open, and host error details remain sanitized.
- The approved F4 and F18 to F21 become Exists with README/ACCEPTANCE updates in the implementation transaction under D-43. Existing defaults, including the legacy signature format, remain unchanged.

## Evidence required

Focused workflow signing, timestamp, staging, ownership and failure tests on net10.0 and net48; build affected targets with StyleCop/XML checks. Exercise an existing provider, test signer and test authority through public APIs. Independent output checks and large-file measurements are completed by W-181, and the full matrix/Docker gate by W-182. Run `make agents-check` and staged `make task-check`.

## Closeout

Implemented in `PdfWorkflowBuilder.Signing.cs` (twelve public terminals: `Sign`/`SignAsync` with a signer and optional authority or with a provider, `Timestamp`/`TimestampAsync`, each to a stream or a path) with `WorkflowFiles.CopyAsync` for the final stream copy. The run's one editor saves the ordinary edits to a private staging file (a delete-on-close temp file for stream output, the F17 temporary sibling for path output) and then signs that file; the copy or publication happens only after signing. No engine change was needed, and the encrypted-input composition works as proposed.

Verification: `make quiet-build` (all targets, StyleCop and XML docs as errors) passed. `WorkflowSigningTests` (23 cases) passed on net10.0 and net48, including an OpenSSL-backed document-timestamp and embedded-timestamp test (`Lane.External`). The Ergonomics fast lane on net10.0 stayed green. Test support: the project now links `ExternalTool.cs` and `OpenSslTimestampAuthority.cs`, and its `TestCompat` gained `AddArgument`, `Kill`, and argument quoting for them.

F4 and F18 to F21 are Exists in `docs/spec/phase-1.md` (D-43), with README and ACCEPTANCE updates. Not run, by scope: independent-tool output checks and large-file memory measurements (W-181) and the full matrix and Docker gate (W-182). Remaining limitation: the staged copy uses temporary disk up to the output size, and a stream output that fails during the final copy can only be truncated best effort.
