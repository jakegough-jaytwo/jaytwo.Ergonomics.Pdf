# W-99. Decide whether to open files whose /P is written as an unsigned number

## Problem

1. **Summary.** `Open` refuses a password-encrypted file whose encryption dictionary writes `/P` as the unsigned 32-bit value, for example `/P 4294967292` for the permission bits that ISO 32000-1 Table 21 writes as the signed integer `-4`. `PdfSecurity.ReadPermissions` accepts only a value in the `int` range and throws `PdfEncryptedException` ("This encryption is not supported.").
2. **Impact.** Files that pypdf encrypts cannot be opened, filled, or signed. pypdf 6.21.1 `PdfWriter.encrypt` writes `/P` this way for RC4-128 and AES-256, even when passed `permissions_flag=-4`. qpdf 12.4.2 reads the same files and reports `P = -4`; pyHanko 0.38.0 and Poppler `pdfsig` 26.08.0 decrypt them.
3. **Reproduction.** With pypdf 6.21.1: `w = PdfWriter(); w.add_blank_page(612, 792); w.encrypt("user", "owner", algorithm="AES-256"); w.write("p.pdf")`, then `PdfDocument.Open(stream, "user")`.
4. **Expected.** Undecided. ISO 32000-1 Table 21 specifies `/P` as an integer holding the bits as a 32-bit two's-complement value, so `4294967292` is outside the specification. Reading is strict, and tolerated writer quirks are a closed list, each with a real-world fixture, a test, and a `README.md` entry (spec §8). pypdf is a widely used writer, so this may qualify.
5. **Actual.** `PdfEncryptedException: This encryption is not supported.` from `PdfSecurity.ReadNumber`, via `ReadPermissions`.
6. **Severity.** Medium: a predictable failure to open files from one common writer. It is a controlled, documented exception, not corruption.

## Why now

Found by W-97 while building an encrypted pyHanko FieldMDP sample: the form was encrypted with pypdf first, and `Open` refused it. W-97 encrypts that sample with qpdf instead. Not queued.

## Scope and exclusions

Decide, under spec §8, whether an unsigned `/P` in the range 2^31 to 2^32 - 1 is a tolerated writer quirk, read as the same 32 bits. If it is: a pypdf-produced fixture, a test for open, fill, and sign under the user and the owner password, the key derivation using the same 32 bits (revisions 2 to 4 hash `/P` into the file key; revisions 5 and 6 check it against `/Perms`), and a `README.md` writer-quirk entry. Excluded: rewriting `/P` in the output, which keeps the original encryption dictionary.

## Acceptance criteria

Either a pypdf-encrypted file opens, fills, and signs with the same permissions qpdf reports, with a fixture, a test, and a `README.md` entry; or the refusal is listed as a known limitation in `README.md`.

## Evidence required

pypdf 6.21.1 as the producer; qpdf 12.4.2 `--show-encryption` for the expected permission bits.
