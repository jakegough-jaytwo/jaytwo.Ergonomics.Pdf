# W-102. Quiet, tiered verification for agents

## Problem

Verification after a change often costs an agent more context than the change itself, even when every check passes. `make docker-builder docker-test` streams two `docker build` logs, `dotnet test` on three targets, two `reportgenerator` runs, and the fuzz smoke run. A green run is thousands of lines that carry no information. Agents also run the full local matrix and then the Docker gate, which runs net10.0, net8.0, and net6.0 twice (W-70's closeout). And step 5 of `pdf-change-verification` reads as a manual review of properties that the build already enforces as errors.

## Why now

The owner asked for verification to cost fewer tokens without weakening what it proves.

## Scope and exclusions

- `tools/agents/quiet_run.py` runs a command, writes its output to `out/logs/<name>.log`, and prints only the exit status, the per-framework `dotnet test` counts, the failing tests with their messages, the deduplicated build errors, and the fuzz smoke result. It prints the log tail only when none of those explains a failure. With `--tests`, a log that has no test summary fails even on exit 0, so a filter that matches nothing cannot pass silently.
- Makefile targets `quiet-build`, `quiet-test` (with optional `TEST_FRAMEWORK` and `TEST_FILTER`, and coverage off), and `quiet-docker-test`, which wraps `make docker-builder docker-test` unchanged. `make agents-test` also runs the wrapper's tests.
- The owner-approved rewording of the `pdf-change-verification` workflow: verification tiers, the quiet targets, the build as the evidence for StyleCop and XML docs, and no re-reading after a green run.
- Excluded: the Jenkins targets and their output, `AGENTS.md`, the Dockerfile, and what any gate requires.

## Acceptance criteria

- A green focused run prints the status line and one count line for each framework.
- A failing run names each failing test with its message and does not print the tail.
- A run whose filter matches no tests fails.
- `make quiet-docker-test` passes on the current tree and reports net10.0, net8.0, net6.0, and the fuzz smoke result.
- `make agents-test` passes.

## Evidence required

Internally tested: the wrapper's unit tests and observed runs of the targets.

## Notes

- 2026-10-21: `make unit-test` passes a fixed trx `LogFileName`, so each target framework overwrites the previous trx; `out/testResults` held only net10.0's 3610 results. The wrapper reads the console summary lines instead. Fixing the trx name changes Jenkins artifacts and is left for the owner.

## Closeout

- Observed: `make quiet-test TEST_FRAMEWORK=net10.0 TEST_FILTER=FullyQualifiedName~SigningAlgorithmTests` printed a status line and `net10.0: 18/18 passed`. A filter matching no test printed `FAIL (exit 0)` with "no dotnet test summary found" and the tail, and make failed. With `JAYTWO_QPDF` pointing at a missing file, the `ForeignPdfTests` run printed `0/8 passed, 8 failed` and each test's name and "qpdf.exe was not found" message. `make quiet-docker-test` printed 8 lines: PASS in 3m50s, 3610/3610 on net6.0, net10.0, and net8.0, and fuzz smoke passed. The full output went to the 280-line `out/logs/docker-test.log`.
- Verification: `make agents-test` (22 workflow tests and 7 wrapper tests) passed. `make agents-check` and `make task-check` passed.
- Skill edits, owner-approved on 2026-10-21 for review: `.agents/skills/pdf-change-verification/SKILL.md` Workflow adds the tier preamble and the quiet targets, splits steps 2 to 4 into focused, targets, and checkpoint tiers, makes the build the evidence for StyleCop and XML docs in step 5, and in steps 6 and 7 uses the `git diff --stat` and changed hunks and forbids re-reading after a green run.
- Limitations: the summary depends on the VSTest console summary format. A runner change that drops those lines makes `--tests` runs fail rather than pass. The trx overwrite in `make unit-test` is not fixed.
