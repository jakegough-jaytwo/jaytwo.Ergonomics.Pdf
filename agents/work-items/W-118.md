# W-118. Give each Docker run its own image and container names

## Problem

`make docker-builder docker-test` uses fixed names (`jaytwo_ergonomics_pdf__builder` for the image and the container). When two runs overlap, the second `docker run` fails with a name conflict (exit 125), but `docker-run` still copies `out/` from the container that holds the name and reports its results. On 2026-10-22, W-112's first Docker run reported another session's results as its own. A concurrent `docker-builder` can also retag the builder image with a different tree.

## Why now

Many local sessions share this repository, and `make quiet-docker-test` is the checkpoint gate. Queued on 2026-10-23 ahead of W-80 at the owner's direction: W-80 and W-81 produce their evidence through that gate.

## Scope and exclusions

- Default the Docker tag to a per-run unique suffix, overridable for Jenkins, so the image and container names never collide.
- `docker-run` fails, and copies nothing, when its own `docker run` fails before the container starts.
- Excluded: Jenkins configuration.

## Acceptance criteria

Two overlapping `make quiet-docker-test` runs each report their own results, and a name conflict fails the run without copying another container's output.

## Evidence required

Internally tested, by two overlapping local runs.

## Notes

- 2026-10-22: W-112 worked around it by running `make docker-builder DOCKER_TAG=jaytwo_ergonomics_pdf_w112` and `make docker-run DOCKER_TAG=jaytwo_ergonomics_pdf_w112`.
- 2026-10-23: Jenkins' `nugetProject.build` sets `DOCKER_TAG`, `DOCKER_BUILDER_TAG`, and `TIMESTAMP` in the environment and calls `docker-builder`, `docker-copy-from-builder-output`, and `docker-clean`, never `docker-run`, so the generated default and the `docker-run` change do not reach it.
- 2026-10-23: A make invocation without `DOCKER_TAG` sets it once to `jaytwo_ergonomics_pdf__<yyyyMMddHHmmss>_<pid>`. The process ID is the `$(shell)` shell's own: under the Chocolatey native make on Windows, `$PPID` was 1 and two concurrent invocations got the same tag. `quiet-docker-test` runs its sub-make with one tag for `docker-builder` and `docker-test`. A caller-set `DOCKER_TAG`, as W-112 used across two invocations, still applies.
- 2026-10-23: Unique tags would accumulate, because a rebuild no longer replaces the last one. `docker-run` and `docker-fuzz-campaign` remove a generated tag's images when they finish; a caller-set tag keeps them. `docker-clean`, which Jenkins calls, is unchanged.

## Closeout

Done 2026-10-23. Each make invocation without `DOCKER_TAG` gets its own image and container names. `docker-run` creates its container before starting it, so a create that fails, such as on a name conflict, fails the target before it copies or removes anything.

Verification:

- Name conflict, with another container from the builder image holding the name and a marker in its `/build/out`. The `HEAD` recipe exited 125 from `docker run`, copied the marker into `out/`, and removed the other container. The new recipe failed at `docker create`, did not copy the marker, and left the other container in place.
- Two `make quiet-docker-test` runs from separate worktrees of `f7deaa4` with this Makefile, started 20 seconds apart. Their builder containers `jaytwo_ergonomics_pdf__20261023105931_5938__builder` and `jaytwo_ergonomics_pdf__20261023105951_5969__builder` ran at the same time. Tree A: PASS in 19m23s; net10.0 4,375/4,375, and net8.0, net6.0, and the netstandard2.0 lane 3,957/3,957 each; clock phase 24/24 on each host; fuzz smoke passed. Tree B, which had one extra marker test: PASS in 19m42s, with exactly one more test on every host (4,376 and 3,958); fuzz smoke passed. Each run reported its own tree. Afterwards no image or container with a generated name was left.
- `make -n` with a generated tag, with `DOCKER_TAG` on the command line, and with it in the environment showed the expected names, with removal only for the generated tag.

Limitations: overlapping runs in the same worktree still share `out/` and `out/logs/docker-test.log`. The verification skill already requires a separate worktree for the gate. An interrupted run, or a `docker-builder` without a following `docker-run`, leaves a generated tag's images for manual removal.
