# W-216. Make R6 password preparation scalar-correct and deterministic

## Problem

W-155 confirmed incomplete SASLprep and platform-dependent failure behavior (Medium). A raw supplementary noncharacter U+1FFFE password authenticates on modern runtimes but throws ArgumentException from normalization on net48; supplementary private use also authenticates. Full scalar prohibitions are required by RFC4013/3454. Modern NFKC versus Unicode3.2 and invariant globalization also change password matches. Evidence: W-155 `aes-256-{supp-private,noncharacter,nfkc,post32}.pdf`, `r6-unicode32-query.pdf`, runtime TSVs and permanent red scalar assertion.

## Scope and exclusions

First specify exact Unicode3.2 preparation/query semantics and behavior when normalization is unavailable. Present any accepted-password policy change to the owner under proposed D-67 before implementing it. Correct confirmed scalar validation and typed failure defects within the adopted contract; do not leak raw framework exceptions. No raw-UTF-8 fallback, runtime package, new password equivalence, encryption algorithm or parser redesign. Protected wording is proposed, not edited, without owner approval. Proposed and unqueued.

## Acceptance criteria

- Prohibited supplementary scalars receive the same documented typed password rejection across supported runtimes, with a permanent ordinary-suite regression.
- Mapping, bidi and normalization follow the adopted pinned semantics over Unicode scalars, including valid supplementary characters; unsupported host globalization cannot silently change password authentication.
- Exact expected behavior for Unicode3.2-unassigned queries versus stored strings is decided explicitly; pypdf's current Unicode normalizer is not treated as a Unicode3.2 oracle.
- Valid SASLprep preparation, wrong passwords and the R5 raw-byte path retain their contract.

## Evidence required

Focused preparation/encryption regressions on all supported Windows runtime families and Linux ICU/invariant mode. Derive tables/expected values from RFC4013/3454 and version-pinned normalization data. Reuse W-155 probes; no full suite, Docker integration checkpoint or qualification claim required.

## Closeout

Not started; design choices await owner disposition. W-155 is the measured red baseline.
