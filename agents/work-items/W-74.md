# W-74. Raise the catalog version up to 1.7

## Problem

A write that uses a feature newer than the file's effective version does not raise the catalog `/Version` (spec §7.5). Today's writes already emit such keys: an added attachment writes `/UF` in its file specification and in `/EF` (ISO 32000-1 Table 44, PDF 1.7) and may write `/Desc` (PDF 1.6), and a metadata write creates an XMP `/Metadata` stream (Table 28, PDF 1.4). On a 1.4 file the library therefore writes keys that are not valid for the declared version, which `.agents/skills/pdf-core-change/references/structural-invariants.md` forbids.

## Why now

Reset plan C2 item 15. `/PageMode /UseAttachments` (W-75) needs it.

## Scope and exclusions

- The effective version is the later of the header and a catalog `/Version` name (ISO 32000-1 7.5.2, 7.7.2).
- Each write declares the version of the newest ISO 32000-1 key it emits, taken from the key's version marker. The PDF Association Arlington model (`tsv/latest`, `SinceVersion`) was the cross-check:
  - adding an attachment: 1.7 (`/UF`); removing one: 1.4 (it rewrites `/EmbeddedFiles`);
  - writing XMP, directly or by an Info edit that keeps XMP in step: 1.4 (`/Metadata`);
  - Info `Title`, `Subject`, `Keywords`, and `ModDate`: 1.1; `Trapped`: 1.3 (Table 317);
  - a fill: 1.2 (widget `/AP` and `/AS`, AcroForm `/NeedAppearances`);
  - a signature or document timestamp: 1.3 (signature field and dictionary, `/SigFlags`).
- When that version is later than the effective version, the same revision sets catalog `/Version`. The catalog `/Version` key is itself PDF 1.4 (Table 28), so a raise writes at least `/1.4`, and never more than `/1.7`. An effective version of 1.7 or later, including 2.0, is never raised or lowered. The header is never rewritten.
- `/AF`, `/AFRelationship`, `/SubFilter /ETSI.CAdES.detached`, `/ETSI.RFC3161`, and `/Type /DocTimeStamp` never trigger a raise: ISO 32000-1 does not define them (Arlington lists them as ISO 19005-3 or ETSI PAdES extensions to 1.7, or PDF 2.0).
- The raise is made inside the write, so a refused or failed write rolls it back with the rest of its edits.
- Excluded: Rotate (`/Rotate` is PDF 1.0), usage-rights removal (it rewrites an existing `/Perms`), and flatten, which W-77 adds.

## Acceptance criteria

`ACCEPTANCE.md` gains an Opening bullet for the raise; the header bullet is unchanged. `README.md` Support matrix "PDF versions" Modify cell states the rule.

- Adding an attachment to 1.4, 1.5, and 1.6 inputs writes `/Version /1.7`, and Poppler `pdfinfo` reports 1.7. A 1.7 input and a 1.4 input with catalog `/Version /1.7` are reported at 1.7 and gain no `/Version`.
- The LibreOffice PDF/A-3b corpus file stays at effective version 1.7 after an attachment add, writes no `/Version`, and `/EmbeddedFiles` still lists its source file. No PDF/A claim is made.
- A catalog `/Version /2.0` stays 2.0 after an attachment add.
- An XMP write raises a 1.3 input to 1.4 and leaves a 1.4 input alone. A fill raises a 1.1 input to 1.4 and leaves a 1.2 input alone. Signing a 1.2 input writes `/Version /1.4` inside the signed range.
- C4: a 128-bit RC4 1.4 input raised by an attachment add under the owner and the user password keeps the prefix, `/Encrypt`, and `/ID`, and `pdfinfo` with that password reports 1.7. A user password without modify is refused before any edit and the save does not extend the file. A refused fill and a failed signature leave no raise. Certification, approval-signature, FieldMDP, and usage-rights decisions are unchanged: the raise rides on writes that already passed them and never changes `/Perms`.

## Evidence required

Independently validated: Poppler `pdfinfo` (the effective-version reader; it reports the later of the header and catalog `/Version`) on every output.

## Closeout

Done 2026-10-21. `PdfEngine` reads the header version at open and computes the effective version from it and the current catalog `/Version`. `RaiseVersion` edits the catalog inside the write that needs it, so the existing backup and restore of fills and signatures roll it back and a refused write never reaches it. Call sites: Info text and date keys, `Trapped`, the `ModDate` refresh, XMP writes, the `/EmbeddedFiles` rewrite (1.4), an attachment add (1.7), a fill (1.2), and a signature or document timestamp (1.3).

Limitations:

- Every attachment add on a file below 1.7 now declares 1.7, because `/UF` is PDF 1.7. W-75's `/PageMode /UseAttachments` (1.6) is therefore already covered whenever it comes with an add.
- Adobe Reader's view of a `/Version` change on a Reader-extended (`/UR3`) file was not tested; no Adobe product is available. The usage-rights decision itself is unchanged.
- An approval-signed file below 1.4 that gets an XMP write gains a catalog `/Version` change after the signature. pyHanko's verdict on that combination was not measured. Signed files in the corpus are 1.4 or later.
- No PDF/A conformance is claimed, and no veraPDF run was made.
