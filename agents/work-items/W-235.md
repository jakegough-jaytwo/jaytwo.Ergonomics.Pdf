# W-235. Retain failed bytes for ordinary workflow Save(Stream)

## Problem

WORKFLOW-STREAM-02 and WORKFLOW-RESTORE-01: a failed ordinary stream save leaves the bytes written, without truncation or rewind. The engine truncated the caller's stream to its starting length.

## Scope and exclusions

Ordinary `Save(Stream)` and `SaveAsync(Stream)`, using W-233's `FailedOutputRetainingStream`. Out: Combine, extract, image-to-PDF, `AppendToSource`, `Sign`, `Timestamp`, the engine.

## Acceptance criteria

- After a source failure past the first output block, sync and async, the destination holds exactly the written bytes, stays open, and the description is consumed.
- A refusal before any write leaves the stream empty and open.
- Other terminals and the engine are unchanged.

## Evidence required

`WorkflowStreamFailureTests` (failed on the old source: 2 of 4); the full Ergonomics suite on net10.0; net48, net8.0 and net6.0 for the new and file tests; build; `make agents-check`, `make task-check`.
