# W-218. Establish an enduring charter for both PDF libraries

## Problem

The owner wants a concise, enduring charter to guide requirements, supported features, and implementation for both libraries. The existing untracked draft describes a narrower four-workflow 1.0 release; README history and the current research backlog provide context but must not determine future scope.

## Scope and exclusions

Develop the charter at `docs/CHARTER.md` and align `docs/SUPPORTED.md` and `docs/behavior.md` with the owner's new reset. Keep SUPPORTED.md a durable intended-scope commitment independent of implementation status; current guarantees belong in behavior.md, and priorities and progress belong in planning records. Preserve existing behavior contracts. Wiring the charter into AGENTS.md and the README remains pending authority alignment; no protected wording, runtime, specification, qualification, or backlog implementation changes in this transaction.

## Acceptance criteria

- A concise charter distinguishes the independently useful engine from the workflow library and records the owner's agreed scope, architectural principles, production standard, compatibility policy, and governance.
- The charter contains no release schedule, exhaustive support matrix, usage examples, or implementation inventory.
- Owner review resolves adoption and the relationship to existing stricter rules before the charter is wired into AGENTS.md and the README.

## Evidence required

Manual comparison with the owner's interview decisions; make agents-check; staged make task-check; git diff --cached --check. Documentation only; no runtime tests or Docker checkpoint.
