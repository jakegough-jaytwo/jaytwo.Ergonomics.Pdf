# W-151. Enforce seed values and report failed signing rollback

## Problem

Signing an existing field can ignore mandatory `/SV` seed-value constraints. A failure after writing can also be followed by a truncate failure that is swallowed, obscuring the destination's final state.

## Scope and exclusions

Inspect mandatory seed-value requirements before signing, honor constraints already supported by the signing API, and refuse unsupported mandatory requirements. Preserve the original signing failure while making a rollback failure and possible partial destination modification observable. Do not widen supported algorithms, profiles, or signer contracts without an owner decision.

## Acceptance criteria

- Supported mandatory seed-value constraints are enforced, and unsupported mandatory requirements fail before signing bytes are committed.
- Optional or irrelevant seed-value entries do not create new refusals.
- Fault-injection tests cover partial writes, successful rollback, failed truncation, and the combination of an original failure with rollback failure.
- Failure reporting never claims rollback succeeded when a caller-owned destination may remain modified, and documentation states the residual risk accurately.

## Evidence required

Focused signing tests with seed-value fixtures and fault-injecting streams on net10.0 and net48, plus the existing signing interoperability tests if signing output changes.
