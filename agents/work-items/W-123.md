# W-123. Interop tests run on net10.0 only, guarded by an output-identity test on every target

## Problem

`make unit-test` runs every interop test on net10.0, net8.0, net6.0, the netstandard2.0 lane, and net48 on Windows. An interop test asks an implementation written elsewhere to judge bytes the library wrote, and the library writes the same bytes on every target (D-52), so four of the five runs repeat the question. In the 2026-10-23 Docker gate, tests that start tools took about 1,180 s of the 2,160 s summed test time on each framework, and their load slowed every other test running beside them.

`make unit-test` also hides a failing test project: its `for` loop over `BUILD_TEST_DIRS` exits with the status of the last iteration, so a failure in `jaytwo.Ergonomics.Pdf.Tests` passes the target when the netstandard2.0 lane passes after it. A two-iteration reproduction under GNU make exits 0 with the first iteration failing.

## Why now

The owner asked for interop to run on one framework (D-52), and W-122 marked the interop tests.

## Scope and exclusions

- `OutputIdentityTests` on every target: seven fixed edits (metadata, fill, fill and flatten, rotation, compressed attachment, RC4 fill, signature) whose appended revision must equal a recorded canonical text. The canonical text inflates FlateDecode streams and masks `/ModDate`, the signature `/Contents`, and the offsets after an inflated stream. `make output-identity-record` rewrites the recorded text from net10.0.
- `make unit-test` builds once and runs each framework in parallel with `--no-build`, `Interop` left out except on net10.0, and fails when any run fails.
- A `Clock` category for tests that assert on elapsed wall-clock time. `make unit-test` leaves them out of the parallel runs and runs them afterwards on each host in turn, with their own coverage output.
- `AGENTS.md` and `README.md` say where interop runs.
- Excluded: caching tool-made inputs across frameworks (External tests still run everywhere), the AES path (its initialization vector is random), and changing any test's assertions.

## Acceptance criteria

1. `OutputIdentityTests` passes on net10.0, net8.0, net6.0, net48, and the netstandard2.0 lane against text recorded on net10.0, and two runs a second apart record the same text.
2. A change to the written bytes fails it on every target with the first differing line.
3. `make unit-test` runs `Interop` on net10.0 only, runs `Clock` tests after the parallel runs, and exits non-zero when any one run fails.

## Evidence required

Internally tested: the output-identity test on every target, the masked-failure reproduction against the new loop, and the Docker gate.

## Notes

- 2026-10-23: Started at the owner's direction on branch `lanes` after W-122.
- 2026-10-23: The writer's nondeterminism is the clock (`/ModDate`, XMP `ModifyDate`), a new `/ID` when the input has none, and AES initialization vectors; only a compressed attachment produces Deflate output. The scenarios give their inputs an `/ID`, use RC4 for the encrypted case, and fix the attachment and signing times, so no library change was needed. The signature `/Contents` is masked because each run makes a new key.
- 2026-10-23: `make unit-test` keeps the parallel frameworks that a multi-targeted `dotnet test` gave it: one build, then each framework as a background `--no-build` run with its own log and TRX file. The TRX names change from `<project>.trx`, which each framework overwrote, to `<project>-<framework>.trx`. Jenkins' `nugetProject.build` is outside this repository; if it reads TRX files by name, it needs the new names.
- 2026-10-23: `docs/spec/phase-1.md` says "Tests run on `net6.0`, `net8.0`, and `net10.0`, and on `net48` on Windows." The suite still runs there, without `Interop`. Raised with the owner in case the spec should say so; not edited.
- 2026-10-23: First Docker gate (`DOCKER_TAG=jaytwo_ergonomics_pdf_lanes`): FAIL in 12m54s. net10.0 4,399/4,399, net8.0 and net6.0 3,981/3,981, netstandard2.0 lane 3,980/3,981; `HardeningTests.dictionary_with_many_distinct_keys_is_parsed_without_a_per_key_scan` took 11.49 s against its 10 s bound. The bound guards against a quadratic parse, which would take minutes, so it was not widened. The eight tests that assert on elapsed time (that one, three in `OpenTests`, and W-121's `HttpTimestampTimeoutTests`) now carry `Clock` and run after the parallel hosts. W-121's commit was merged from `wip` first so its class could be marked.

## Closeout

Done 2026-10-23. `make unit-test` runs `Interop` on net10.0 only, `Clock` tests after the parallel hosts, and fails when any run fails. `OutputIdentityTests` holds on every target. The owner approved the `AGENTS.md` and verification-skill wording before merge.

Verification:

- `make quiet-test TEST_FILTER="Category=Clock|FullyQualifiedName~OutputIdentityTests"` on Windows 11: PASS, 31/31 on net10.0, net8.0, net6.0, net48, and the netstandard2.0 lane (criterion 1). `make output-identity-record` twice, five seconds apart, wrote identical text.
- With `/Rotate 90` recorded as `/Rotate 180`, net10.0 and net48 each failed with `rotate line 7 differs on this target`, the expected and actual lines, and the record instruction (criterion 2).
- The `unit-test` recipe with a stub `dotnet`: no filter but `Category!=Clock` on net10.0, `Category!=Clock&Category!=Interop` elsewhere, then `Category=Clock` per host; a failing parallel run and a failing clock run each fail the target, and a passing set reaches the coverage step (criterion 3). The old loop's masked failure reproduced under GNU make before the change.
- `make quiet-docker-test DOCKER_TAG=jaytwo_ergonomics_pdf_lanes`: PASS in 13m37s. Parallel runs: net10.0 4,375/4,375 (with `Interop`), net8.0, net6.0, and the netstandard2.0 lane 3,957/3,957 each, all about 11.3 minutes; clock phase 24/24 on each host in 3 to 4 s; fuzz smoke passed. The same day's three-host gate before this change took about 23 minutes.
- `make quiet-test LANE=fast TEST_FRAMEWORK=net10.0`: PASS, 3,910/3,910.

Limitations: `make unit-test` on Windows (with net48 and coverage) was not run; the fast lane and the filtered runs above covered net48. Jenkins' TRX handling for the new file names is unverified. Interop evidence for net48 and the netstandard2.0 build now rests on output identity, which does not cover a runtime-specific Deflate encoder defect or the library's own assertions inside `Interop` tests.
