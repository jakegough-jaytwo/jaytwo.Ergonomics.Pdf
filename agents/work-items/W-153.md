# W-153. Add bounded and path-safe attachment extraction

## Problem

Attachment names and declared `/Params /Size` values are untrusted. Consumers need a supported way to bound decoded extraction bytes and convert an embedded name into a safe local filename without treating it as an output path.

## Scope and exclusions

Add an explicit decoded-byte limit for attachment reads or extraction and a convenience primitive that produces a safe filename component. Keep the existing streaming API available. Do not choose an output directory for the caller, perform malware scanning, or claim that attachment content is safe.

## Acceptance criteria

- A caller can enforce a decoded-byte limit independent of the declared attachment size, with deterministic failure before bytes beyond the limit are returned or published.
- The filename primitive neutralizes rooted paths, traversal segments, separators, reserved platform names, empty names, and other tested unsafe forms without silently selecting a directory.
- Existing streaming behavior remains available and sparse for large attachments.
- XML documentation and README guidance state that names, sizes, and contents are untrusted.

## Evidence required

Focused attachment tests for compressed and uncompressed content, false declared sizes, limit boundaries, hostile names, and large streaming behavior on Windows and Linux.

## Closeout

Completed 2026-10-24.

- Added `PdfAttachment.Open(long maxDecodedBytes)`. It limits decoded bytes independently of the untrusted declared
  `/Params /Size`, supports synchronous and asynchronous stream reads, and throws `PdfAttachmentTooLargeException`
  before returning a byte beyond the caller's limit. `Open()` remains unchanged and unlimited.
- Added `PdfAttachment.GetSafeFileName()`. It emits one non-empty component bounded to 255 UTF-16 code units and 255
  UTF-8 bytes; neutralizes path separators, traversal-only names, portable invalid characters, trailing periods and
  spaces, and Windows device names; and deliberately does not choose a directory or guarantee uniqueness.
- Updated XML documentation, `README.md`, and `ACCEPTANCE.md` to identify attachment names, declared sizes, and content
  as untrusted.

Verification:

- `make quiet-test TEST_FILTER=FullyQualifiedName~AttachmentTests` on Windows: engine attachment tests 41/41 on
  net10.0, net8.0, net6.0, net48, and the netstandard2.0 lane; matching workflow attachment tests 18/18 on each runtime.
- The same focused engine command in the Ubuntu 26.04 builder image: 41/41 on net10.0.
- `make quiet-build`: PASS for the solution and all targets, including StyleCop and XML documentation.
- `graphify update .`: PASS (6 code files re-extracted; graph rebuilt to 6,559 nodes).

Limitations: sanitized names can collide, and a limited stream may have returned up to the limit when the next read
discovers more content. Callers that need all-or-nothing publication must copy to a private temporary file, then publish
it only after the copy completes.
