# W-135. Split PdfParser into lexer, object parser, and cross-reference and object-stream readers

## Problem

`Internal/PdfParser.cs` is 1,384 lines that mix tokenizing, object parsing, classic and stream cross-reference reading, and object-stream parsing. D-55 makes the parser async-capable in W-132; the owner asked for the parser to be refactored for maintainability first.

## Scope and exclusions

Behavior-preserving split (`csharp-refactoring`):

- `PdfLexer`: tokens, the pushback, and the token caps.
- `PdfParser`: values, dictionaries, arrays, indirect objects, and stream extents.
- `PdfXrefReader`: classic sections, xref stream entries, the entry budget, and their limits.
- `PdfObjectStreamReader`: object-stream headers and objects, and the read-factor budget.

Constants move with the code that enforces them; tests and fuzz targets follow. No change to parsing behavior, messages, offsets, limits, or allocation, and no async work (W-132).

## Acceptance criteria

- Each new file holds one responsibility; no file in the split exceeds about 600 lines.
- The build passes with StyleCop warnings as errors on every target, and parser, hardening, allocation, and open tests pass unchanged apart from the moved member names.

## Evidence required

`make quiet-test LANE=fast` (the parser sits under every engine test), plus the build of every target.

## Closeout

Split `PdfParser.cs` (1,384 lines) by moving code verbatim: `PdfLexer` (567 lines; tokens, pushback, `MaxTokenBytes`), `PdfParser` (360; values, dictionaries, indirect objects, stream extents, `MaxContainerEntries`), `PdfXrefReader` (365; classic sections, stream entries, the entry budget and its limits), `PdfObjectStreamReader` (119; headers, objects, the read factor), plus the `PdfToken` and `PdfTokenKind` types. Messages, offsets, limits, and allocations are unchanged. Renamed members: `XrefEntryBudget`, `MergeXrefEntry`, `ParseXrefEntries`, and `EnsureXrefColumns` became `PdfXrefReader.EntryBudget`, `MergeEntry`, `ParseStreamEntries`, and `EnsureColumns`; the xref constants dropped their `Xref` prefix; `ParseObjectStream` became `PdfObjectStreamReader.Parse`. `ParseStreamEntries` is static, since it never used parser state, so `PdfEngine.ReadXrefStream` no longer takes a parser. Tests and the fuzz `objstm` target follow the new names.

Verification: `dotnet build jaytwo.Ergonomics.Pdf.sln` and the fuzz project, 0 errors on every target with StyleCop warnings as errors; `make quiet-test LANE=fast` passed 3,917/3,917 on net10.0, net8.0, net6.0, net48, and the netstandard2.0 build on net8.0.

For owner approval: `.agents/skills/pdf-core-change/references/structural-invariants.md` line 15 and `.agents/skills/pdf-fuzz-qualification/references/targets.md` line 10 still name `MaxXrefEntries`, `MaxXrefStreamObjects`, `XrefEntryBudget`, and `PdfParser.ParseObjectStream`. The proposed new names are `PdfXrefReader.MaxEntries`, `PdfXrefReader.MaxStreamObjects`, `PdfXrefReader.EntryBudget`, and `PdfObjectStreamReader.Parse`. Dated reports keep the old names as history.
