# W-78. Rotate pages

## Problem

Pages cannot be rotated (spec W6, §7.2).

## Why now

Reset plan C2 item 20.

## Scope and exclusions

- Set `/Rotate` on the page object, normalized to 0, 90, 180, or 270.
- The signed-document opt-in of §7.2.

## Acceptance criteria

- `PdfDocument.Pages[n].Rotation` accepts 0, 90, 180, and 270 and normalizes every other positive or negative multiple of 90 into that range. A value that is not a multiple of 90 throws `ArgumentOutOfRangeException` and leaves the document clean.
- The normalized `/Rotate` is written directly on the selected page object, overriding an inherited `/Rotate`. Reopening reports the new rotation while the media box, crop box, and field rectangle remain the same PDF user-space coordinates; the field reports the new page rotation.
- pypdf reads the direct page `/Rotate`, the unchanged boxes, and the unchanged widget rectangle. Poppler renders the page in the rotated orientation.
- DocMDP blocks rotate at `P` 1, 2, and 3. An approval signature or document timestamp requires `PdfDocument.AllowBreakingSignatures`; with the opt-in, the existing signed bytes stay as a prefix. FieldMDP does not apply.
- Rotation removes `/UR3` on an unsigned document because no usage right grants it, and keeps `/Perms` unchanged on a signed document.
- Plan C4: AES-256 and 128-bit RC4 input rotate under the owner and a user password with modify permission; a user password without modify permission refuses and leaves the document clean. `/Encrypt` and `/ID` are kept, the original bytes are a prefix, pypdf reads the result with the password, and every documented refusal leaves a later save byte-identical.

Refine these criteria, and the `ACCEPTANCE.md` rows they add or change, when the item becomes active. A write item also meets every check in plan C4.

## Evidence required

Independent reader and renderer.
