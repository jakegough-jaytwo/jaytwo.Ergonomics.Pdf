# W-96. Owner review of the W-68 form value choices

## Problem

W-68 (commit W-68) shipped three choices that the owner wants to revisit before 1.0. Each was recommended as built and is reversible before 1.0.

1. **Value type (spec §12 question 7).** `PdfFieldValue` is a readonly struct whose default is `None`, not a class with `null` for no value, so the spec's `Dictionary<string, PdfFieldValue>` example raises no nullable warning. Question 7 is still open in `docs/spec/phase-1.md` until the owner closes it.
2. **What `Export` leaves out.** Signature fields, push buttons, and password fields. Read-only fields are exported, so a caller filling from an export must skip them using `PdfField.ReadOnly`.
3. **No value clears radio and choice fields.** Needed so a form with an unselected radio or combo box can be filled back from its own export.

Related: removing `SetText`, `SetCheckBox`, `SetRadio`, and `SetChoice`, and renaming `PdfAppearanceDisposition.NeedAppearances` to `NeedsViewer`, break existing callers.

## Why now

The owner asked on 2026-10-21 to note these and return to them later. Not queued.

## Scope and exclusions

- The owner confirms or changes each choice. A confirmed question 7 is closed in the spec with the owner's approval; a changed choice becomes its own item.
- Excluded: any change before the owner decides.

## Acceptance criteria

Each choice is recorded as confirmed or turned into an item, and spec §12 question 7 is closed or left open on the owner's word.

The owner's decision, recorded in Notes.
