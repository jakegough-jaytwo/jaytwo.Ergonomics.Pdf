# W-14. Add a second PDF-aware signature verifier

## Problem

pyHanko 0.38.0 is the only recorded PDF-aware verifier. `SignedCms.CheckSignature` does not open the PDF and therefore does not satisfy the second-verifier requirement.

## Why now

Gate G4 requires two independent verifiers, one of which understands PDF signature semantics.

## Scope and exclusions

Run Poppler `pdfsig`, or another PDF-aware verifier that is not pyHanko. PDFBox is acceptable when its validation limits are recorded. Do not count `SignedCms` as the second verifier and do not add signature validation to the library.

## Acceptance criteria

The second verifier checks supported signed output, and the record names the tool, version, and property established.

## Evidence required

Independently validated evidence under `QUALIFICATION.md` section 6.

  - **Tests.** `Pdfsig.cs` locates `pdfsig` through `ExternalTool.Locate("JAYTWO_PDFSIG", ...)` and `certutil` through `JAYTWO_CERTUTIL`, beside `pdfsig`, or `PATH` outside Windows, builds a fresh NSS database trusting only the test's roots (`,C,`; `C,,` is SSL only and left the root untrusted), and runs `pdfsig -nssdir sql:... -no-ocsp`. `SigningInteropTests` gains three tests that run `pdfsig` and pyHanko on the same bytes, and the SoftHSM test adds a `pdfsig` check and is renamed `pkcs11_signature_matches_pkcs1_and_pyhanko_and_pdfsig_trust_the_chain` (acceptance-matrix row 43 updated). `validate_signature.py` gains an `invalid` check: an intact byte range whose signature value does not verify. What each test establishes, the tool versions, and `pdfsig`'s limits are in `agents/evidence/qualification/g4-pdfsig.md`.
  - **pdfsig limits.** No modification analysis (a later revision is only `Not total document signed`); the embedded RFC 3161 token is not checked; the library's `/ETSI.RFC3161` document timestamp is `Signature Type: unknown`, `Signature has not yet been verified.`, exit 1; the certificate is validated at the current time, not the signing time; the exit code ignores trust.
  - **Finding (W-97, proposed, not queued).** On an encrypted file the library writes `/M`, `/Reason`, `/Location`, `/ContactInfo`, and `/Name` in plaintext, as `AGENTS.md` and spec §7 require. Poppler and pypdf decrypt them and get garbage; pyHanko writes them encrypted and leaves only `/Contents` plaintext. With the tests' usual CMS signing time at the Unix epoch, `pdfsig` falls back to `/M` and crashes (access violation, 12 of 12 encrypted samples; also on an unencrypted file with a non-date `/M`). The signature itself verifies. The encrypted case here signs with a current time, with a comment pointing to W-97. Changing the plaintext rule is the owner's decision.
  - **Finding (W-98, proposed, not queued).** In the Windows Release run with all four targets at once, `SignatureTests.stalled_timestamp_response_headers_still_time_out` failed once on net48: the timeout's inner exception was null, not `TimeoutException`. It passed 8 of 8 runs alone and in a full net48 rerun. No runtime code changed here; the likely cause is a timer race in `HttpTimestampAuthority`.
  - **W-94.** A dated note there names `pdfsig` and `certutil` for the `AGENTS.md` tool paragraph, which W-14 does not edit.
