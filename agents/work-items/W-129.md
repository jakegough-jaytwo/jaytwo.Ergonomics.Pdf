# W-129. Create and enforce the jaytwo.Pdf engine project boundary

## Problem

Reset stage R1 step 1 (`reset-plan.md` section 7). The engine lives in `src/jaytwo.Ergonomics.Pdf` under the `jaytwo.Ergonomics.Pdf` namespaces. D-54 and `AGENTS.md` place it in a non-packable `jaytwo.Pdf` project that `jaytwo.Ergonomics.Pdf` references one way.

## Scope and exclusions

- Add `src/jaytwo.Pdf/jaytwo.Pdf.csproj` with the current targets and runtime dependencies and `IsPackable=false`, and add it to the solution.
- Move every source file under `src/jaytwo.Ergonomics.Pdf` into it, renaming namespaces from `jaytwo.Ergonomics.Pdf` to `jaytwo.Pdf` and `jaytwo.Ergonomics.Pdf.Internal` to `jaytwo.Pdf.Internal`. `jaytwo.Ergonomics.Pdf` references `jaytwo.Pdf` and keeps no PDF implementation.
- `jaytwo.Pdf` grants `InternalsVisibleTo` to the existing test, `netstandard2.0` lane, and fuzz assemblies until W-130 renames them.
- Point the test, comparison, and fuzz projects at `jaytwo.Pdf` and update their namespaces.
- A boundary test fails if `jaytwo.Pdf` references `jaytwo.Ergonomics.Pdf`.
- State in Closeout how `pack` and `nuget-check` behave with the unpackaged engine (`AGENTS.md` CI); change the `Makefile` only as that requires.
- Update namespaces in `README.md` and `ACCEPTANCE.md`.

No API redesign, algorithm change, or test move between projects (W-130). Signing code moves as-is.

## Acceptance criteria

- Every target builds with StyleCop warnings as errors; `jaytwo.Pdf` has no reference to Ergonomics, and the boundary test passes.
- Existing tests pass unchanged except for namespaces and project references.
- `OutputIdentityTests` passes without re-recording: the move changes no output bytes.
- The fuzz project builds against `jaytwo.Pdf`.

## Evidence required

`make quiet-test LANE=fast` (the change is cross-cutting), `OutputIdentityTests` on net10.0, and `make fuzz-smoke`.

## Closeout

Done. The 71 engine source files moved with `git mv` to `src/jaytwo.Pdf` (`IsPackable=false`, the same targets and `netstandard2.0` packages, `InternalsVisibleTo` for the three existing test and fuzz assemblies). Their namespaces are now `jaytwo.Pdf` and `jaytwo.Pdf.*`. `jaytwo.Ergonomics.Pdf` has no sources: just a project reference to `jaytwo.Pdf`, with its own package references and `InternalsVisibleTo` removed. The test, `netstandard2.0` lane, comparison, and fuzz projects reference `jaytwo.Pdf`. Tests changed only in usings, plus `EngineBoundaryTests`, which asserts that the assembly is named `jaytwo.Pdf` and references no `jaytwo.Ergonomics*` assembly. `tools/fuzz/run-campaign.sh` now instruments `jaytwo.Pdf.dll`. `README.md` has the new usings and names the engine project; `ACCEPTANCE.md` had no namespace references, so it is unchanged.

Packaging: `pack` still packs only `jaytwo.Ergonomics.Pdf`. Its nupkg now declares a dependency on `jaytwo.Pdf 0.1.0`, which is not published, and `nuget-check` still runs against it. `nuget-push` now exits 1 with a D-54 message before pushing anything, so a package that cannot be installed is never published. Removing that one line restores push once the owner adopts packaging. If Jenkins `nugetProject.build` calls `nuget-push` on `main`, that stage will fail on purpose.

Found along the way: since W-122, the comparison project (which is not in the solution) failed to build, because the `ExternalTool.cs` it links calls `Lane`. It now links `Lane.cs` too and builds.

Verification: the solution builds with StyleCop warnings as errors, and so does `test/jaytwo.Ergonomics.Pdf.Comparison`. `make quiet-test LANE=fast` passes 3911/3911 on net10.0, net8.0, net6.0, net48, and the net8.0 `netstandard2.0` lane; that includes `OutputIdentityTests` with no re-recording and `EngineBoundaryTests`. `make fuzz-smoke` passes: 8 targets, 0 failures.
