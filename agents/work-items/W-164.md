# W-164. Concatenation, form namespaces, and encrypted input (N2)

## Problem

Concatenation adds several input occurrences, form-field collisions, and encrypted inputs to extraction (spec N2, A2, A11).

## Scope and exclusions

Accept several occurrences, including one file twice. Add one parent field per occurrence and refuse a form the writer cannot preserve. Add the encrypted-input option, the permission rule per input, and removal of the encryption layer only. Excluded: re-encrypting the output and merging same-named fields.

## Acceptance criteria

- A2: equal field names in two occurrences stay separate fields, and links stay inside their occurrence.
- A11: an encrypted input is refused without the option. With it, owner access and sufficient user access succeed; R2 needs bits 4 and 5 and R3 or later needs bits 5 and 11. Every input is checked.
- RC4, AES-128, and AES-256 inputs decrypt to unencrypted output with the compression filters unchanged; a `/Crypt` filter is removed with its parameters.
- A form with unpreservable scripts, calculation order, or default resources is refused before output.

## Evidence required

Focused tests on net10.0 and `make quiet-build`.
