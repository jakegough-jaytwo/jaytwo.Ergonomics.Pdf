# W-226. Carry an unedited direct trailer Info dictionary through an incremental save

## Problem

Found while testing W-224: when the source trailer holds `/Info` as a direct dictionary and a save appends a revision for an unrelated edit, the new trailer has no `/Info`, so reopening loses Title and every other Info value. `WriteTrailerEntries` emits `/Info` only for an indirect Info object number. The original bytes remain a prefix, so a reader of the newest trailer sees no Info (the older trailer's Info is not consulted).

## Scope and exclusions

Write the existing direct Info dictionary into the new trailer. Out: other trailer entries, a full-document rewrite, spec changes. Broader trailer findings are recorded below, not fixed.

## Acceptance criteria

- After an unrelated edit and `SaveIncremental`, a direct trailer Info keeps its values on reopen; original bytes are a prefix; an indirect Info and a no-edit save behave as before.
- qpdf accepts the output and shows `/Info` in the trailer.
- The regression test fails on the old code.

## Evidence required

`InfoPreservationTests` against old and new code; metadata and encryption tests; full net10.0 suite; build; `make agents-check`, `make task-check`.

## Closeout

2026-11-01: reproduced through the public API: Title `Old` before the save, null after reopen (direct case only; the indirect control and the no-edit control passed on the old code). Fix: `PdfIncrementalWriter.WriteTrailerEntries` writes `_store.InlineInfo` as a direct dictionary when there is no indirect Info, through the new `PdfSerializer.WriteTrailerValue`, which encrypts its strings as object 0, generation 0 (the way the loader decrypts them). This applies to both the classic trailer and the xref-stream dictionary.

Checks run: `InfoPreservationTests` net10.0 6/6 (the direct-Info edit test and the qpdf test failed on the old code; the qpdf run showed a trailer with no `/Info`); full `jaytwo.Pdf.Tests` net10.0 4827/4827; new and W-224 tests net48 13/13; `make quiet-build` (StyleCop as errors); `make agents-check`, `make task-check`. qpdf 12.3.2 `--check` and `--show-object=trailer` are the independent reader. Not run: Docker checkpoint, Ergonomics suite. Not covered: an xref-stream source with a direct Info and a hybrid file were not tested; no independent reader exists for the encrypted case.

Separate observations, not fixed: (1) ISO 32000-1 treats the trailer as unencrypted, so decrypting and encrypting direct trailer Info strings as object 0 is the loader's existing convention and may disagree with other readers. (2) W-224's untested cancellation path remains untested.
