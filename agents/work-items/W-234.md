# W-234. Amend ASSEMBLY-FORM-02 naming and correct the forms status wording in the pages contract

## Problem

The owner decided that an input entry with no repeated page keeps `InputN.` field names and that an entry in which any page repeats uses `InputN.CopyM.` for every retained field, even when the repeated page has no fields. This supersedes the uniform `Copy1` rule of ASSEMBLY-FORM-02. Separately, `docs/spec/pages.md` still called the forms contract frozen and unadopted, though forms is adopted as W-219-FORMS-2026-10-31-R2.

## Scope and exclusions

Documentation only: ASSEMBLY-FORM-02 and its dependent wording in the pages contract, an adoption-record amendment, the matching drafting records, and the forms status wording in the pages contract. Out: ASSEMBLY-FORM-03 to 05 (including uneven-repeat grouping), forms eligibility, any new behavior, code, tests, `docs/behavior.md`, `docs/acceptance.md`. `docs/spec/opening-and-saving.md` carries the same stale forms wording; it is not changed here.

## Acceptance criteria

- ASSEMBLY-FORM-02 states the entry-level switch exactly as decided; FORM-03 to 05 and the partial-group table are unchanged apart from a sentence saying group numbers appear in names only for repeating entries.
- No wording in `docs/spec/pages.md` calls forms frozen or unadopted, and the forms boundary adds or removes no assembly behavior.
- The adoption record, history, reconciliation and closeout proposal agree with the amended rule.

## Evidence required

`make agents-check`, `make task-check`, and a review of the documentation diff.

## Closeout

2026-11-01: Documentation amended as scoped. Implementation of the naming rule is not started; it needs its own item. Existing tests that assert `Input1.Name` for repeated entries (`PageConcatenationTests.cs` lines 27 to 49 and 188) will change then.
