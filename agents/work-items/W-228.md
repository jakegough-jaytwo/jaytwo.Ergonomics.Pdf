# W-228. Reject invalid workflow terminal arguments before the description is consumed

## Problem

WORKFLOW-BEGIN-01 (adopted): null and syntactically invalid arguments, an ineligible destination stream (not writable, not seekable, not empty at position zero) and a path that cannot be formed fail without consuming the description; from the point those checks pass, execution has begun. `PdfWorkflowBuilder` called `Begin()` first in the save, sign, timestamp and append terminals, so every such rejection consumed it. `PdfCombineWorkflow` claimed first as well. The builder's stream check also ignored `Position`. An existing test (`a_rejected_terminal_call_also_consumes_the_workflow`) encoded the old behavior.

## Scope and exclusions

Move the claim after the source-independent argument checks in every terminal; add the position check to the builder streams; keep the single atomic claim. Rule for the checks that depend on the file system or the input rather than on an argument (missing destination directory, existing file without overwrite, append on an input that cannot be appended): they stay after the claim, as refusals. Out: the adopted output and ownership rules, direct-file output and the create-or-overwrite default (WORKFLOW-FILE-04, a separate implementation gap), the W-227 encrypted direct-source loader observation (recorded, untouched).

## Acceptance criteria

- Each rejected case leaves the description usable for a corrected terminal call that runs once.
- A refusal, failure and pre-cancelled token after accepted arguments each consume it exactly once; later calls write nothing.
- Concurrent calls cannot both execute; a rejected call does not take the claim.
- New tests fail on the old code.

## Evidence required

`WorkflowBeginTests` and the signing cases against old and new code; full Ergonomics net10.0 suite; build; `make agents-check`, `make task-check`.

## Closeout

2026-11-01: confirmed that every rejected argument consumed the description in all builder terminals and in Combine. Fix: `Begin()` (and the Combine `Interlocked` claim) moved after the argument checks; the builder and Combine stream checks now also require `Position == 0`. The old consumption-on-rejection test was replaced by the new tests.

Covered (net10.0): `Save`/`SaveAsync` to a stream (null, read-only, non-seekable, non-empty, position 5, the input stream) and to a path (null, empty, illegal character, the input file); `Sign`/`SignAsync` to a stream and path (the same stream and path cases plus null options, wrong-kind options and a null signer); Combine `Save`/`SaveAsync` to a stream (all five cases, the input stream) and to a path (the three path cases); consumed-once cases for a refusal, pre-cancelled `SaveAsync`, `SignAsync` and Combine, missing directory, existing file, and `AppendToSource` on a read-only source; pre-cancelled token with a rejected argument; three concurrent `Save` calls including one invalid. On the old code 31 of 39 new cases failed (the 8 that passed are the consumption controls).

Checks run: full `jaytwo.Ergonomics.Pdf.Tests` net10.0 240 passed, 3 skipped (the skips predate this item); `make quiet-build` (StyleCop as errors); `make agents-check`, `make task-check`. The same-path check against the input file now runs only when the destination directory exists, because `SamePath` throws `FileNotFoundException` for a missing directory and the existing missing-directory test expects `DirectoryNotFoundException`. Not run: net48 and the other frameworks, the `jaytwo.Pdf.Tests` suite (no change to that library), Docker checkpoint.

Not covered: `Timestamp` terminals, concurrency of path terminals, non-seekable streams for Combine, `AppendToSource` argument cases (it takes none).
