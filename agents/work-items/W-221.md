# W-221. Refuse metadata edits that touch a duplicately defined XMP property

## Problem

METADATA-VALIDATE-01 (adopted, `docs/spec/metadata.md`) requires a touched XMP property to be defined in exactly one place across the top-level descriptions; defined more than once, in competing forms, or with duplicate `xml:lang` entries, the edit is refused with no change to Info or the packet. `XmpEditor` instead edits the first description only, so a duplicate is silently updated in one place (or a second definition is added when the property lives in a later description), and the refusal path cannot run before Info changes.

## Scope and exclusions

In: locate a touched mapped property across all top-level descriptions; refuse the duplicate cases with `PdfXmpException` before Info or XMP changes, including the automatic ModDate refresh; edit a single definition where it lives. Out: refusal of other-root or malformed packets (current leave-packet-unchanged behavior stays), raw replacement, cancellation and I/O fault injection, new public API, and `docs/spec/metadata.md`.

## Acceptance criteria

- META-A7 duplicate cases refuse with no change; an unrelated duplicate does not refuse and survives; a single definition in a later description is edited in place.
- Existing metadata, FZ-3 and workflow metadata tests still pass.

## Evidence required

`make quiet-test TEST_FRAMEWORK=net10.0 TEST_FILTER=FullyQualifiedName~MetadataTests`; the new tests fail without the source change; fast lane on net10.0; `make task-check`.

## Closeout

Implemented: `XmpEditor.Locate` counts definitions (attribute plus element) across top-level descriptions and duplicate `xml:lang` values, refusing with `PdfXmpException`; the edit uses the single definition's own description; `PdfInfoMetadata.CheckXmpEdit` runs that check for the key and the automatic ModDate refresh before any Info change (text, date and Trapped setters). Four tests added to `MetadataTests` (6 cases). Without the source change 5 of them fail; the unrelated-duplicate control passes either way by design. `docs/behavior.md` and `docs/acceptance.md` (previously a `TODO` stub, now one enforced META-A7 row) updated; no criterion weakened.
