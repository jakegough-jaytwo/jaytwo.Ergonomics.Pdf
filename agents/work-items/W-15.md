# W-15. Timestamp authority outside pyHanko

## Problem

`Fixtures/tsa_server.py` uses pyHanko's `DummyTimeStamper`, and the pyHanko 0.38.0 check is the same toolchain. No independent verifier had checked a document timestamp from a different authority.

## Why now

Gate G5 requires an independently implemented RFC 3161 authority, and a document timestamp is a separate capability.

## Scope and exclusions

Use a timestamp authority that is not pyHanko, and have a verifier that is not that authority check a document timestamp. The library-side imprint, digest algorithm, and nonce checks stay in W-04. Do not add TSA trust validation to the library.

## Acceptance criteria

A token from the non-pyHanko authority is embedded, and an independent verifier accepts the document timestamp under an explicit test trust configuration. The record names the authority, the verifier, their versions, and the properties established. `QUALIFICATION.md` section 7.

## Evidence required

Independently validated.

## Closeout

Accepted at the independently validated level for the document timestamp. G5 is not passed. OpenSSL 3.2.4 `openssl ts -reply` answered the library's own nonce-bearing request, and `DocTimeStampSignatureProvider` embedded the token through `PdfDocument.Sign`. pyHanko 0.38.0 `validate_pdf_timestamp` reported the document timestamp intact, valid, trusted, and `ENTIRE_FILE`, with the test root as the only trust anchor. `openssl ts -verify` returned `Verification: OK` over the `/ByteRange` bytes, which is corroboration from the authority's own toolchain. A different root gives `trusted=false`, and a flipped byte gives `intact=false`. `OpenSslTimestampTests` passed 2/2 and `SigningInteropTests` 4/4 on `net8.0` and `net6.0`, and both fail when OpenSSL is missing. A mutation that reissues the TSA certificate fails the ESS signing-certificate check. Limitations: the token had no certificates, because the request omitted `certReq` (D-14), so pyHanko accepted it only when the test added the TSA certificate to the parsed token in memory, not to the PDF. No CMS signature timestamp from an authority other than pyHanko was tested.
