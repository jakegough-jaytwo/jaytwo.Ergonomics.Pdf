# W-146. Verify the R2 exit criteria at an integration checkpoint

## Problem

The stage R2 exit criteria (`reset-plan.md` section 8) concern the operations together: composition into one revision, public-API-only execution, rejection before output, and shorter caller code. Each operation item checks only its own operation.

## Scope and exclusions

- Add a composition test: one workflow with every R2 operation appends exactly one incremental revision, keeps the input as an exact prefix, inspects the same as the direct-engine sequence (spec F4), and reads no more source bytes than that sequence on a large fixture (F15).
- Add a boundary test: the `jaytwo.Ergonomics.Pdf` assembly references only `jaytwo.Pdf` and the framework, and `jaytwo.Pdf` grants it no `InternalsVisibleTo`.
- Check that the `README.md` workflow examples are shorter than their direct-engine equivalents, using W-141's side-by-side, and fix any that are not.
- Run the integration checkpoint.

Excluded: the MuPDF render checks (W-80, which follows this item) and new operations. A gap found here becomes its own item unless it is a defect in a test this item adds.

## Acceptance criteria

- The composition and boundary tests pass.
- Each R2 exit criterion except the renderer criterion is met, with its evidence named in Closeout.
- `make docker-builder docker-test` passes.

## Evidence required

The focused tests, `make quiet-test LANE=fast`, and `make docker-builder docker-test` from a separate worktree.
