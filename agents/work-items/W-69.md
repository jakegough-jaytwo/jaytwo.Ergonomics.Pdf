# W-69. Async signer, timestamp, and save

## Problem

The signer and timestamp interfaces and the save methods are synchronous, which suits neither cloud key services nor network output (spec W20). W-49 found that timestamp-authority exceptions are not sanitized; that is folded in here.

## Why now

Reset plan C2 item 10. It rewrites the interfaces the signing items build on.

## Scope and exclusions

- Async signer and timestamp interfaces with `CancellationToken`.
- `SaveIncrementalAsync` and `SignAsync` beside the synchronous methods.
- Add the D-39 package on `netstandard2.0`.
- Sanitize `ITimestampAuthority` exceptions (former W-49).
- Excluded: async reads.

## Acceptance criteria

- Sync and async results are byte-identical.
- Cancellation leaves the destination unchanged.
- Timestamp-authority exceptions carry no provider details.
- Both verifiers (W-14) accept the output.

Refine these criteria, and the `ACCEPTANCE.md` rows they add or change, when the item becomes active. A write item also meets every check in plan C4.

## Evidence required

pyHanko and `pdfsig` on async-signed output.
