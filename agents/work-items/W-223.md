# W-223. Create no XMP packet for a clear that has no automatic date to carry

## Problem

META-A4 says a clear with no packet creates none, while METADATA-DATE-01 and CUSTOM-01 create a minimal packet for an automatic ModDate. The owner resolved this on 2026-11-01: a clear creates a minimal packet only when it triggers an automatic ModDate refresh, and then it holds only that date; an explicit ModDate clear, or a clear under an explicit ModDate override, creates none. The code created an empty packet for those last two cases.

## Scope and exclusions

In: the CREATE-01 bullet and META-A4 wording in `docs/spec/metadata.md` (owner-approved clarification, nothing else weakened); the missing no-packet case in `SyncXmp`; tests; behavior and acceptance records. The "Remaining gaps" note already records W-221's fix (done in W-222). Out: META-A9 fault injection, independent-reader checks, any other contract text.

## Acceptance criteria

- Mapped clear with automatic ModDate: saved packet holds only the date. Explicit ModDate clear and clears under an override: no packet; Info and XMP state verified after Save/reopen.
- A refused clear keeps earlier pending edits.

## Evidence required

Focused `MetadataTests`; the new no-packet tests fail before the fix; fast lane net10.0; Ergonomics tests; build; `make task-check`.
