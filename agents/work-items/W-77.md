# W-77. Flatten form fields

## Problem

Forms cannot be flattened (spec W3, §7.1, §7.2).

## Why now

Reset plan C2 item 19. It is in the owner's original charter.

## Scope and exclusions

- `PdfAcroForm.Flatten()` flattens every field except signature fields; `Flatten(fullNames)` flattens the named fields, including an unsigned signature field (§7.1, §12 question 6 keeps the current rule).
- Each flattened widget's normal appearance (`/AP /N`, selected by `/AS` for buttons) is painted as a form XObject placed by ISO 32000-1 12.5.5, on each page whose `/Annots` lists the widget. The existing page content is wrapped in `q`…`Q` by adding streams to `/Contents`; no content stream is decoded. Hidden and NoView widgets are removed without being drawn. A widget with an `/OC` is painted inside `/OC … BDC … EMC`.
- Flattened widgets leave the page `/Annots`, flattened fields leave `/Fields`, their parents' `/Kids`, and `/CO`; a parent left with no kids goes too. When no fields remain, `/XFA` and `/NeedAppearances` are removed. A flatten of a hybrid XFA form removes `/XFA` in the same revision (W4).
- Refusals before any change: XFA-only (`PdfUnsupportedFormException`); DocMDP at every `P` (`PdfCertificationLockedException`); FieldMDP on a flattened field; a named signed signature field and, unless `PdfDocument.AllowBreakingSignatures` is set, any signature (`PdfSignatureConflictException`); the permission bits (`PdfEncryptionRestrictedException`); `/NeedAppearances true` and a widget whose value has no usable appearance (`PdfUnsupportedFormException`).
- Usage rights: no UR3 right grants a flatten, so `/UR3` is removed on an unsigned document (§7.3).
- Excluded: flattening other annotation types; rotate (W-78), which will reuse `AllowBreakingSignatures`; MuPDF (W-80).

## Acceptance criteria

- Flattened output rendered by Poppler with annotations hidden matches the filled form rendered with its widgets, including rotated pages, crop-box and media-box offsets, appearance `/Matrix` and `/BBox` placement, check boxes and radios, and corpus forms (ACCEPTANCE.md AcroForm, new flatten rows).
- qpdf `--check` and pypdf accept the output; pypdf finds no flattened widget in `/Annots` and no flattened field in `/Fields`; the original bytes are a prefix.
- Signed signature fields are never flattened; DocMDP blocks flatten at `P` 1, 2, and 3; a FieldMDP lock on a named field refuses.
- An opted-in flatten after a pyHanko approval signature leaves that signature intact and valid in pyHanko, which reports the later change as a modification beyond form filling, and pdfsig reports the signature valid but not covering the whole file.
- C4: AES-256 and RC4 input under the owner and the user password; a user password without the modify or annotate bit refuses; new streams are encrypted with the document's cipher and `/Encrypt` and `/ID` are kept; every refusal leaves the document clean and a later save writes nothing; usage rights are removed on an unsigned document and kept on a signed one.

## Evidence required

Poppler (`pdftoppm`, `pdftotext`) for rendering; qpdf and pypdf for structure; pyHanko and pdfsig for the signed case. MuPDF is W-80.

## Notes

- 2026-10-20: Created under W-63 from `agents/reference/charter-reset-plan.md` C2.
- 2026-10-21: Activated. The "two renderers" criterion is split as W-76 split it: Poppler here, MuPDF through W-80 (a dated note on W-80 records it). Corpus probe (pypdf over every corpus form): empty text fields without `/AP` are common (110 of 118 widgets on the 1040-ES), most check boxes in the `Off` state have no `/Off` appearance, 86 I-9 appearance streams omit `/Subtype /Form`, the 1040-ES has four `/OC` push buttons without appearances, and no widget sets NoRotate or `/MK /R`. So a widget without an appearance whose field shows no value draws nothing, an `Off` state with no appearance draws nothing, and an appearance stream that omits `/Subtype` gains `/Subtype /Form` so `Do` can paint it.
- 2026-10-21: Implemented. `PdfAcroForm.Flatten()` and `Flatten(fullNames)`, and `PdfDocument.AllowBreakingSignatures`, the opt-in spec 7.2 names; it lives on the document so W-78's rotate can use it too. Order of checks: arguments, XFA-only, DocMDP at any `P`, names (unknown, signed signature field), an empty selection returns, FieldMDP, the signature opt-in, the modify and annotate permission bits (ISO 32000-1 Table 22: page content is bit 4, removing form fields also needs bit 6), `/NeedAppearances`, then each widget's appearance and NoRotate. Draws follow each page's `/Annots` order, the order viewers paint overlapping widgets, and a widget is drawn on every page whose `/Annots` lists it, not on its `/P` page, because `/Annots` is what viewers show. A page's `/Contents` must be loaded to tell a stream from an array, so the flattened page's content stream dictionary is read; its bytes are not.
- 2026-10-21: Rendering. Poppler 26.09.0 renders the flattened pages with `-hide-annotations` pixel-identical to the filled pages with their widgets on every built and corpus case except page 5 of the FAA 8710-1, where 22 pixels of the 4.5-point generated text differ in anti-aliasing with the text in the same place (`pdftotext -bbox` boxes agree). The render check allows 48 pixels per page and compares word boxes to 0.1 point. Red check: dropping the `/BBox` origin from the translation fails the placement case by 59,650 pixels.
- 2026-10-21: Corpus. After the bulk fill of `CorpusTests` less the values that return `NeedsViewer` (comb fields on the CMS-40B, W-9, I-9, and VA 21-4138 would set `/NeedAppearances`), every corpus form with fields flattens except the certified GPO bill (`P` 1) and OPM OF-306 (`P` 2), which refuse; 14 forms flatten, including the pyHanko-approved CMS-40B with the opt-in, whose approval stays intact and valid in pyHanko.
- 2026-10-21: Records. Relabeled the W-105 footnote of `acceptance-matrix.md` from a second `[^e14]` to `[^e15]`; W-47 already used `[^e14]`.
- 2026-10-21: For the owner. Two readings of the spec that the owner may want to confirm. (1) Spec 7.1 says a widget without a usable appearance makes flatten throw. This item throws only when the widget's field shows a value (text, a selected choice, a checked box or selected radio) and draws nothing for a field that shows none, because empty text fields without `/AP` are on nearly every corpus form (the literal reading would refuse the 1040-ES, FAA 8710-1, OPM OF-306, CMS-40B, W-9, and VA 21-4138) and the value is what a viewer would show. (2) Spec 7.2 says "any approval signature"; this item asks for the opt-in on any signature, a document timestamp included, because validators report a page-content change after a document timestamp the same way.
