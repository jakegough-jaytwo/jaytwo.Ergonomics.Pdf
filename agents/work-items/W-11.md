# W-11. Evidence that a revision 4 stream can use a different cipher from its strings

## Problem

The opening row says revision 4 strings and streams can use different ciphers. `CreateRevision4` reads `StrF` and `StmF` separately, but `revision4_can_mix_aes_strings_with_rc4_streams` decrypted only the title, and its file had no stream. This is W-03 clause 11.

## Why now

The W-05 Core audit and W-03 found an acceptance clause with no assertion.

## Scope and exclusions

Add a revision 4 test whose stream cipher differs from its string cipher. No `src/` change. Do not edit `ACCEPTANCE.md`.

## Acceptance criteria

A revision 4 file with AES strings and an RC4 stream opens, and both the string and the stream decrypt.

## Evidence required

Not stated in the original entry. Internally tested, the level at which it was accepted.

## Closeout

Accepted. `StandardEncryptor.EncryptRc4` encrypts with the revision 4 RC4 object key of an existing file key, and `revision4_rc4_stream_decrypts_beside_an_aes_string` passed on `net8.0` and on `net6.0`. Opening with password `user` returns title `Secret` from the AES string cipher and the 40 embedded-file bytes from the RC4 stream cipher. `PdfBuilder.cs` and `ACCEPTANCE.md` were not changed.
