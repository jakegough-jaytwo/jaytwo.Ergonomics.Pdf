# W-26. Review the parser from outside its implementer

## Problem

No one other than its implementer had reviewed the parser for hostile input. Gate G8 asks for an independent review of the parser and the signer.

## Why now

G8 is release-blocking, and a code review was possible before the fuzz run.

## Scope and exclusions

The Signing Engineer reviews the parser, read-only. No `src/` and no tests. Report confirmed defects, or state that none were confirmed, with the files read. This is not the fuzz run and does not replace W-18. Do not pass G8.

## Acceptance criteria

A report lists confirmed defects, or states that none were confirmed, and names the files read.

## Evidence required

Not stated in the original entry. A code review, confirmed by the Technical Lead.

## Closeout

Accepted as the parser review. G8 is not passed, and W-18 stays open. The Signing Engineer reported seven defects, and the Technical Lead confirmed all seven from the code. None were executed.

1. Comment skipping recurses with no depth cap.
2. A `/Prev` chain of distinct offsets recurses with no depth cap.
3. Cyclic `/Length` and object streams parse the same object again.
4. `Resolve` follows reference cycles with no seen set.
5. `WalkField` recurses on `/Kids` with no seen set.
6. `WalkNames` recurses on name-tree `/Kids` without recording the node.
7. A malformed xref `/Index`, xref field width, or object-stream header throws `IndexOutOfRangeException`, `FormatException`, or `OverflowException`.

W-28 is the bounded fix. Reports: `agents/reports/2026-10-18-signing-engineer-B-26.md`, `2026-10-18-tech-lead-B-26-review.md`, and `2026-10-18-product-manager-B-26.md`. Completed 2026-10-18.
