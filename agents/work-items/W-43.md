# W-43. Refuse check-box widgets with different on-state names (F-2)

## Problem

Skill-review finding F-2. One check-box field had two widgets whose `/AP /N` dictionaries used `First` and `Second` as their on-state names. `SetCheckBox("Agree", true)` chose `First` as the field `/V` and wrote `/AS /First` to both widgets. The second widget had no `First` appearance, so the fill reported success while publishing an appearance state the widget could not draw.

## Why now

A supported fill silently produced an inconsistent field. The approved skill plan (D-27, step 2) said to reproduce it first and, if confirmed High, fix it before the W-18 campaign.

## Scope and exclusions

Reproduce, then refuse the inconsistent fill before the document is dirtied. Document the refusal. No change to fields whose widgets agree.

## Acceptance criteria

`SetCheckBox(name, true)` on a field whose widgets advertise different non-null on-state names throws `PdfFieldValueException` and does not dirty the document. The regression test fails on the unfixed source. `README.md` and `ACCEPTANCE.md` record the behavior.

## Evidence required

Not stated in the original entry. Internally tested.

Accepted as the fix for F-2, at the internally tested level. `PdfEngine.SetCheckBox` refuses a checked field when two widgets advertise different non-null on-state names, before `EditAny`, so the document stays clean. `AcroFormTests.check_box_widgets_with_different_on_states_are_rejected_without_writing` builds the two-widget field, requires `PdfFieldValueException`, saves, and proves the stream length is unchanged.
