# W-159. Document secure hosting responsibilities

## Problem

Hosts need one clear account of the controls the libraries enforce and the deployment controls they cannot provide internally. Without it, opening, modifying, or incrementally saving a PDF may be mistaken for sanitization.

## Scope and exclusions

Document process-level CPU and memory isolation, concurrency limits, temporary-storage controls, timestamp-endpoint restrictions, attachment extraction policy, and malware scanning responsibilities. Tie the guidance to the final bounds and API contracts from the prerequisite items. Do not claim a library-enforced control that is only operational guidance.

## Acceptance criteria

- Guidance distinguishes enforced parser/operation limits from host deployment controls.
- It covers resource isolation, concurrency, temporary files, timestamp network policy, attachment extraction and scanning, and handling of untrusted output.
- It states prominently that successful open, edit, or incremental save is not sanitization and does not physically remove historical content.
- Every library guarantee cited by the guidance is traceable to shipped behavior; proposed behavior is not advertised as shipped.

## Evidence required

A documentation review against `AGENTS.md`, `ACCEPTANCE.md`, and the completed prerequisite items, plus link and XML-documentation build checks where applicable.
