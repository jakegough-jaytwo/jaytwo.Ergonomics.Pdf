# W-232. Write the ordinary workflow Save(path) directly with create-or-overwrite and fail-if-exists

## Problem

WORKFLOW-FILE-01 to 04 (adopted): ordinary file output is written directly to the destination, after the pending edits and available validation and before anything is created or truncated; an absent destination is created, an existing one is overwritten by default, and fail-if-exists is an explicit choice; a save that fails after writing starts leaves the file in place. The implementation staged to `.<name>.<random>.tmp`, published it, left the destination untouched on failure, and replaced an existing file only with `Overwrite = true`.

## Scope and exclusions

`Save(path)` and `SaveAsync(path)` of `PdfWorkflowBuilder`. Out: Combine, `Sign` and `Timestamp` (still staged; their default stays fail-if-exists), the engine's own truncation of an unfinished destination (WORKFLOW-RESTORE-01's engine mode is a separate gap in `jaytwo.Pdf`), the adopted contract, and the W-227 loader observation.

Decisions made here (the contract leaves API spelling open): the existing `PdfFileSaveOptions.Overwrite` stays the fail-if-exists switch (`false` means fail-if-exists) and its unset value is now `true`. The staged terminals read the unset value as `false` through an internal `OverwriteOr(false)`, so their behavior does not change; the one visible oddity is that `Overwrite` reports `true` for an unset value on options passed to those terminals. The destination is opened with `FileMode.Create` or `FileMode.CreateNew`, so fail-if-exists also holds if the file appears after the check. This is a behavior change to a public default; it follows the owner-adopted WORKFLOW-FILE-04.

## Acceptance criteria

- Absent destination created, existing one overwritten by default and with `Overwrite = true`, refused with `Overwrite = false` (input unread, destination unchanged, description consumed).
- A known refusal creates and truncates nothing; input-alias refusals precede opening, with the default overwrite.
- A failure or cancellation after the destination opened leaves the file in place and consumes the description; no temporary file.
- Signing, timestamp and Combine behavior is unchanged.

## Evidence required

`WorkflowDirectFileTests` on the old and new source; the Ergonomics suite on net10.0; the file-output tests on net48; build; `make agents-check`, `make task-check`.

## Closeout

2026-11-01: implemented. `WorkflowFiles.CheckDestination` (the alias and existence checks, shared with `Publish`) and `OpenDirect` are new; `SaveFileAsync` applies the edits, checks the destination, then opens it and saves in place. On the old source 5 of 15 new tests failed (default overwrite, the known refusal with an existing file, and the failure-in-place cases).

Existing tests that encoded the old behavior were changed: the two tests that relied on the old default now pass `Overwrite = false`; the default-options assertion now expects `true`; and `cancellation_during_an_async_path_save_leaves_no_file` became `..._leaves_the_failed_file_in_place`.

Checks run: `make quiet-build` (StyleCop as errors) exit 0; full `jaytwo.Ergonomics.Pdf.Tests` net10.0 278 passed, 3 skipped (pre-existing), exit 0; `WorkflowDirectFileTests`, `WorkflowFileSaveTests` and `WorkflowBeginTests` net48 74 passed, 1 skipped, exit 0; `make agents-check` and `make task-check` with their exit statuses checked. Not run: the Docker checkpoint (this is a single-library change, not a named integration or release checkpoint), net6.0 and net8.0, the `jaytwo.Pdf.Tests` suite (no change to that library).

Uncovered parts of the adopted rules: an unfinished destination is truncated by the engine rather than left as the partial bytes WORKFLOW-FILE-03 describes (engine restoration mode, a separate gap); symbolic-link and hard-link destinations under direct writing and the hard-link-during-processing race; concurrent same-path saves; WORKFLOW-FINAL-01 (final position, durability); exact error types and WORKFLOW-ERROR-01 and CLEANUP-01 scenarios; Combine, signing and timestamp still use staged publication.
