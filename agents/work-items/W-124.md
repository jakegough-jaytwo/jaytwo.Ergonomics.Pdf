# W-124. Make focused verification the default

## Problem

Routine changes inherit more testing, evidence maintenance, reading, and work-item prose than their risk requires, slowing implementation and consuming excessive agent context.

## Scope and exclusions

Make focused tests and compact records the default. Keep broader verification available for explicit risks, integration checkpoints, and release qualification. Do not weaken the product contract or release gates.

## Acceptance criteria

- Routine tasks default to the smallest tests that can falsify the changed contract.
- Fast, matrix, Docker, independent-tool, reporting, and qualification work is opt-in and justified by risk or release scope.
- Executable work items no longer require `Why now` or `Notes` sections.
- Confirmed defects still receive a permanent regression test, and public behavior changes still update the public contract.

## Evidence required

Run the workflow validator tests, `make agents-check`, and staged `make task-check`. No product tests or Docker gate: this item changes process records and their validator, not PDF behavior.

## Notes

- Owner-approved rule edits: `AGENTS.md` makes focused verification the default; `QUALIFICATION.md` limits inventory maintenance to qualification work; `pdf-task-workflow` shortens records and removes routine reports; `pdf-change-verification` makes the broader test tiers and qualification evidence opt-in.
