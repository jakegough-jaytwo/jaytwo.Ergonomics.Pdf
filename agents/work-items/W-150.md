# W-150. Correct signature inspection and revision semantics

## Problem

Signature inspection and revision listing can misstate malformed structures: a missing `%%EOF` can produce a wrong revision boundary, a populated signature dictionary can appear signed without proving validity, and coverage names can imply more than structural `/ByteRange` analysis establishes.

## Scope and exclusions

Correct revision-boundary parsing and make the public inspection models distinguish field population, structural byte-range validity, claimed revision coverage, and cryptographic verification. Rename misleading public members where necessary while the libraries remain pre-1.0. Do not add trust, revocation, or cryptographic signature validation.

## Acceptance criteria

- Missing revision footers, invalid offsets, overlapping ranges, incomplete signature dictionaries, and byte ranges ending away from a revision have deterministic documented outcomes.
- No public property implies cryptographic validity or trust that the library does not establish.
- Structural `/ByteRange` validity is observable separately from field population and claimed revision coverage.
- Existing library-produced signatures retain their inspection results and continue to pass the established interoperability checks.
- Public behavior documentation is updated with the changed contract.

## Evidence required

Focused signature-inspection and revision tests, including permanent regressions for confirmed defects, plus the existing signing interoperability tests for unchanged output behavior.

## Closeout

2026-10-24.

**Defect: a section without a footer borrowed the next one.** `RevisionEnd` searched the 64 KiB after a cross-reference section for the first `startxref`. A historical section with no footer of its own therefore took the next revision's footer, and two revisions reported the same end.

- Severity: high. Revision listing and the signature's claimed revision misreport.
- Fix: the footer must follow the section after white space only (ISO 32000-1 7.5.5, 7.5.8.1). Otherwise `Revisions` throws `PdfParseException`, and the other reads still work.
- Regression: `RevisionTests.historical_section_without_its_own_footer_blocks_revision_listing` failed before the fix ("No exception was thrown") and passes after it.
- `SourceTests`' indirect-`/Length` chain fixture had the same missing footer. It now writes the footer, and what the test checks is unchanged.

**Public API changes (pre-1.0, as scoped):**

- `PdfSignatureInfo.IsSigned` is now `HasSignatureDictionary`.
- `PdfSignatureInfo.SignedRevisionEnd` is now `ByteRangeEnd`.
- `PdfSignatureInfo.SignedRevisionNumber` is now `ByteRangeRevisionNumber`.
- `PdfRevision.IsCoveredBySignature` is now `EndsAtSignatureByteRange`.
- New `PdfSignatureInfo.ByteRangeStatus` (`PdfByteRangeStatus`): `Missing`, `NotFromFileStart`, `PastEndOfFile`, `Overlapping`, `GapNotHexString`, `WellFormed`, checked in that order. It reads only the two gap delimiter bytes.
- Unchanged: syntactically malformed `/ByteRange` values (not four non-negative integers, or overflow) still throw.

`README.md` and `ACCEPTANCE.md` are updated.
