# W-175. Research per-framework coverage output for a common jaytwo Makefile

## Problem

1. **Summary.** `make unit-test` runs `jaytwo.Pdf.Tests` and `jaytwo.Ergonomics.Pdf.Tests` in parallel for each framework. Both write coverlet output to the same path for that framework, for example `out/coverage/net8.0/coverage.net8.0.cobertura.xml`, so whichever finishes last overwrites the other. The Jenkins log for build 13 shows only the `jaytwo.Pdf.Tests` report surviving for net8.0 and net6.0, so the merged coverage understates `jaytwo.Ergonomics.Pdf`.
2. **Context.** The owner intends a common Makefile across the jaytwo libraries (`jaytwo.Ergonomics.Images`, `.S3`, `.Logging`, `jaytwo.AdoTools`). A fix here should be the pattern those libraries share, not a repo-local patch.
3. **Related.** W-174 isolated each parallel run's temp directory, which stops the coverlet hits-file race but not the shared output path.

## Scope and exclusions

Determine how each sibling library's Makefile lays out test runs and coverage output, and which solution works for all of them. Candidates include a per-project `CoverletOutput` directory, a `MergeWith` JSON chain, and emitting JSON per run for `reportgenerator` to merge. Weigh parallel safety, the Jenkins `recordCoverage` pattern (`out/coverage/Cobertura.xml`) and `publishHTML` directory, and the clock-test runs. Write findings and a recommendation to `agents/reference/w-175-coverage-output.md`. No Makefile change and no change to another repository; the implementation is a follow-up item after the owner chooses.

## Acceptance criteria

- The reference document states the observed output layout in each sibling Makefile, the failure mode here, and at least two candidate fixes with trade-offs.
- It recommends one approach and lists the follow-up work for this repository.

## Evidence required

Read the sibling Makefiles and reproduce the overwrite with two parallel runs on one framework. Quote the paths observed.
