# W-47. Fit auto-sized text and paint MK colors

## Problem

With `/DA` size 0, generated text size follows field height only, so a wide value can be clipped while fill reports success. Regenerated appearances also retain `/MK` but do not paint `/BG` or `/BC`, causing colored boxes to disappear.

## Why now

The clipped value is a visible wrong result on a supported operation.

## Scope and exclusions

For single-line WinAnsi text with `/DA` size 0, reduce the height-derived size until the value fits inside the width, with six points as the floor. Paint `/MK /BG` and `/MK /BC` with supported gray, RGB, and CMYK arrays and the `/BS /W` width. Exclude multiline and comb auto-size changes, captions, icons, rotation, non-solid border styles, and fonts outside the existing Helvetica subset.

## Acceptance criteria

Update the documented limitations and matching acceptance row. A long value fits or reaches the six-point floor; background and border paint behind text and inside the box; fields without `/MK` produce the same stream as before.

## Evidence required

Internally tested plus Poppler `pdftoppm` evidence that the value is not clipped and the colors appear.
