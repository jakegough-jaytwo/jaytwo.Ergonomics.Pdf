# W-144. Attachment and page-rotation workflow operations

## Problem

Stage R2 includes adding and removing attachments and rotating pages (spec W6, W8 to W13). As workflow operations, attachment content becomes a deferred input with its own ownership, which the engine's `Add(name, Stream, leaveOpen)` does not cover for a description recorded before the run.

## Scope and exclusions

Add attachment add (stream and file path) and remove, and page rotation, on W-142's pipeline, with the defaults, conflict rules, and signature opt-in that W-141's decision chooses. Attachment content is opened and read only during the run, streamed as the engine requires, and never buffered whole.

Excluded: any change to engine attachment or rotation behavior, and page-level file attachment annotations (never in scope).

## Acceptance criteria

Refine these criteria from W-141's decision at activation.

- Describing an attachment opens no content, and a file-path attachment is opened during the run and closed after it, on success and on failure.
- Add, remove, and rotate workflows each append one revision whose bytes equal the direct-engine sequence.
- Each conflict the decision lists (for example, adding and removing one name, or rotating one page twice) is rejected before the destination is written, or is resolved by its stated rule.
- A rotation angle that is not a multiple of 90 is rejected before the source opens. A page number outside the document is rejected before the destination is written.
- Rotation on a document with an approval signature requires the decision's opt-in.

## Evidence required

Focused `jaytwo.Ergonomics.Pdf.Tests` on net10.0 and `make quiet-build`.
