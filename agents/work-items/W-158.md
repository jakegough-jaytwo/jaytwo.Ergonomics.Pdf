# W-158. Document signature inspection and revision trust boundaries

## Problem

Public guidance must clearly distinguish structural signature inspection from cryptographic verification and trust, current-document write gates from historical revision analysis, and incremental preservation from removal of older sensitive content.

## Scope and exclusions

Update public documentation and relevant API remarks after W-150 settles the inspection names. Explain fail-closed handling of unresolved or unusual DocMDP references and retain strict malformed-signature behavior. Do not implement signature validation, trust, revocation, or full historical analysis.

## Acceptance criteria

- Documentation separately defines inspection, cryptographic verification, trust validation, modification-permission enforcement, and historical revision analysis.
- It states that earlier revisions may retain signatures and sensitive content and that incremental writes do not remove them.
- It explains the default strict/fail-closed treatment of malformed signature and DocMDP structures.
- Examples and API remarks use the final W-150 terminology and do not imply stronger guarantees.

## Evidence required

Documentation link and terminology checks, XML-documentation build, and focused inspection tests sufficient to confirm every behavioral statement already ships.
