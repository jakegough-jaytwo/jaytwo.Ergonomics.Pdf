# W-30. Bound the predictor /Columns allocation

## Problem

The W-28 re-review (`agents/reports/2026-10-18-tech-lead-B-28-re-review.md`, section 4) confirmed this from the code. It was not executed. `PdfStreamDecoder.UnpredictPng` allocates `previous = new byte[rowBytes]` before it checks that any row exists. `PdfParser.EnsureXrefColumns` sums `/W` with unchecked casts before `ReadWidths` validates it, and writes that sum into `/Columns` when a PNG predictor has no `/Columns`. `/W [268435455 0 0]` with `/Predictor 12` and empty decoded data allocates about 256 MiB before `ReadWidths` throws `PdfParseException`. An explicit `/Columns 268435455` on any predictor stream does the same. A few bytes of input cause an allocation that does not follow the working set.

## Why now

Memory following the working set is part of the charter. The path is confirmed and the fix is small. G8 stays unpassed.

## Scope and exclusions

Bound the predictor `/Columns` before allocating in `PdfStreamDecoder.cs`, and validate `/W` with checked arithmetic before `EnsureXrefColumns` uses it in `PdfParser.cs`, with regression tests. No parser or decoder rewrite. No change to the 32 MiB and 64 MiB decompression caps. Do not pass G8. Does not replace W-18.

## Acceptance criteria

`/W [268435455 0 0]` with `/Predictor 12` and empty decoded data, and an explicit `/Columns 268435455` on a predictor stream, each throw `PdfParseException`, do not allocate a row buffer sized from `/Columns` before a row exists, and do not extend the file. The Technical Lead sets the allocation bound the test measures. Xref streams with Flate and PNG predictor 12 still open, per the xref-stream row in `ACCEPTANCE.md`. `QUALIFICATION.md` section 10. G8 is not passed.

## Evidence required

Internally tested. Not a gate pass.

## Closeout

Accepted as the bounded fix, at the internally tested level. G8 is not passed. `Unpredict` computes the row width in `long` and refuses one of `int.MaxValue` bytes or more. `UnpredictPng` returns before any buffer sized from `/Columns` when no full row exists. `EnsureXrefColumns` calls `ReadWidths` before it sums `/W`, so the sum is at most 24. `OpenTests` passed 51/51 on `net8.0` and on `net6.0`. `/W [268435455 0 0]`, an explicit `/Columns 268435455`, and `/W [4563402751 0 0]`, each with `/Predictor 12` and empty decoded data, throw `PdfParseException`, allocate under the bound, and leave the stream bytes unchanged. With both fixes reverted, those cases allocated 268,526,576 to 268,543,352 bytes and failed. `xref_stream_with_predictor_and_object_stream_reads_info` passed in every tree. The four library targets built with 0 warnings and 0 errors. `README.md` and `ACCEPTANCE.md` were not changed. Limitations: an explicit `/Columns` on a non-xref predictor stream is covered only by reading the code. `IntOf` still narrows `/Columns`, `/Colors`, and `/BitsPerComponent` without a range check, which is no longer an allocation path. A malformed `/W` is now refused before the decode, with the `/W` message. The full suite was not run, and this is not the fuzz run.
