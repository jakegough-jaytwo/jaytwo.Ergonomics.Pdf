# W-183. Generate fuzz seeds before instrumenting the engine

## Problem

W-181's declared Docker campaign at `55e5ac6` aborts with exit 134 before any target runs. `run-campaign.sh` instruments `jaytwo.Pdf.dll` before seed generation. W-104's seed builder executes CMS parsing and DER helpers to classify/assert seeds, outside a libFuzzer callback. Identical seed generation passes before instrumentation and aborts with `System.AccessViolationException` in `CmsSignatureReader.Read` after instrumentation. Reproduction is retained in W-181's campaign evidence. Medium severity: campaign startup is broken; no uninstrumented product defect or mutated-input finding is demonstrated.

## Scope and exclusions

Generate and validate seeds with the uninstrumented Release engine, then instrument it before invoking any target. Add a short real-runner regression that exercises CMS and RFC 3161 startup in the existing fuzz image. Preserve target semantics, classification assertions, instrumentation of fuzz callbacks, limits and campaign allocations. No runtime or protected-guidance change.

## Acceptance criteria

- Seed generation completes before engine instrumentation; the resulting CMS and RFC 3161 targets run instrumented through libFuzzer.
- The permanent startup regression runs the existing runner with one worker and a bounded one-second allocation per target. It checks both target completions, zero finding artifacts and normal finalization. The pre-fix runner fails this regression at seed generation; the corrected runner passes.
- The ordinary deterministic smoke still passes. W-181 resumes its full allocation separately; this regression is not campaign qualification.

## Evidence required

Run `make agents-check`, deterministic smoke, the startup regression against the pre-fix and fixed runner in the existing Docker fuzz image, shell syntax checks, and staged `make task-check`. The runner-only change needs no new full framework/Docker integration checkpoint; W-182 still owns R4 integration.

## Closeout

- Moved instrumentation after both internal and external seed generation. Engine code, target semantics, classification assertions and all limits are unchanged.
- Added `tools/fuzz/test-campaign-startup.sh`, a permanent real-runner regression with one worker and one second per target. With the original image runner it aborts at CMS seed classification with the confirmed AccessViolationException; with the corrected mounted runner it passes both instrumented targets, records nonzero coverage, exits 0 and leaves zero artifacts. CMS: 11,303 executions, coverage 713; RFC 3161: see retained W-181 evidence archive. Runner elapsed time is three seconds per target including wrap-up. This is a startup regression, not W-181's qualification campaign.
- `make fuzz-smoke` passed every seed and 2000 deterministic mutations per target, all nine targets, zero uncontrolled failures. Shell syntax, `make agents-check`, staged `make task-check` and whitespace checks passed. No product parser finding or runtime fix was needed. W-181 resumes with its full declared allocation, preserving the failed attempt and this reproduction.
