# W-182. Verify the R4 signing exit at an integration checkpoint

## Problem

R4 must close on the final implementation before the remaining security phase becomes eligible. Individual feature, DSS and fuzz results do not alone establish the integration exit in reset-plan.md section 10.

## Scope and exclusions

Run a separate-worktree integration checkpoint at the final R4 commit. Check the D-64 contract and R4 exit criteria against W-180, W-103, W-104 and W-181 evidence. Add only missing checkpoint assertions. A defect in already committed work gets its own item and must be resolved before this checkpoint passes. No new behavior, protected wording, runtime signature validation, release-gate re-adoption, or package publication.

## Acceptance criteria

- Direct-engine and ergonomic signing are independently verified; workflow validation/order, one editor, revisions, staging, prefix, publication, cancellation and failure guarantees have passing named coverage.
- Existing RSA/ECDSA, digest, CMS/PAdES, timestamp, encryption and certification guarantees remain covered; no newly demonstrated R4 correctness defect is hidden by classification or verifier disagreement. The separately scheduled security items remain under D-62 rather than being silently pulled into this checkpoint.
- DSS B-B/B-T classification and signing-specific CMS fuzz evidence are fresh for the final implementation; later changes to covered code require the affected evidence to be rerun. Unsupported or not-run checks are explicit and cannot be counted as passes.
- The full framework matrix, including Windows net48 and the netstandard2.0 lane, passes. `make docker-builder docker-test` passes from a separate worktree, with the newly required tools and deterministic CMS smoke included.
- Record an explicit pass against every R4 exit criterion, exact revision, commands and evidence locations. Packaging/release remain suspended. Completion unblocks only the remaining security phase; R5 still follows that phase under D-62.

## Evidence required

Full Windows framework matrix and Jenkins-equivalent Docker gate from a separate worktree, plus freshness review of W-103/W-181 independent verifier, profile and campaign records. Use the existing quiet wrappers where appropriate. Run `make agents-check` and staged `make task-check`.
