# W-117. Append a cross-reference stream to a file whose last section is a cross-reference stream

## Problem

iText 9.8.0 cannot open this library's incremental output on a file whose last section is a cross-reference stream (`agents/evidence/itext-comparison.md`, finding 1). The appended classic table's `/Prev` points at the stream. After a classic section, iText reads every `/Prev` as another classic table. That read fails, and iText rebuilds the cross-reference by a line scan that misses object-stream members. qpdf, pyHanko, and pdfsig accept the same files.

## Why now

The owner added iText to the compatibility tests on 2026-10-22. Acrobat-era and qpdf-written files commonly end in a cross-reference stream. Queued on 2026-10-23 ahead of W-80 at the owner's direction: `QUALIFICATION.md` G2 requires each interoperability failure to be fixed, excluded with justification, or a release blocker before 1.0. The owner decides between those at activation, and approves the `AGENTS.md` and spec wording if it is fixed.

## Scope and exclusions

- When the section at `startxref` is a cross-reference stream, write the update as a cross-reference stream: `/Type /XRef`, `/Size`, `/Prev`, `/Root`, `/Info`, `/ID`, `/Encrypt`, `/W`, and `/Index`, Flate-compressed and never encrypted. Classic and hybrid sources keep classic appends.
- This changes the wording of `AGENTS.md` ("Write classic xref only") and `docs/spec/phase-1.md` ("Writes use classic cross-reference tables"), which needs the owner's approval. It also updates `README.md` and `ACCEPTANCE.md`.
- Excluded: rewriting earlier sections, and object streams in the update.

## Acceptance criteria

1. On a source whose section at `startxref` is a cross-reference stream, `SaveIncremental`, `Sign`, and a document timestamp append one revision that ends in a cross-reference stream as D-56 describes, and a second save chains to it. Classic and hybrid sources still append a classic table. The original bytes stay a prefix.
2. On an encrypted cross-reference-stream source, the appended stream is plaintext and the output reopens under the user and the owner password.
3. `Revisions` lists one more revision after each save.
4. iText 9.8.0 reads every write path's output on cross-reference-stream sources: metadata, XMP, attachment, and rotation edits; a single fill, a bulk fill, and a flatten; signatures for every key and format, then a later revision; and fills and signatures on qpdf RC4-128 and AES-256 files under both passwords. The corpus iText check runs on every corpus file, with no skip list.
5. On cross-reference-stream sources, qpdf `--check` accepts a fill, a signature, and a later revision, pypdf reads the filled value, and pyHanko and pdfsig verify the signature. pyHanko reports it intact, and after the later revision, intact with the modification level that revision implies.
6. The signature appendix bound and the G7 workloads on qpdf's object-stream sources pass unchanged.

## Evidence required

Independently validated with iText 9.8.0, qpdf, pypdf, pyHanko, and pdfsig. Focused tests, the affected `Interop` and `Corpus` tests, the G7 `LargeData` tests on object-stream sources, and the fast lane on every target, since every write path changes.

## Closeout

Done. `PdfIncrementalWriter` writes the section in the format of the one at `startxref` (`PdfObjectStore.AppendsXrefStream`, set at open): a classic table as before, byte for byte, or a Flate cross-reference stream under the next free object number that lists itself and carries the trailer entries in plaintext. `/Size` grows by that object.

1. `XrefStreamAppendTests` reads the appended section without the library: save, chained save, `Sign`, a second signature, and a document timestamp after a cross-reference stream; classic and hybrid sources keep a classic table; AES-256 under both passwords.
2. Its interop test: on qpdf object-stream forms, unencrypted and AES-256, `qpdf --check` passes a fill, a signature, and a later fill, pypdf reads the value, `pdfsig` verifies, and pyHanko reports intact and `FORM_FILLING`.
3. `ITextInteropTests` runs every case on classic and qpdf object-stream sources (24 cases). The corpus iText check has no skip list; `IText` counts a field as terminal when no kid has a `/T`, as `form_values.py` does, because iText lists a widget carrying `/DA` as a nameless child field on the USCIS I-9 and FAA 8710-1, on the untouched sources too.
4. Red check: with the `src/` change stashed, 17 of the new and reshaped tests fail.
