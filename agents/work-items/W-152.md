# W-152. Strengthen workflow publication and path isolation

## Problem

The workflow's best-effort path checks do not fully characterize intermediate symbolic links, hard links, destination replacement races, and input/output aliases across Windows and Unix. A separate-output save must not overwrite its open input where the configured safety contract forbids it.

## Scope and exclusions

Review the shipped D-60 atomic-publication design against path and file identity behavior on supported platforms, then close confirmed gaps with fail-closed checks where identity cannot be established safely. Preserve atomic publication unless evidence and an owner decision require a redesign. Do not add native interop or a runtime dependency without approval.

## Acceptance criteria

- A separate-output save cannot overwrite its open input through normalized paths or tested link aliases when the safety contract forbids it.
- Unsafe or unverifiable destinations fail before publication where necessary, without removing or corrupting the input or prior destination.
- Tests cover intermediate and final-segment symbolic links, hard links, destination replacement races, concurrent publication, and failed publication on Windows and Unix where the platform supports each case.
- Public documentation states the guarantees and remaining race or identity limitations precisely.

## Evidence required

Focused workflow publication tests on Windows net10.0 and net48 and Linux net10.0, including platform-specific link and concurrency cases.
